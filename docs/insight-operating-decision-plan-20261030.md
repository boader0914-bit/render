## 자료와 계산 의미

- 정확한 예약 리드타임은 **한국시간의 숙박 시작일에서 실제 예약 접수일을 뺀 달력 일수**다. 예약 건 기준과 객실 수 가중 기준을 구분한다. 생성일·변경일·수집일을 예약 접수일로 대신하지 않는다.
- 관측 자료는 두 관측 사이의 공개 예약 순변화와 증가 시점의 구간을 보여준다. 그 값은 실제 신규 예약 건수나 정확한 접수일이 아니다. 같은 구간의 취소·재예약·재고 변경 가능성을 보존한다.
- 관측이 시작되기 전 이미 예약된 객실과 수집 범위 밖의 장기 선행 예약을 식별한다. 향후 30일 자료만으로 30일보다 앞선 예약 시점을 복원하지 않는다.
- 비교는 같은 매장·상품 조건·숙박일 성격·예약 선행 구간·성숙한 관찰 기간으로 맞춘다. 현재의 월~목/금~일 평균만으로 일반 평일이나 특정 날짜의 할인 필요를 확정하지 않는다.
- 가격은 같은 상품·인원·박수·이용 유형·취소 조건·포함 혜택의 숙박 객실 판매금액으로 해석한다. 데이유즈 및 런치·디너 재사용은 기존 객실 공유 근거를 유지한다.
- 쿠폰 사용률의 발급·노출·사용 분모와 만료 여부를 구분한다. 쿠폰 사용 예약을 모두 추가로 생긴 예약으로 계산하지 않는다. 사업주 부담 할인과 플랫폼 부담 할인도 구분한다.
- 할인 후 실결제액, 실제 환불·정산, 수수료, 추가 제공 원가가 없으면 이익·실수령을 확정하지 않는다. 계산 가능한 매출과 비용 소계의 범위를 표시한다.
- 재방문 판단은 같은 매장 안의 고객 구분값과 이전 실제 이용 기록을 사용한다. 타 매장의 고객 정보나 취소 예약만으로 재방문 고객을 만들지 않는다. 이름·연락처 원문은 판단 카드에 담지 않는다.
- 예약자 기준의 재예약과 실제 투숙자 기준의 재방문을 구분한다. 대리예약이나 같은 전화번호만으로 고객을 자동 병합하지 않는다. 기간 내 고객 중 재방문 고객 비중과 첫 이용 뒤 N일 내 재방문율은 다른 지표다. 후자는 기준 이용일과 N일 추적이 완료된 고객군을 정한 뒤 계산하고 미확인 고객을 따로 남긴다.
- 수량·금액 미확인을 0으로 채우지 않는다. 고객 화면의 예약수량 단위는 기존 ‘실’을 유지하고, 숙박일별 수량과 기간 누적 수량의 의미를 함께 기록한다.
- 목표 리드타임·할인율·금액·대상 기간·원가 기준은 전문가/사업주가 정하기 전 미정이다. 현재 검토 규칙의 숫자를 성과가 검증된 업계 기준으로 옮겨 쓰지 않는다.

## 저장 경계와 연결 구조

공통 판단 카드에는 개인정보나 개별 숙소의 실제 가격을 담지 않는다. 이후 실제 적용 기록은 `customerId + companyId + productId + stayPeriod`에 귀속해 인사이트 영속 저장소에 별도로 보관한다.

적용 기록에는 `cardId`, `catalogVersion`, `cardRevision`, 근거 수집 번호·업체 통합 계산 버전·관측 기준일, 입력 출처와 확인 시각, 전문가 검토 여부, 사업주의 실제 선택을 연결한다. 자료를 새로 읽어도 이미 기록한 제안·실행·발행본을 덮어쓰지 않는다. 공통 노하우와 개별 매장의 예외·성과를 분리한다.

자료 흐름: 데이터랩의 저장 근거/사업주 실제 기록 → 필요한 조건 점검 → 전문가가 검토한 카드의 적용 초안 → 사업주 선택·실행 기록 → 조건을 맞춘 결과 회고. 카드 편집이나 화면 열기가 수집 또는 쿠폰 발급을 일으키지 않게 한다.

## 화면 구성

이번 로컬 검토 화면에는 방향 출처, 초안 상태, 미정 조건, 필요한 자료와 판단 질문을 우선 노출한다. 카드 안에서 해석·행동·예외·중단 조건·지표를 펼쳐 확인한다. 숫자 입력, 실제 업체 연결, 승인·발급·수집 버튼은 만들지 않는다.

후속 운영 화면의 제안은 대상 상품·숙박일, 확인한 흐름, 경험에 따른 해석, 권장 행동, 제외 조건, 다음 확인 결과로 구성한다. 홈에는 우선 검토할 1~3개 판단을 노출하고, 전체 숙박일 보기와 기존 근거 확인은 유지한다.

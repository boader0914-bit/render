# 업체 DB 검토 카드 UI 개선

대상은 운영 웹의 업체 DB 상세 → 검토·수정 도구다. 우이동가족캠핑장(`cmp_place_1066973528`)에서 라이트·다크 모드의 불일치를 확인했다. 인사이트·BG·예약 워커는 이번 변경 대상이 아니다.

## 문제와 변경

- 검수 상태 버튼에 고정된 흰 배경·푸른 테두리를 공통 테마 색으로 덮어씌운다. 메모 입력, hover·키보드 초점, 선택된 검수 상태도 같은 테마를 사용한다.
- 검토 메뉴 5개를 PC에서 한 줄로 배치한다. 모바일은 같은 이름·순서를 유지하고 메뉴 안에서만 가로로 이동한다. 상태 버튼은 모바일에서 높이 44px 이상이다.
- 실제 펼쳐진 도구와 메뉴 선택 표시·`aria-pressed`를 함께 바꾼다. 직접 접기·펼치기, 기본정보 수정 바로가기, 채널 보정 바로가기에 동일 동작을 사용한다.
- 업체별 열린 도구와 접기 선택을 브라우저 메모리에서 보관한다. 상세자료를 비동기로 불러오거나 검수 상태를 저장하면서 화면을 다시 그려도 사용자의 선택이 유지된다. 이 UI 상태는 업체 DB·원본·서버 설정에 저장하지 않는다.
- 도구 안의 중첩 테두리와 지나치게 작은 버튼·굵은 글자를 정리한다. 테마 CSS 변경은 해당 도구 안으로 한정한다.

## 로컬 검증

- 신규 실제 함수 기반 검사: 메뉴 5개 선택, 접근성 상태, 직접 펼침/접기, 비동기 자료 로딩, 업체 전환, 이전 DOM 이벤트 무시 통과.
- 수정 바로가기 회귀 통과. 기존 화면 탐색 120개, 통합 DB·업종 UI·예약 색상 관련 41개 통과.
- 공통 테마 대비 검사 통과(71 라이트·25 다크 선택자, 16 예약 색상 검사).
- 외부 요청을 금지한 모의 자료 서버에서 PC와 모바일 390px을 확인했다. 두 모드에서 메뉴 5개 모두 열린 내용과 선택 표시가 일치하며 페이지 폭 390px, 문서 폭 390px으로 가로 넘침이 없었다. 메뉴 자체는 폭 282px 안에서 516px의 항목을 가로로 보여준다.
- 모의 업체에서 검수 완료 상태를 저장한 뒤 열린 카드와 선택 표시 유지, 라이트의 연녹색 선택 상태 및 다크의 어두운 버튼과 밝은 글자 표시를 확인했다. 운영 업체의 검수 상태를 변경한 검사가 아니다.

## 배포 전 확인한 별도 메모리 오류 보완

카드 변경 배포 전, 기존 `5822227` 운영 프로세스에서 2026-10-11 23:44:39 KST 힙 메모리 부족 종료 및 23:44:41 재시작을 확인했다. 수집 작업은 없었으며 원본·설정 파일 해시는 이전 확인과 같았다. 이 기록만으로 실패 당시의 원인 객체를 확정할 수는 없다.

- 업종 계산의 원본 재사용 캐시는 추가 업종 요청 때만 만료를 처리해, 다른 엔진 조회까지 원본을 붙잡을 수 있었다. 완료 후 30초 타이머로 자동 해제하며, 교체·무효화·종료 시 취소한다. 이전 타이머의 새 캐시 삭제를 막고 타이머에 원본을 포획하지 않는다.
- 업체 통합 엔진의 선택 업체 메타데이터는 전체 원본 목록을 보관하지 않고 필요한 객실 기준·보정값·검색 노출·회차 상태만 보관한다. 원본 파일, 계산 규칙, 응답 수치 및 수집 설정은 변경하지 않는다.
- 업종 원본 읽기·저장·변경 감지 65개 검사와 API 회귀를 통과했다. 별도 120MiB 힙 모의검사에서 다음 업종 조회 없이 타이머만 실행한 뒤 모든 이전 원본 행의 참조 해제를 확인했고, 다른 엔진의 모의 원본 할당 및 원본 해시 보존 검사를 통과했다.
- 업체 통합 회귀(53회 원본 읽기) 및 API 검사도 통과했다. 별도 GC 모의검사에서 이전 전체 목록 보관은 7종 원본 객체를 유지했고 축약 후에는 모두 해제했다. 전체 조회 응답과 저장 월 파일(`sourceDigest` 포함), 원본 관측 JSON이 같았다.
- 이 보완은 불필요한 장기 보관 경로를 줄인다. 만료 전 서로 다른 엔진의 읽기, 대형 원본 단독 파싱 등의 최고 메모리까지 보장하는 검사는 아니며 운영 오류 전체 해결로 단정하지 않는다.

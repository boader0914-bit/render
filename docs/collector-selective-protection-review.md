# 수집기 보호 검토 후 선택 해제

네이버 제한을 감지하면 기존과 같이 모든 수집기의 새 요청을 중단한다.
관리자가 실제 오류를 검토하여 문제된 수집기는 보류하고 나머지만 해제하기로 결정한 경우 아래 관리자 API를 사용한다.

`POST /api/collector-review-release`

```json
{"confirm":"resume-unaffected-after-review","heldWorkerKey":"manual","holdThrough":"2026-10-10"}
```

- `holdThrough`는 요청 당시 한국시간 오늘 날짜여야 한다.
- 모든 수집기의 실행과 대기 작업이 없을 때만 적용한다.
- 보류 대상의 원래 `COLLECTOR_PROVIDER_BLOCKED` 정보는 `reviewHold.sourceBlock`에 보존한다.
- 보류 대상은 `COLLECTOR_REVIEW_HOLD`로 유지하고 나머지의 연동 보호만 해제한다.
- 다른 원인의 보호나 별도 당일 보류까지 함께 해제하지 않는다.
- 보류한 날에는 일반 보호 해제로도 해당 수집기를 해제할 수 없다.
- 날짜가 바뀌어도 자동 재개하지 않는다. 이후 원인을 검토하고 명시적으로 해제해야 한다.
- 예약, 수집 속도, 기존 결과와 실패 기록은 변경하지 않으며 작업을 생성하지 않는다.
- 새 제한을 감지하면 전 수집기의 공통 보호가 다시 적용된다.
- 관리자 인증·동일 출처 검사를 유지한다. 중간 실패 시 모든 수집기를 다시 보호한다.
- 변경 전후의 비밀값 없는 운영 기록은 `operations/collector-protection-reviews/`에 저장한다.

중앙 웹만 배포하면 적용된다. 크롤러 실행 코드와 원격 워커의 차단 감지 코드는 변경하지 않는다.
검증은 broker/web 단위 테스트, 카드 준비 상태 테스트, 외부 통신과 실제 크롤러를 금지한 운영 웹 통합 테스트로 수행한다.

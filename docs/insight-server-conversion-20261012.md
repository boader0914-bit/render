# 0923 서버의 인사이트 전환

## 구성

- 중앙 데이터랩은 업체 DB·수집 결과·월별 집계와 별도 고객 저장소를 유지한다.
- BG(`manual`)는 기존 수집 엔진으로 예약·수동·인사이트 요청을 처리한다.
- 0923 웹서비스(`srv-d9jf91v41pts73cj9bu0`)는 인사이트 고객 화면과 중앙 API 중계 서버로 전환한다.
- 기존 무료 인사이트는 새 서버의 운영 검수가 끝날 때까지 유지한다.

고객·관리자 계정과 등록 관계는 중앙 `/var/data/customer_insight/`의 SQLite 파일에 남는다. 업체 수집 DB와 고객 저장소는 별도 파일이며 이번 변경으로 병합하거나 이동하지 않는다.

## 개발 내용

`INSIGHT_COLLECTION_WORKER_KEY`는 서버가 선택하는 인사이트 수집 대상이다. 허용값은 `manual`, `scheduled`, `web`이며 생략 시 기존 `scheduled`를 유지한다. 운영 전환 값은 `manual`이다. 고객의 임의 워커 지정은 허용하지 않는다.

새 자료 준비 작업에 `execution.workerKey`를 저장한다. 이는 업체·관측일·수집 범위의 재사용 지문과 분리한다. 설정 변경·재시작·고객 간 공유 때문에 기존 요청을 다른 워커에 재접수하지 않는다. 과거 작업에 실행 정보가 없으면 원래 영수증만 조회한다. 하루 1회 고객 제한과 관리자 면제를 유지한다.

`COLLECTOR_RETIRED_WORKER_KEYS=scheduled`는 0923의 신규 수집·예약·작업 배정을 차단한다. 기존 결과·영수증·복구 자료와 이미 배정된 작업의 종료 처리는 보존한다. 상태와 카드는 ‘인사이트 서버로 전환’으로 표시한다. 예약 파일의 원래 조건을 덮어쓰지 않고 전환 상태에서는 타이머·예약 발생·다음 실행을 중지한다. 설정을 생략하면 기존 동작이다.

## 운영 적용 순서

1. 중앙 세 수집기의 실제 진행·대기·예약·보호 상태, 0923의 미전송 자료와 저장공간을 확인한다. 진행·대기·전송이 남아 있으면 완료 확인 전 서버 역할을 바꾸지 않는다.
2. 검증한 동일 커밋의 중앙 배포에 `INSIGHT_COLLECTION_WORKER_KEY=manual`, `COLLECTOR_RETIRED_WORKER_KEYS=scheduled`를 함께 적용한다. 기존 예약 파일과 BG 보호·속도 설정은 보존한다.
3. 중앙 health와 워커 상태를 확인하고, 0923 신규 요청 거절 및 기존 자료 조회를 검증한다. 이 과정은 실제 외부 수집을 실행하지 않는다.
4. 0923의 시작 명령을 `node customer-portal/connected-server.cjs`, health 경로를 `/api/health`로 설정한다. 공개 주소는 실제 접속 주소, 중앙 주소는 `https://staydatalab.kr`이다. 같은 기존 인사이트 서버 연결키는 비밀 환경변수로만 설정한다.
5. 0923에 검증 커밋을 배포하고 로그인·내 매장·경쟁업체·지역분석·리포트 및 PC/모바일 양 테마를 확인한다. health 200만으로 중앙 인증이나 고객 화면 검수 완료로 판단하지 않는다.
6. `insight.sabun.co.kr`의 Render 등록·권한 DNS·TLS·Host/Origin을 확인한 뒤 고객 주소를 전환한다. 주소가 바뀌면 로그인은 다시 필요하다. 기존 무료 주소는 검수 종료 전 계속 유지한다.

필요한 중앙 변경은 수집 연결 대상과 전환된 워커 접수·표시뿐이다. 객실 총량·예약·매출 계산·업체 검수값·분석 집계 규칙은 변경하지 않는다.

# 인사이트 전략 준비 1단계: 비교 자료 확인

## 범위

기존 데이터랩 통합 결과에 표시용 근거를 연결한다. 경쟁분석의 현재 30일과 리포트의 전체 숙박일·월별·직접 선택 기간에서 같은 `비교 자료 확인` 구성요소를 사용한다. 객실·예약·매출 산식, 데이터랩 원본과 발행본, 정기수집 승인·예약 설정을 수정하지 않는다. 이 개발은 새 수집이나 정기수집 재개를 실행하지 않는다.

## 표시와 판단

- 업체 고유번호와 등록 관계를 유지하고 선택 업체를 한 번씩 표시한다.
- 업체별 객실 기준, 확보일/선택일, 마지막 관측일을 표시한다. 확보 범위를 계산할 날짜 근거가 없거나 일수·중복 충돌이 있으면 `확보 범위 미확인`으로 남긴다.
- 업체별 확보 범위와 업체 쌍의 공통 비교 날짜를 구별한다. 공통 날짜는 중앙 비교 결과의 명시적 날짜 목록만 사용한다.
- 수량·예약률·매출의 비교 여부를 따로 표시한다. 중앙의 비교 보류를 브라우저에서 비교 가능으로 승격하지 않는다. 수량이 확인돼도 가격이 없으면 매출 비교를 보류할 수 있다.
- 다른 지역 업체는 운영 참고로 표시하며 지역 수요가 보정된 직접 경쟁으로 해석하지 않는다. 구형 비교 결과와 저장 자료 미리보기는 최종 비교 판단을 보류한다.
- 정상 0실·0원과 미확인을 구별한다. 금액 미확인 날짜·예약수량, 확인된 매출 소계를 표시하되 전체 매출로 표시하지 않는다.
- 접힌 근거에서 수량 미확인 날짜, 금액 미확인 날짜, 수량·관측일·객실 기준의 비교 제외 사유, 업체 DB 링크를 확인한다. 관측 실패·데이유즈 공유 근거 부족 등의 원인은 허용한 코드의 쉬운 문구로만 표시한다. 외부 오류 원문과 인증정보는 표시하지 않는다.
- 최신 확인 실패 시 기존 정상 자료를 유지한다. 계산 중에는 저장 자료임을 표시하고 최종 비교로 표시하지 않는다. 경쟁분석 자동 갱신 때 펼친 근거는 유지한다.
- 로그인 상태 확인이 끝나기 전에는 비교 선택 저장소를 생성하지 않아 새로고침 시 경쟁업체 선택이 지워지지 않도록 한다. 인증 해제·계정 변경 시 기존 권한과 요청 토큰을 무효화하는 처리는 유지한다.

`customer-portal/web/comparison-readiness.js`는 입력 결과의 안전한 표시 모델만 만든다. 네트워크·저장·수집 부작용이 없다. `comparison-readiness-view.js`를 경쟁분석과 리포트가 공유하고, 두 스크립트는 기존 정적 자산 버전 관리에 포함된다.

## 실제 저장 자료를 이용한 로컬 검수

2026-10-27 한국시간의 데이터랩 관리자 조회에서 내 매장 월명 글램핑(16실), 등록 경쟁업체 해핑글램핑(15실)·럭셔리 안성M글램핑장(9실)을 확인했다. 두 경쟁업체는 모두 다른 지역이다. 내 매장의 기존 연결 확인 대기 상태를 임의 승인하지 않는다.

`GET /api/company-master/integrated?companyId=…&month=…&view=saved`로 9~11월의 저장된 집계 9개를 읽고 기존 고객용 투영을 적용한 사본으로 검수한다. 원본 재수집·복구·강제 재계산을 요청하지 않는다. 검수 자료는 저장소 밖 별도 로컬 폴더에 두며 개인정보·인증정보를 포함하지 않는다. 로컬 화면은 운영 화면으로 설명하지 않는다.

실제 자료의 선택 범위·관측 기준일은 사본에 기록된 시각을 따른다. 9월 기준 월명 30/30일, 해핑 30/30일, 안성M 3/30일이며, 월명과 해핑의 같은 관측일·숙박일 공통 비교 날짜는 10일이다. 두 업체의 월별 확보일이 같아도 관측일이 다르면 전체 30일을 동일 조건으로 비교하지 않는다. 매출 미확인과 과거 관측 공백은 복구된 것으로 설명하지 않는다.

## 검증 명령

```
npm --prefix customer-portal run check
npm --prefix customer-portal run test:comparison-readiness
npm --prefix customer-portal test
```

런타임에 npm이 없는 경우 `node --test "customer-portal/test/*.test.cjs"`로 같은 전체 테스트를 실행할 수 있다.

정기수집의 세 업체는 사본 확보 시 모두 `paused`, `nextRunAt=null`이었다. 이 기능의 조회·표시·로컬 검수 과정에는 정기수집 설정을 저장하는 경로가 없다. 운영 배포는 별도 요청 시 진행한다.

2026-10-27 개발 검수 완료: 인사이트 전체 테스트 1,203개 중 1,202개 통과·기존 1개 건너뜀·실패 0개. 실제 저장 자료 사본의 전체/9월/10월/향후 30일 범위를 확인했고, PC·390px 모바일의 라이트/다크에서 정렬·가로 넘침·미확인 표시를 검수했다. 경쟁업체 2곳 선택 후 새로고침해 내 매장 포함 3개 행이 유지되고, 보기 전환 뒤 펼친 근거가 유지되는 것을 확인했다. 운영 읽기 전용 재확인에서도 세 정기수집 예약은 `paused`, 다음 예약 없음, 진행·대기 없음이었다. 이 단계의 운영 배포는 수행하지 않았다.

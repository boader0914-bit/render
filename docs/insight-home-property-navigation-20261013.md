# 인사이트 홈·내 매장·설정 정리

## 화면 역할

- 홈: 등록 현황, 내 매장 요약과 자료 보기 링크.
- 내 매장: 한 곳이면 A. 업체 기본정보, B. 예약채널, C. 통합관측으로 바로 진입. 여러 곳이면 대상 선택.
- A. 업체 기본정보: 접힌 정보 수정·검수 요청과 요청 이력. 원본 공통 DB를 즉시 덮어쓰지 않는다.
- 설정: 등록업체 관리, 등록 해제, 자료 갱신, 개인 별칭·메모. 등록 해제는 계정의 관계만 해제한다.
- 별도 내 매장 등록 경로: `#register-own`. 단일 매장의 상세 진입과 새 등록 경로가 충돌하지 않게 한다.

## 등록 상태

일반 고객의 `pending` 내 매장은 `내 매장 확인 대기`로 표시하고 관리자 확인이 필요하다는 이유를 안내한다. 자료 조회는 기존 권한 규칙에 따라 가능하다.

`admin_preview`는 `관리자 체험`으로 표시한다. 저장된 `pending` 관계를 자동 승인하거나 기존 등록·검수 규칙을 바꾸지 않는다. 실제 관리자 승인 절차는 기존 그대로 유지한다.

## 로그인 후 저장자료 준비

로그인/세션 확인 완료 후 내 매장 우선으로 최대 네 업체를 순서대로 사전 조회한다. 기존 등록업체 결과 GET만 사용하며 새 수집을 요청하지 않는다. 사전 조회와 업체 상세의 같은 요청은 공유한다.

회사 목록에 이미 포함된 업체명·주소·검수 객실 수·시설은 상세 진입 즉시 표시한다. 상품·예약채널·통합관측을 아직 받지 못했다면 각각 자료 연결 중으로 표시하며 모르는 수량을 0으로 바꾸지 않는다.

완료 결과는 계정·업체·숙박월별 페이지 메모리 캐시에 유지한다. 기존 캐시는 최대 24항목/30분이며 메뉴 재진입 시 먼저 표시하고 뒤에서 최신 상태와 권한을 확인한다. 계정 변경·로그아웃·등록 해제·접근 거부·수정 요청은 관련 캐시를 폐기하고 이전 요청의 늦은 응답도 배제한다. 작성 중인 수정 폼은 성공·실패 응답이 덮어쓰지 않게 한다.

## 첫 조회의 한계

현재 데이터랩 API는 상품·예약채널·통합관측을 하나의 응답으로 반환한다. 이번 인사이트 전용 변경은 해당 API와 데이터랩 코드를 변경하지 않는다. 따라서 처음 방문할 때 실제 예약채널·상품은 결합 응답이 도착할 때까지 기다린다. 새로운 A/B 전용 API를 구현한 것으로 안내하지 않는다.

## 검증 및 적용 범위

- 인사이트 프런트와 테스트만 변경. 데이터랩·워커 코드, 운영 DB, 수집 일정은 변경하지 않는다.
- 프런트 전체 테스트 117개 통과. 사전조회 순서·중복 요청·계정 분리·권한 만료·수정 폼 보호·등록 한도·원본 유지 검증 포함.
- 로컬 가상 업체로 홈, 내 매장 직접 진입, 설정, 기본정보 수정 요청과 PC 라이트/모바일 다크 화면 검수.
- 운영 배포는 별도 단계다.

# 외부 저장소 개발 방향

작성일: 2026-11-14 · 상태: 설계 준비

이번 작업은 외부 저장소의 개발 방향을 정리한다. 계정·버킷 생성, 자격증명 발급·입력, 외부 연결, 자료 복사·이동·삭제, 저장 경로 전환, 운영 배포는 포함하지 않는다. 현재 개발 우선순위는 수집 화면 전체 구성 개선이다.

## 목표와 저장 역할

누적 원본은 외부에 보관하고 평소 관리자 조회에 필요한 자료는 서버에서 바로 읽을 수 있게 한다. 후보 저장소는 Cloudflare R2 Standard이며 실제 연결 방식과 저장 위치는 추후 검증한다.

| 위치 | 보관할 자료 | 조회 방식 |
| --- | --- | --- |
| Render 운영 서버 | 업체 고유 ID와 현재 운영 DB, 수집 목록·검색 색인, 최신 월별 집계와 비교선, 일정·보호 상태 | 목록·검색·차트는 서버 자료로 표시 |
| 외부 비공개 저장소 | 검증된 과거 회차 원본과 정규화 관측 묶음, 복원용 manifest | 필요한 회차·키워드·기간의 자료만 조회 |
| 용량 제한 서버 캐시 | 최근 열어 본 외부 원본의 검증된 사본 | 동일 자료 재조회 시 재사용; 상한·만료·정리 정책 적용 |

외부 저장소에서 매번 전체 원본을 내려받아 목록이나 월별 차트를 계산하는 구조는 피한다. 목록 색인에 `runId`, 수집시각, 키워드, worker, 품질·DB 반영 상태, 저장 위치·객체 키·크기·SHA-256·스키마 버전을 연결한다. 저장소 변경 후에도 화면의 실제 회차와 선택 상태를 같은 ID로 유지한다.

## 자료 구분과 중복 방지

- 원본 보관 단위는 **수집 월 → 회차(runId) → 자료 종류**를 기본으로 한다. 수집 월과 대상 숙박 월은 별도 필드로 보존한다.
- 분석 조회 단위는 **숙박 월 × 키워드 × 상품(숙박/데이유즈)**다. 한 번의 수집이 다음 달 숙박일까지 포함해도 해당 숙박 월에 연결한다.
- 파생집계는 `(companyId, stayDate, productType)`를 기준으로 최신 유효 관측을 채택한다. 같은 업체를 여러 회차에 관측한 것을 반복 합산하지 않는다. 실제 채택 규칙에는 관측시각·품질·회차 연결을 포함하며 동일시각 충돌은 감추지 않는다.
- 업체 ID, 병합·정정 이력, 원본 관측, 품질 판정과 출처 run 연결은 보존한다. 부분·누락·비공개·실제 0을 서로 구분하고 정상 관측이 없는 값을 0으로 채우지 않는다.
- 증분 처리에는 입력 지문, 처리 버전, 이미 채택한 회차/관측 키를 기록한다. 같은 완료 이벤트를 재수신해도 최종 값과 합계가 재가산되지 않아야 한다. 실패 후 재시도와 순서가 뒤바뀐 이벤트도 실자료 사본으로 검증한다.
- 가격 확인 소계와 부분 자료 소계는 현재 계산 정의를 유지한다. 정상 자료와 겹친 부분 자료를 중복 포함하지 않는다.

## 현재 코드가 요구하는 별도 개발

기존 읽기 경로는 로컬 `outputs`, `company_master/companies.json`, `history/observations.jsonl` 등에 연결돼 있다. 파일을 먼저 옮기고 경로만 바꾸면 목록·상세·이력·월별 계산이 유지된다고 볼 수 없다. 로컬/외부를 같은 `runId`로 조회하는 저장소 어댑터와 색인 연결을 먼저 개발해야 한다. 이력 색인이 파일 식별자·크기·수정시각·바이트 위치에 의존하는 부분도 새 저장 단위에 맞춰 검증한다.

`scripts/lib/keyword_monthly_source_copy.cjs`의 현재 코드에서 월별 준비용 핵심 사본 상한은 **512MiB**, 자체 임시 작업 상한은 **1GiB**다. `inspect()`와 `copy()`의 핵심 사본 계산에는 `outputs/`가 제외돼 있다. 따라서 **과거 outputs를 외부 보관하면 디스크 여유는 늘릴 수 있지만, 핵심 사본 512MiB 제한을 직접 해결하지는 않는다.** 해당 문제는 전체 핵심 이력 사본 의존을 줄이는 기간별 조회·증분 집계 개발로 별도로 해결한다. 한도나 보호 검사를 임의로 높이거나 우회하지 않는다. 이 문서의 값은 로컬 코드 기준이며 현재 운영 용량을 새로 측정한 결과가 아니다.

## 전환 순서

1. **설계 확정**: 외부 보관 대상과 서버 유지 대상을 목록화하고 현재 읽기·복구 참조를 연결한다. 대상 파일 수·용량, 복원 범위와 캐시 상한을 정한다.
2. **사본으로 어댑터 개발**: 외부 원본 읽기, 목록 색인, 무결성 확인, 제한된 캐시와 오류 표시를 구현한다. 운영 자료와 일정은 변경하지 않는다.
3. **복사·복원 검증**: 별도 승인된 대상만 복사하고 원본·사본의 바이트 수와 SHA-256을 대조한다. 외부 객체를 다시 읽어 동일성을 확인하고 격리된 경로에 복원해 실제 목록·상세·집계 기대값을 대조한다. 객체 키 존재나 업로드 응답만으로 성공 처리하지 않는다.
4. **조회 전환 검증**: 관리자 실제 목록·검색·상세·선택 회차·페이지·조회 조건을 확인한다. 수집 원본과 이력 연결, 월별 공급·예약 수량·비율을 같은 기준으로 대조한다. 새 자료 쓰기와 보관 작업이 겹치는 상황도 확인한다.
5. **제한적 운영 전환**: 검증된 범위만 전환하고 기존 로컬 원본과 되돌릴 수 있는 매핑을 유지한다. 현재 조회 경로로 되돌리는 절차를 검증한다.
6. **서버 정리 별도 판단**: 복원 검증과 운영 조회 검증이 끝나도 원본을 자동 삭제하지 않는다. 실제 복구 참조·보존 조건·예상 회수 용량을 다시 확인해 구체적인 정리 목록을 제시하고 별도 승인을 받는다.

## 장애와 화면 표시

- 외부 읽기 실패 시 기존에 검증한 집계·목록은 해당 관측시각과 함께 표시하고, 요청한 원본 상세는 읽기 실패/미확인으로 표시한다. 다른 회차 자료로 대신 채우지 않는다.
- 파일 누락·SHA 불일치·스키마 불일치·타임아웃·캐시 만료를 구분해 기록한다. 저장 실패를 정상 완료로 처리하거나 수집 원본을 덮어쓰지 않는다.
- 캐시는 전체 용량·객체별 용량·수명·동시 다운로드 수를 제한한다. 원본이 외부에서 검증됐다는 근거가 없는 파일은 캐시 정리 대상으로 자동 분류하지 않는다.
- 목록 최신화와 결과 선택은 분리한다. 목록 갱신이 기존 키워드/기간/worker/품질 조건, 입력 초안, 선택 run과 페이지를 바꾸지 않아야 한다.

## 연결과 권한

외부 버킷은 비공개로 두고 서버 전용 자격증명을 사용한다. 읽기, 복사 쓰기, 정리는 가능한 한 권한과 실행 경로를 구분한다. 키는 채팅·보고서·화면·클라이언트 JavaScript·로그에 노출하지 않는다. 실제 키 발급·입력은 별도 연결 단계에서 다룬다. 객체 경로 입력은 허용된 run/월 범위와 고정 루트 안으로 제한한다.

## 속도와 통과 기준

현재 외부 저장소의 실제 지연 시간은 측정하지 않았다. 처음 원본을 읽는 경우에는 네트워크 지연과 전송 시간이 추가될 수 있다. 배포 전 실자료 사본으로 아래 항목을 같은 조건에서 반복 측정하고 기준치를 정한다.

| 항목 | 비교할 조건 | 통과 시 확인할 내용 |
| --- | --- | --- |
| 보관함 목록·검색 | 기존 로컬 / 새 색인 | 외부 전체 원본 읽기 없이 동일 목록·필터·순서·페이지 표시 |
| 월별 분석·비교선 | 기존 저장 집계 / 새 저장 구조 | 동일 기준 수량·비율·누락 상태, 요청마다 전체 이력 재계산 없음 |
| 과거 회차 상세 | 로컬 / 외부 첫 조회 / 캐시 재조회 | 내용·SHA 일치, 읽은 바이트·요청 수·대기 시간 비교 |
| 장애 | 외부 타임아웃·누락·무결성 오류 | 기존 목록 유지, 잘못된 성공·0 표시 없음, 제한 내 종료 |
| 증분 처리·복원 | 중복 이벤트·부분 자료·순서 역전·복원 | 중복/상충 키 검사, 최신 유효값 채택과 전체 합계 일치 |

평균과 느린 요청 구간(p95), 파일 크기, 캐시 적중 여부, 총 다운로드 바이트를 함께 기록한다. 외부 보관 도입만으로 모든 화면이 빨라진다고 보장하지 않는다.

## 유지 조건

정규 하루 6회 일정·기존 간격·호출 한도·동시 요청·보호 장치, 수집 원본·이력과 KOSIS 전면 보류를 유지한다. 외부 저장 작업은 기존 네이버 수집을 실행·재실행하거나 누락분을 소급 수집하지 않는다. 본 계획은 운영 정책이나 보호 중단 기준을 변경하지 않는다.

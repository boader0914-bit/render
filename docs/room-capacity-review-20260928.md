# 숙박 상품 전체 조회와 객실 수 검토 경고

## 수집 범위

숙박 상품 조회의 업체별 40개 상한을 제거한다. 첫날과 이후 숙박일에 목록으로 확인된 모든 숙박·미분류 상품을 조회한다. 날짜별 상세 저장의 80개 상한도 제거한다. 같은 상품 ID만 중복을 제거하며, 같은 이름의 별도 상품은 저장 후 검토 대상으로 표시한다. 상품 수를 물리적 객실 수로 확정하지 않는다.

`selectProductTargets(items, 0)` 또는 생략은 전체 상품이다. 양의 정수는 명시적 제한이다. 별도 데이유즈 상세 20개 제한과 요청 간격·동시성·차단 중단·재시도·예약 일정은 그대로다. 전체 조회 상품 수가 늘어난 업체는 요청량과 소요시간이 늘 수 있다. 전체 상품 목록 자체가 불완전하거나 요청이 실패하면 해당 진단을 유지한다.

이전 결과를 재수집하거나 원본 자료·기존 완료 상태를 변경하지 않는다. 오래된 40개 제한 기록은 기존 미조회 근거로 남는다.

## 객실 수 경고

기본 총량은 최대 관측 수량, DB 검수값이 있으면 검수값 우선이다. 공개 객실 안내는 참고값이다. 경고 생성은 총량·예약·매출 산식을 바꾸지 않는다.

`capacityReview`에는 원인 코드, 심각도, 적용 범위, 설명과 근거를 저장한다. 근거 없이 신뢰도 점수를 만들지 않는다.

- 미검수 글램핑의 최대 관측 수량이 40실을 넘으면 검토 경고를 표시한다. 40은 수집·계산 상한이 아니다.
- 같은 객실명의 일반·연박 등 중복 상품 후보, 다른 시설 유형 혼합, 묶음형 상품을 경고한다. 이름만으로 중복 재고를 자동 차감하지 않는다.
- 상품 목록·조회 범위가 불완전하거나 객실 재고 근거가 부족하면 경고한다. 수집 범위는 해당 예약 업체 번호와 정확히 일치하는 manifest 자료만 사용한다.
- 정상 응답 재고 0과 실패·차단·누락을 구분한다. 정상 0만으로 객실 총량 감소를 확정하지 않는다.
- DB 검수 총량이 있으면 중복·혼합·자료 부족은 참고로 표시한다. 수집 수량이 검수값을 넘는 등 충돌은 ‘수집 수량 확인’으로 경고하면서 검수값을 유지한다.
- 충분한 전체 상품 재고가 확인된 날짜가 있고 다른 날짜만 일부 누락된 경우에는 관측 참고로 구분한다.

수집 결과의 접힌 카드와 상세 화면, 업체 DB의 객실 기준 카드에 빨간 아이콘·문구·사유를 표시한다. 라이트·다크 테마를 각각 적용하며, 색상만으로 정보를 전달하지 않는다. 수집의 완료/일부 완료와 객실 총량 신뢰도 경고는 서로 별도다.

과거 업체 DB는 저장된 상품명·날짜 요약과 현재 DB 검수값으로 경고만 읽기 재평가한다. 상품별 최대값을 정상 재고 응답으로 되살리지 않으며, 저장되지 않은 실패 원인도 만들어내지 않는다. 조회에서 DB 쓰기·추가 수집·원문 복구를 새로 호출하지 않는다.

## 검증

외부 네이버 요청 없이 68개·85개 상품의 여러 날짜 전체 조회 및 저장, 상품 ID 중복, 명시 제한, 차단 이후 신규 요청 중단을 모의 검증한다. 총량 경고 테스트에는 DB 우선 적용, 동일 객실 후보, 시설 혼합, 정상 0/오류 0, 과거 미조회 기록, 날짜 누락, 계산값 불변을 포함한다.

- `node --test scripts/test_collector_product_coverage.cjs scripts/test_collector_crawler_contract.cjs`
- `npm run test:shared-inventory`
- `node scripts/test_worker_cards_integration.cjs`
- `node scripts/test_surface_contrast.cjs`

검증은 실제 대량 수집의 성공을 뜻하지 않는다. 운영에서는 다음 사용자가 시작한 수집의 manifest에서 대상·조회·성공·실패·누락 수를 확인한다.

추가로 실행한 `test_collector_day_use.cjs`의 ‘미수집 데이유즈가 있는 경우 전화예약 추정 0’ 기대값 1건은 이전 커밋 `32e0c16`에서도 동일하게 실패했다(현재 정책의 결과는 4). 이번 변경에서 예약·매출 정책이나 해당 기대값을 바꾸지 않았다. 이번 기능의 상품 조회·경고·저장·차단 및 월간 재계산 회귀 검증은 통과했다.

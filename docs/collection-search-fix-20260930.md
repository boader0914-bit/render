# 조천숙소·제주바블 검색 실패 수정

## 확인된 원인

- 운영 기준 커밋: `cc94b72be2d395f09cc4b201dad1fba556f9f3db`.
- 조천 숙소(2026-09-30): 예약 일정 조회 308건 성공 후, 요청의 빈 `searchRegion`이 결과에서 `조천`으로 바뀌어 `COLLECTOR_SCOPE_MISMATCH`로 등록 실패.
- 제주바블(2026-09-29): 일반 키워드 모드에서 첫 검색 후 실행 실패. 결과의 지역값도 달라 검증 오류가 최초 실패를 가렸다. 당시 최초 응답/예외 내용은 보존되지 않아 세부 원인은 확정하지 않는다.
- 기존 함덕 복구 기능은 과거 보존자료의 복구 경로이며, 새 수집의 빈 지역값 처리 오류는 별도로 남아 있었다.

## 변경

1. 요청에 `SEARCH_REGION`이 있으면 빈 문자열도 그대로 유지한다. 필드가 없는 기존 CLI 호출만 이전 지역 추론을 유지한다. 결과 검증기의 조건 비교는 완화하지 않는다.
2. 워커 카드의 검색 대상을 `지역·키워드` 또는 `업체명`으로 선택한다. 즉시수집과 예약 설정 모두 전달하며 기존 설정에 필드가 없으면 종전 키워드 모드를 유지한다. DB에서 넘어온 업체명 검색 모드도 보존한다.
3. 최초 검색 실패의 알려진 오류 코드, 단계, HTTP 상태, 검색 시도 기록을 실패 결과에 저장한다. 결과 조회와 진단 화면에도 전달한다. 원문 응답, 스택, 쿠키, 자격증명은 저장하지 않는다. HTTP 200은 검색/예약 성공을 뜻하지 않는다.
4. 네이버 차단 감지, 실패 결과의 파생 DB 반영 금지, 당일 중복수집 보호, 워커 속도는 변경하지 않는다.

## 검증

- 단위·계약 테스트 184개 통과: 빈 지역 유지, 업체명 `placeList` 응답과 이름 필터, 검색 응답 해석 실패/HTTP 오류, 실패 기록 정제, 예약 모드 전달, 엄격한 결과 검증, 차단 보호, 중복 보호.
- 검색 모드 분류 및 패키지 `check` 통과.
- 로컬 HTTP 통합 검증: 운영 웹 실행/검증, 세 워커 결과의 중앙 보관함·업체 DB 연결, 기존 보존자료 복구와 거절 조건, 진단 API의 읽기 전용·비밀정보 제외.
- 테스트는 모의 응답과 임시 저장소를 사용한다. 네이버 실제 수집, 운영 DB 수정, 기존 실패 자료 복구는 수행하지 않는다.

# 정규 6회 전환과 주간 수집 모니터

관리자가 날짜별 시간·키워드를 한 화면에서 확인할 수 있도록 선택일 카드, 키워드별 월~일 표와 슬롯 상세를 추가한다. 화면은 실제 저장 배정·하루 시험·현재 설정으로 계산한 예정·기록 미확인을 구분한다. 정상 완료는 같은 배정/실행의 품질과 DB 반영이 모두 맞을 때만 표시한다.

`GET /api/collection-monitor`는 관리자 전용·7일 범위·`private,no-store`이며, 초기화된 순환 DB와 후처리 메모리의 제한된 snapshot만 읽는다. 미초기화·닫힘·누락·크기 초과는 unknown/unavailable로 유지하며 일정 할당·복구·수집을 시작하지 않는다. 화면이 보이는 관리자에게만 15초 조회를 적용하고 로그아웃/권한 오류 시 이전 데이터와 늦은 응답을 폐기한다.

기존 전체 설정 저장은 정지 시 queued 예약을 변경하므로, 정규 횟수 변경에는 `POST /api/collection-rotation/daily-limits`를 사용한다. `workers`와 `expectedRevision`만 받으며, 기존 수집기 순서/정체성 및 나머지 조건을 유지하고 새 revision의 일일 배정 수만 저장한다. 이미 배정된 날짜·슬롯·커서·시험·enabled·보호는 바꾸지 않으며 다음 미배정 날짜부터 적용한다. active/ticking·보호·불확실 실행·미래 시험·충돌·stale revision은 무변경 거절한다. UI의 정규 6회 전환은 현재 09시·120분·웹 2+BG 2인 정상 활성 설정에서 웹 3+BG 3만 요청한다.

## 검증

- 순환·하루 시험·후처리·모니터·공식 횟수 전환·UI 회귀 테스트.
- 실제 오늘 4 queued와 과거 이력/시험/커서/조건이 보존되고 다음 날짜만 6이 되는 fixture.
- 보호 중단을 재활성화하지 않는 guard, admission 이후 CAS/자정/정지 경합.
- 조회의 I/O/상태 변경 0, SQL 응답·행 수 상한, 민감 receipt 제외와 정확한 DB 연결.
- 관리자/메서드/JSON/명시적 same-origin 경계와 무변경 실패.
- 저장 4·시험 6·계산 6, 조건 21일·1–20위, 날짜/검색/수집기/상태 필터, 키보드 focus, 로그인 만료.

이번 소스 변경은 요청 gate·동시 요청 설정·호출 한도·collector 실행 payload·기존 실제 간격 계산·KOSIS 모듈을 수정하지 않는다. KOSIS 검수와 native 초기/주간 보완은 기존 보류를 유지한다. 운영 반영과 설정 저장 후의 실제 첫 적용일·배정 및 보존 결과는 별도 운영 영수증으로 확인한다.

# 관광지수·KOSIS 실제 응답 원본 보관과 범위 근거 연결

2026-10-17 개발·독립 검수 기준. 신규 외부 API 호출, 운영 배포 또는 운영 저장 자료 갱신을 승인·완료했다는 기록이 아니다.

## 목적

앞으로 기존 승인된 지표 갱신을 실행할 때 관광지수와 KOSIS의 실제 응답을 보관한다. 보관 원본을 재검증한 뒤 같은 지역·기간·지표의 저장 결과와 연결한다. 정리된 숫자나 요청 지역을 원본 응답으로 재생성하지 않는다. 특정 지역에만 적용하는 예외는 두지 않는다.

방문자 원본 복원 기능은 기존대로 유지한다. 체류·소비, 관광자원 수요, 관광 다양성은 operation별 원본이 대상이다. KOSIS는 표별 getMeta/getList 응답 쌍을 보관한다. 원본이 남아 있지 않은 과거 자료를 새로 확보한 원본으로 소급 검증하지 않는다.

## 자료 흐름

1. 기존 관리자 갱신 또는 이미 승인된 갱신 작업이 공급자 응답을 받는다.
2. 응답 본문을 기존 엄격한 파서로 해석한다. 관측 0, 누락, 비공개·억제, 공표 대기, 오류와 범위 불일치를 구별한다.
3. 요청의 안전한 식별 정보와 실제 원본 응답을 공유 보관 모듈에 전달한다.
4. 원본 파일을 불변으로 저장한 뒤 원본 번호·의미 해시·안전한 참조를 해당 캐시에 연결한다.
5. 저장 자료 정리 작업에서는 참조된 원본만 읽고 공급자별 파서로 재검증한다. 성공한 월·연도·operation에만 근거를 연결한다.
6. 화면은 저장된 파생 결과를 읽는다. 일반 GET과 화면 진입은 외부 요청, 원본 저장, 큰 원본의 재검사를 시작하지 않는다.

## 공유 보관 인터페이스

공유 모듈 `scripts/lib/regional_response_evidence.cjs`는 원본 파일의 안전성과 무결성을 담당하고, 실제 지역 범위·지표 의미의 검증은 공급자별 모듈이 담당한다.

- `write({ kind, identity, response, secretValues })`: 허용한 종류와 안전한 식별 필드, 실제 응답을 검증한 뒤 불변 파일과 참조를 반환한다.
- `read(ref, { kind, identity })`: 허용된 원본 경로와 의미 해시, 예상 종류·식별 정보가 일치할 때만 본문을 반환한다.

`kind`와 식별 필드는 형식·길이를 제한한다. 인증키, 쿠키, 토큰, 헤더, 환경변수, 비밀값이 포함된 전체 URL을 식별 정보에 넣지 않는다. 요청값과 실제 응답에서 확인한 지역·기간은 구별한다. 원본 번호·해시·경로만으로 공급자 응답의 지역 범위가 검증된 것은 아니다.

보관 대상은 KOSIS의 실제 메타데이터·자료 배열과 관광지수의 실제 응답 행·페이지 번호·전체 개수·응답 코드 등 검증 진단이다. 관광지수는 기존 요청 파서가 추출한 검증 대상 행과 페이지 정보를 사용하므로 공급자 HTTP 본문의 모든 필드를 복제하는 기능이 아니다.

공유 보관 모듈은 전달받은 JSON 객체의 키를 정렬한 정규 JSON을 저장하며, 전달받은 모든 필드의 값·형식과 배열 순서를 보존한다. 공급자에게서 전송된 HTTP 본문의 공백·키 순서까지 같은 바이트 사본이나 전체 HTTP 헤더를 뜻하지 않는다. 안전하지 않은 보관 대상은 일부 필드를 임의로 지워 저장하지 않고 보관을 거부한다.

## 파일과 비밀값

- 보관 크기의 상한은 32MiB다. 직렬화·파일 크기·읽은 바이트 상한을 모두 검사한다. 읽기는 상한을 넘기기 전에 중단할 수 있어야 한다.
- 파일은 허용한 원본 폴더 안의 정확한 경로여야 한다. 상위 경로 이동, 절대 경로 주입, 다른 폴더로 빠지는 심볼릭 링크를 거부한다. 파일 종류와 실제 경로를 확인하고 검사 중 변경을 감지한다.
- 새 공유 보관 파일은 정규 JSON의 의미 해시와 실제 저장 바이트의 해시가 모두 참조 SHA-256과 같아야 한다. 의미가 같은 JSON이라도 파일의 키 순서·공백·바이트가 바뀌면 변조로 거부한다. 기존 방문자 원본은 과거의 보기 좋게 저장한 JSON과 의미 해시 정책을 그대로 따르며 이 새 파일 형식으로 임의 변환하지 않는다.
- 임시 파일을 완전히 저장한 뒤 배타적으로 게시한다. 같은 원본 번호가 이미 있으면 기존 내용과 무결성을 검사하고 재사용하며 덮어쓰지 않는다. 손상된 기존 파일은 자동 교체하지 않는다.
- 같은 종류·식별 정보·응답 본문은 같은 내용 식별자로 재사용한다. 보관·검사 시각만 달라져 파일이나 파생 결과를 계속 새로 만들지 않는다.
- 공급자가 비밀값을 응답에 그대로 되돌려주는 경우도 고려한다. 알려진 비밀값의 원문·인코딩 표현이 보관할 자료에 포함되면 저장을 거부한다. 비밀값을 가린 본문을 변형 없는 원본이라고 표기하지 않는다.
- 같은 실행에서 원본 보관 실패만을 이유로 공급자 요청을 자동 반복하지 않는다. 사용자가 나중에 별도의 갱신 작업을 명시적으로 시작하면 기존 잠금·호출 예산·보충 정책에 따라 필요한 요청을 한 번 수행할 수 있다. 실제 정상값을 0으로 바꾸거나 이전 정상 캐시를 소실시키지 않고 보관 실패 진단을 별도로 남긴다. 보관하지 못한 파일을 저장·복원 완료로 표시하지 않는다.
- 로그·공개 오류·화면 근거에는 안전한 오류코드와 원본 ID·해시·검증 기간만 사용한다. 원본 경로·응답 본문·비밀값을 오류 메시지에 포함하지 않는다.

## 관광지수별 검증

원본은 공급자·자료 종류·adapter와 버전·실제 월·요청 범위·operation에 연결한다. 페이지가 여러 개면 페이지 번호, 전체 개수, 수신 행 수, 응답 코드와 정상 여부를 보관해 전체 범위를 판정할 수 있어야 한다.

다음 조건이 같은 저장 관측과 일치할 때만 보관 원본의 범위 근거를 복원한다.

- 실제 응답의 지역 코드와 이름, 시·도 또는 시·군·구 수준
- operation과 지표 코드, 전체 지표와 세부 지표의 구별
- 실제 기준월, 수치, 단위, 정상·누락·부분 상태
- 페이지 완전성, 중복·충돌, 잘못된 지역·기간 행

정상적인 전체 지역 응답은 대상 지역을 정확히 추출해 검증한다. 다른 지역 행을 대상 지역으로 대신 사용하거나 합산하지 않는다. 다른 operation의 원본을 동일 값이라는 이유로 재사용하지 않는다. 부분 응답은 전체 정상 응답으로 승격하지 않으며, 기존 파서가 전체 지표 하나의 완전성을 명시적으로 인정하는 정책과 자료 묶음 전체의 완전성을 구분한다.

## KOSIS 검증

같은 표의 실제 getMeta/getList 응답을 함께 보관한다. 기관·표·정의 버전·분류 체계와 실제 기준기간을 연결한다. `newEstPrdCnt=1`은 최신 자료를 요청하는 조건이며 특정 월 또는 연도의 자료가 확보됐다는 뜻이 아니다. 실제 응답 `PRD_DE`와 `PRD_SE`를 기준으로 한다.

복원에서는 원본 메타데이터의 지역명·상위 지역 관계로 C1 매핑을 다시 검증하고, 실제 getList 행의 C1, 표, 항목, 세부 분류, 단위와 기간을 검사한다. 재파싱한 결과의 값·0·누락·억제 상태가 보관 캐시와 같아야 한다. 정리된 rows에서 C1을 임의로 붙인 자료는 복원 근거가 아니다.

같은 이름의 다른 시·도 지역은 서로의 원본을 공유하지 않는다. 별칭은 동일 원장 식별자로 연결되는 경우에만 허용한다. 하위 구 값을 상위 시의 지수로 합산하거나 임의 평균하지 않는다.

## 기간과 파생 저장

근거의 기간은 월간은 `YYYY-MM`, 연간은 `YYYY`로 검증한다. 실제 관측 행의 공표 주기와 근거 기간 형식·값이 모두 같아야 한다. 월간·연간 근거를 서로 바꾸거나 연간 값을 월별로 반복하지 않는다. 최신월 근거를 과거 기간 전체에 전파하지 않는다.

기간별 저장 결과에 안전한 원본 번호·해시·검사 버전·검사 항목·검사 시각을 연결한다. 공개 저장 결과에는 원본 파일 경로를 넣지 않는다. 검증 상태는 `restored`, `already_verified`, `pending`, `rejected`를 구분하고 완료 상태의 사유가 빈 값이라는 이유로 실패 코드로 바뀌지 않게 한다.

근거가 추가되는 실제 변경은 파생 결과의 입력 지문에 반영한다. 검사 시각만 바뀌는 경우는 지문에서 제외한다. 새 결과를 만들더라도 이전 원본·캐시 이력·발행 결과는 보존한다. 미검증은 정상 수치와 구별해 남기며, 실제 지역 불일치가 확인된 관측은 기존 정상 자료 복원 정책으로 되살리지 않는다.

원본 보관 실패는 `EVIDENCE_WRITE_ERROR`로 자료 준비 기록과 지역 자료 관리에 남긴다. 관광 갱신의 `response_evidence_storage_failed`도 이 안전한 코드로 정리한다. 정상 관측 행의 값·0·확보율은 유지하며 API 응답 실패와 구별해 **응답 원본 보관 실패 · 저장된 지표 유지**를 표시한다. 자료 준비 기록을 다시 읽어도 실패 원인이 사라지거나 공급자를 다시 호출하지 않는다.

## 성능과 반복 확인

원본 검사는 명시적 저장 자료 재정리와 기존 배경 계산에서만 실행한다. 같은 파일을 동시에 검사할 때는 공유 작업을 사용하고, 결과의 작은 요약만 제한적으로 재사용한다. 원본 버퍼나 대형 JSON을 장기간 메모리에 보관하지 않는다.

현재 정리 작업은 최대 36개월을 읽으므로 요약 재사용 범위도 이를 고려해 여러 지역 순차 처리에서 전체 원본을 반복 해싱하는 일을 피한다. 파일 내용·식별자·크기·수정 정보가 바뀌면 기존 성공 결과를 그대로 재사용하지 않는다. 일반 화면의 2초 목표는 배포 후 실제 자료의 저장 조회와 실제 렌더링을 구별해 측정한다.

## 격리 검증 완료 기준

1. 새 지역 fixture에서 관광 operation별·KOSIS 표별 정상 원본 보관 후 캐시 재시작·명시적 재정리·공통월 또는 공통연도 비교까지 외부 통신 없이 재현한다.
2. 월간·연간의 정상 0, 누락·억제·부분 응답 상태와 값·단위·기간을 보존한다.
3. 해시, 원본 ID, 지역, 상위 지역, 표, operation, 지표, 단위·기간·주기, 값·페이지가 하나라도 다르면 근거를 승격하지 않는다.
4. 경로 이탈·심볼릭 링크·파일 손상·과대 파일·비밀값·기존 파일 충돌·쓰기 실패를 안전하게 거부한다.
5. 원본 보관 실패나 부분 자료가 이전 정상 자료를 덮어쓰지 않는다. 같은 실행에서 보관 실패만을 이유로 공급자를 자동 재요청하지 않으며, 나중에 시작한 별도의 명시적 갱신은 기존 보충 정책을 따른다.
6. 일반 cache GET·지역 화면 GET은 원본 파일 생성·변경·큰 원본 재검사·외부 요청을 일으키지 않는다.
7. 같은 응답·같은 근거는 재사용되고 실제 정정 응답은 새 원본과 결과를 만든다. 과거 파일의 바이트 해시는 유지한다.
8. 보관 원본이 없는 기존 자료는 미확인을 유지한다. 임의로 원본을 복원하거나 새 자료를 과거 월에 적용하지 않는다.

운영 배포, 실제 API 갱신, 기존 저장 자료 재정리와 실제 화면 검수는 이 개발 기준의 로컬 검증과 별도로 승인·수행·기록한다.

## 로컬 검증 기록

- 공유 보관·관광 7개 operation·KOSIS·기간 계약·지역 저장·비교·자료 준비 및 화면 진단 시험: 310개 통과, 실패·건너뜀 0개.
- 실제 공급자 모듈을 사용하는 격리 지역 2곳의 통합 시험: 관광 7개, KOSIS 월간 26개·연간 6개 지표가 공통월·공통연도 비교까지 연결됐다. 서로 다른 수치와 정상 0으로 항목 연결을 확인했다.
- 원본 참조 없는 과거 캐시: 값을 유지하면서 보관 근거는 미확인으로 남겼다. 다른 지역 원본을 빌려 비교하지 않았다.
- 서비스·저장소 재시작 뒤 재사용 조회: 원본 경로 접근·새 계산·외부 요청·파일 변경이 없음을 감시해 확인했다.
- 격리 앱의 저장 결과 재사용 API와 지역 자료 준비·월간 리포트 API: 통과. 실제 외부 통신은 차단한 시험이다.
- 지역 분석·전망의 실제 앱 API 최종 실행도 통과했다. 앞선 실행에서는 전망의 후속 작업 대기가 간헐적으로 시간 초과됐으며, 변경 전 `bd4bd3a`에서도 같은 입력 지문과 대기열 현상으로 재현됐다. 진단 실행과 최종 현재 버전 실행은 통과했다. 실패한 기준 버전 응답에는 `REGIONAL_STORE_UNAVAILABLE`도 있어 구체 내부 예외를 추가로 확인해야 한다. 원본 보관 변경 때문이거나 특정 대기열 경합이라고 단정하지 않으며, 전망 저장·후속 작업의 간헐 실패는 별도 개선 대상으로 남긴다. 이는 전체 회귀 실행이 항상 안정적이었다는 뜻이 아니다.
- Windows의 디렉터리 junction 거부는 검증했다. 파일 symlink 생성은 호스트 권한이 없어 해당 세부 검사를 실행하지 못했으며, 이를 실제 파일 symlink 검증 완료로 보고하지 않는다.

`npm run test:regional-stored-evidence`는 원본 보관·재검증의 집중 시험이며, `npm run test:regional-common-criteria`는 저장·비교·자료 준비와 앱 API까지 포함하는 회귀 시험이다. 로컬 가상 자료의 조회 시간은 운영 화면 2초 목표 달성 증거로 사용하지 않는다.

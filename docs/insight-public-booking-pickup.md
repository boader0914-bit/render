# 인사이트 공개예약 독립 증감

공개예약 관측 변화는 전체 예약수량·객실 기준·방막기·매출 판정과 별도로 검증한다. 전체 재고가 데이유즈 공유 미확정으로 보류돼도, 같은 상품의 정상 공개예약 원본은 독립 비교할 수 있다. 전체 예약수량과 예약률의 보류를 해제하지 않으며 신규 예약·취소 확정 건수로 표현하지 않는다.

## 계산 기준

- 업체 번호·플레이스 번호·수집번호·관측시각을 모두 연결한다.
- 숙박상품 번호·목록 유형·수량 단위·재고 기준이 같은 날짜만 비교한다.
- 원본의 HTTP 정상 응답, 수집 오류 없음, 재고·관측 확인, 정수 공개예약 수량, 수량 충돌 없음을 검증한다.
- 데이유즈, 전화예약 안내용 상품, 방막기·재고 차이·매출을 공개예약에 섞지 않는다.
- 최신 두 관측 회차의 동일 숙박일을 비교한다. 상품 구성 변경·중복 충돌·불명확한 응답은 미확인으로 남기며 조용히 더 오래된 회차로 대체하지 않는다.
- 정상 0과 음수 변화는 유지한다. 여러 달에 같은 근거가 전달돼도 같은 관측 구간·상품·숙박일은 한 번만 계산한다.
- 계산 결과는 `publicOnly=true`, `inferredChange=null`, `wholeReservationRestored=false`, `actionable=false`를 유지한다.

## 연결과 저장

데이터랩 신규 API와 수집은 추가하지 않는다. 인사이트의 기존 권한 검증을 통과한 업체별 저장자료 GET에만 `publicBookingPickup` 필드를 덧붙인다. 기존 업체·기간·고객 권한 확인이 실패하면 로컬 근거도 제공하지 않는다.

원본 근거는 인사이트 영속 디스크의 `insight-public-bookings` 전용 폴더에 연결 서버 구분·업체 번호의 해시로 분리한다. 실제 운영 기본 경로는 `/var/data/insight-public-bookings`이며, 명시적 설정은 `INSIGHT_PUBLIC_BOOKING_DIR`이다. 공개 정적 파일 경로나 고객 업로드 API를 제공하지 않는다.

`public-booking-pickup-store.cjs`의 `importLedger()`는 검증된 정규화 원본만 받는다. 원본 파일의 SHA-256과 정규화 자료의 내용 해시를 보존하고, 동일 수집번호의 다른 내용은 거절한다. 원본은 내용별 파일에 보관하고 색인은 원본 저장 성공 후 교체한다. 이전 색인도 내용별 파일로 유지한다. 빈 등록·오류 등록은 기존 정상 자료를 지우지 않는다. 가용 공간 200MiB 이하이면 등록하지 않는다.

원본을 가져오는 운영 작업은 원본 파일의 해시를 실제 확인한 뒤 업체 번호와 함께 `importLedger()`에 전달한다. 일반 업체 조회 응답은 응답 단위·원문 확인값 등이 생략되어 있으므로 없는 검증 정보를 만들어 등록하지 않는다. 향후 원본 연결 작업 전에는 검증된 저장 원본 가져오기로만 보완한다.

## 2026-10-30 보완 범위

피카푸와 앤더포레의 저장 원본 2026-10-27 / 2026-10-28 두 회차를 가져온다. 공통 숙박일 2026-10-30~2026-11-09에서 피카푸는 4상품·+2실, 앤더포레는 30상품·+1실이다. 다른 기간의 값으로 확대하지 않는다. 산가원은 현재 숙박일의 이전 유효 원본이 없어 가져오지 않고 미확인을 유지한다.

수집 원본·기존 통합 DB·발행 리포트·수집 일정은 변경하지 않는다. 정기수집은 중지 상태를 유지한다.

## 검수

계산기·어댑터·저장소·HTTP·클라이언트 검증은 `customer-portal/test/*public*pickup*.test.cjs`에 있다. 운영에서는 실제 원본 가져오기 영수증, 프로세스가 다른 읽기에서도 같은 결과가 조회되는지, 고객별 업체 권한, 기간·요일 필터, 정상 0과 미확인, 수집 미실행·예약 중지를 확인한다.

## 계산과 비교의 약속

### 대상 표본

- 기본 검색범위는 네이버 플레이스 1~20위이며, 광고·자연검색·지역검색은 별도 순위다. 키워드가 경남이어도 실제 주소지가 다른 업체라면 구분해서 표시한다.
- **회차별 상위 20개**는 키워드 노출 표본의 흐름이다. 업체 교체 효과가 포함된다.
- **선택 회차의 업체 고정**은 같은 업체 집단의 변화다. 순위 밖으로 나가 미수집되면 공백으로 유지한다.
- **공통 업체·숙박일 비교**는 구성효과를 분리해 내 매장과 비교할 때 사용한다. 비교 업체 수, 날짜 수, 관측시차와 예약 선행구간을 함께 표시한다.
- 과거 자료에서 높은 예약률을 보인 업체만 골라 기준선으로 삼지 않는다. 규모·성과 등급은 별도로 확정되기 전 추가하지 않는다.

### 예약률과 월 마감

예약률 = 같은 유효 표본의 `(공개예약 + 타채널 추정예약) 합계 ÷ 공급수량 합계`.

업체별 예약률을 단순 평균하지 않는다. 오류·차단·미수집 날짜는 분자·분모에서 제외하고 빠진 업체·날짜와 확보율을 표시한다. 수량은 고객 화면에서 **실**로 표시하되, 기간 합계는 숙박일별 수량을 누적한 것임을 정의한다.

같은 `companyId × 숙박일 × 상품유형`은 관측 마감시각 이내이며 숙박일 이후가 아닌 최신 유효 관측 한 건만 채택한다. 최신 유효 후보와 최신 시도의 실패 상태는 분리해, 저장 자료가 보이더라도 갱신 실패를 알 수 있게 한다. 키워드가 달라도 같은 업체·숙박일 자료를 업체 DB에서 다시 더하지 않는다. 키워드 지표 간 표본은 겹칠 수 있으므로 키워드 합계들을 전체시장 합계로 더하지 않는다.

DB 검수 객실수가 우선이다. 검수값이 없을 때 최대관측 추정과 신뢰상태를 받고, 계산버전·객실수 기준이 바뀌면 증감 직접비교를 보류한다. 월 마감 자료는 최신 유효 **관측**이며 실제 결제·취소 정산이 끝난 확정 매출은 아니다.

### 예약 선행 구간과 실제 리드타임

- 실제 예약 리드타임 = KST 달력 기준 `숙박 시작일 − 실제 예약접수일`.
- 수집에서 알 수 있는 것은 같은 숙박일에 예약 증가가 확인된 **두 관측 사이의 구간과 순증감**이다. 실제 접수일이나 신규 예약 건수로 바꾸지 않는다.
- 9/20과 9/22 관측 사이에 2실 늘었다면 그 구간에서 순증가가 확인된 것이다. 어느 날 신규 예약이 몇 건 발생했는지, 취소·재예약이 있었는지는 알 수 없다.
- 관측 이전에 이미 예약된 수량, 31일 조회 범위를 벗어나는 예약 선행기간, 미관측 구간은 복원했다고 표시하지 않는다.
- 서로 다른 수집회차의 전체 31일 예약률을 빼지 않고, 동일 업체·상품·숙박일 및 비교 가능한 객실 기준을 맞춘다.

### 가격·쿠폰·데이유즈

- 상품의 공개 표시가격은 실결제액이 아니다. 성인수·박수·상품구성·혜택·취소조건이 맞는 경우에만 비교한다. 최초 검색의 checkIn/checkOut을 날짜별 상품 가격의 박수 조건으로 임의 변환하지 않는다.
- 금요일을 일괄 평일 또는 주말로 뭉개지 않는다. 요일 7개와 공휴일·휴일 전날을 별도 달력 정보로 보존하고, 평일/주말 묶음은 명시한 규칙으로 산출한다.
- 숙박·데이유즈·런치·디너의 물리적 객실 재사용은 데이터랩에서 보정한 결과와 근거를 받는다. 인사이트에서 합산 후 다시 보정하지 않는다.
- 상품별 가격 미확인은 0원이 아니다. 유효한 예약수량과 확인 금액 소계는 보이되 총매출 및 미확인 가격 수량·사유를 구분한다.
- 업체 수준 쿠폰 노출과 특정 상품의 쿠폰 표시는 다른 정보다. 발급·사용·실부담·추가 예약 효과는 따로 연결할 자료다.

## 연결 전 개발 순서

1. **이번 완료:** 저장 원본 구조·누락·중복·표본 변동 검토, 입력 요구사항 JSON, 이 계획서와 재현 가능한 프로파일.
2. 데이터랩 카테고리 완료 후 입력 스키마·명칭·표본 포함 규칙을 대조한다. 원본 read-only 변환기는 이때 붙인다. 외부 API 호출·수집 기능을 포함하지 않는다.
3. 기존 월명 및 등록 경쟁업체를 canonical ID로 연결하고, 같은 월·숙박일·관측 마감 기준의 예약률과 가격·확보율부터 표시한다. 개인화 행동 조건은 계속 검토 상태다.
4. 상품별 관측 이력으로 예약 증가 관측구간과 동일 선행일 비교를 연결한다. 과거월의 마감 요약만으로 현재 임박 객실을 권하지 않는다.
5. 운영자의 실제 사례·쿠폰 조건·실제 예약/비용 자료가 갖춰지면 판단 카드별 실행 조건을 검토하고 기록한다. 자동 가격 변경·쿠폰 발급은 별도 범위다.

## 연결 수용 기준

- 다른 키워드 혼입, 20위 초과·중복 업체, ID 매핑 미확인을 발견한다.
- 회차별 31일 이동과 표본 업체 교체가 예약 순증감으로 계산되지 않는다.
- 원본의 외부 상세 참조와 CSV 인라인 상세를 모두 읽되 같은 상세를 중복 합산하지 않는다.
- 구형 응답 미확인 0과 정상 확인 0을 구별하고, 수량과 금액의 유효성을 각각 표시한다.
- 주간·요일·월 합계가 동일한 선택 행에서 검산된다. 기대 업체·일 수는 표본 규칙과 포함 기간에 맞는다.
- 예약률 분자·분모, 원본 수집번호, 관측 마감, 객실 검수·계산 버전과 미확인 사유를 확인할 수 있다.
- 원본 revision이 바뀌면 저장 정상 결과를 먼저 표시하고 새 버전으로 갱신하되, 기존 발행본은 바뀌지 않는다.
- 가격 조건이 없으면 비교를 보류하고, 쿠폰 노출을 사용 실적이나 효과로 보여주지 않는다.
- 인사이트와 데이터랩의 정기수집을 다시 켜거나 워커·일정·원본·발행본을 수정하지 않는다.

## 현재 코드에서 재사용할 정의와 차이

- `scripts/lib/monthly_reports.cjs`: 업체×숙박일×유형 중복키, 최신 유효 관측 선택, 공급 가중 예약률, 수량·매출 확보율, 선택·제외 근거.
- 같은 파일의 기존 `keywordMembership()`는 월 내 순위 또는 숙박 관측으로 확인한 업체를 모으며 **rank<=20을 강제하지 않는다**. 새 카테고리에서 1~20위·표본규칙을 명시적으로 받아야 한다. 기존 구현과 이번 요구사항이 이미 같다고 가정하지 않는다.
- `scripts/lib/monthly_report_insights.cjs`: 관측 사이 증가 구간은 실제 예약 리드타임이 아니라는 구분.
- `scripts/inventory_estimation.cjs`: 객실 검수·공유 데이유즈·시간대 재사용·가격 복구의 근거와 정책 버전.
- 이 파일들을 이번 준비 작업에서 수정하거나 데이터랩에 배포하지 않는다.

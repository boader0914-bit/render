그래프·캘린더·표의 선택일이 연동된다. 보라색 막대는 타채널 추정 수량이 양수인 정상 날짜에만 표시하며 선으로 연결하지 않는다. 정상 0은 기준선과 0만원으로, 오류·누락·객실 수 충돌은 미확인으로 표시한다. 객실 수와 예약률이 서로 맞지 않는 값도 정상 막대로 표현하지 않는다.

## 이용 흐름

- 내 매장 또는 경쟁업체 등록 후 해당 업체의 A 기본정보, B 예약 채널, C 최근 운영 관측, D 누적 이력을 바로 조회한다.
- `업체 자료 보기`는 저장 DB 조회만 수행한다. `30일 예약·추정매출 수집`은 별도 설정을 열며, `수집 시작` 제출 시에만 기존 수집 명령을 보낸다.
- 저장 자료 다시 보기, 표시 방식 변경, 지표/숙박월 선택은 새 수집을 만들지 않는다.
- 기본 보기는 기존 DataLab 형태의 A~D와 캘린더, 접힌 날짜별 표다. 그래프·캘린더·표로 전환할 수 있고 보기 방식만 해당 브라우저에 기억한다.
- 기존 일반 고객 계정 전체 한국시간 하루 1회, 관리자 고객 화면 일일 제한 없음 정책을 유지한다. 등록 대상 권한, CSRF, 같은 조건 재사용, 수집 차단 보호도 그대로 유지한다.

## 자료 기준

- 업체 고유 ID 및 명시적으로 병합된 ID만 통합한다. 이름이 같아도 다른 업체 자료를 가져오지 않는다.
- 고객 자신의 과거 수집 요청 runId에 조회를 고정하지 않는다. 최신 공유 업체 DB 자료를 읽고, 고객 요청의 진행 상태와 실제 표시 자료가 다르면 구분해 안내한다.
- DB 검수 총량, 상품 보정, 공유 데이유즈 제외, 정상 응답 0과 오류/누락을 구별하는 기존 DataLab 계산을 재사용한다. 현재 검수값으로 다시 계산하며 원문을 수정하지 않는다.

## 두 그래프의 차이

1. **숙박일별 흐름(C)**: X축은 숙박일. 각 날짜의 최신 저장 자료로 공개 예약, 방막기 추정, 각각의 숙박 추정매출 또는 추정 예약률을 표시한다. 수량의 단위는 객실 수(실)다.
2. **같은 숙박월의 예약 변화(D)**: X축은 한국시간 관측일. 동일한 숙박일 묶음에 대해 그 시점까지의 최신 값만 합산한다. 수집 회차별 스냅샷을 서로 더하지 않는다. 기간 합산 수량은 객실·박이다.

월 비교 대상은 저장 자료에 등장한 숙박일의 고정 집합이다. 예를 들어 10월 3~31일만 있으면 `29/31일 · 일부 숙박일 · 월 전체 합계 아님`으로 표시한다. 최초 관측 이후 수집 범위가 넓어진 것을 예약 증가로 오인하지 않도록, 앞선 관측에 이 고정 집합의 날짜가 부족하면 합계를 미확인으로 둔다. 실제 달력의 모든 날짜가 있어야 월 전체로 표시한다.

그날 다시 관측하지 않은 숙박일은 직전 값을 유지한다. 같은 날짜의 최신 관측에 오류가 있으면 이전 성공값으로 숨기지 않는다. 표에 정상 숙박일 수, 당일 재관측 날짜 수, 고정 비교 날짜를 표시한다. 유효한 관측 2회가 있을 때만 그 두 관측일 사이의 차이를 보여주며, 실제 예약 접수액이나 취소액으로 표현하지 않는다.

녹색 실선은 공개 예약, 보라색 점선은 방막기 추정이다. 오류/누락/총량 충돌에는 선을 끊으며 가격 불확실 구간의 매출도 미확인으로 둔다. 현재 숙박월이 있으면 우선 표시한다. 다른 월 선택은 화면 계산만 수행한다.

# 지역분석 저장·갱신 1차 구현

이 문서는 개발 상태를 설명한다. 운영 배포·운영 갱신 예약 활성화·실제 외부 자료 수집을 완료했다는 기록이 아니다.

## 화면 배치

- 기존 지역분석 5개 메뉴와 모바일 순서는 유지한다.
- **지역 현황**: 공통 선택 지역의 저장된 지표를 분류별로 접고 펼친다.
- **자료·출처**: 같은 결과의 기준기간·누락월·오류·저장 시각을 확인한다.
- **DB → 지역 DB**: 저장 자료 정리, 즉시 갱신, 자동 갱신 정책과 작업 상태를 관리한다.
- 자동 갱신은 기본 비활성이다. 화면을 열거나 설정을 읽는 행위는 작업을 만들지 않는다.

## 구현 범위

1. 최신 정상월을 포함한 13개월 기준을 추가했다. 기존 12/24개월 검색과 1/24개월 준비 기능, 과거 저장 자료는 보존한다.
2. 방문자·체류소비·관광자원수요·다양성·KOSIS·검색의 저장 자료를 표준 결과로 만든다.
3. 관광 지표는 지표별 최신 정상월이 끝나는 창을 사용한다. 자료 미제공과 실제 공급자 오류는 구분하며 정상 0은 관측값으로 유지한다.
4. 인구·산업은 실제 월간/연간 공표기간을 보존하고 13개월 확보율을 적용하지 않는다.
5. 검색은 한 번에 정규화된 응답 묶음을 사용한다. 이전 24/12개월 응답을 참고할 때도 다른 묶음의 월별 값을 합치지 않는다.
6. 저장 결과와 작업·정책은 디스크에 기록하고, GET은 외부 API·원본 전체검사·재계산을 하지 않는다.
7. 공식자료가 바뀌면 이미 관리 중인 해당 지역의 결과만 저장 자료로 다시 정리한다. 계산 도중 변경된 자료는 이전 계산 결과를 게시하지 않고 후속 작업으로 반영한다.

## 저장·조회 계약

`DATA_DIR/regional_analysis/`:

- `queue.json`: 작업, 지역별 정책, 변경 자료 버전과 미반영 범위.
- `results/<scopeHash>/<resultId>.json`: 변경하지 않는 결과 파일.
- `latest/<scopeHash>.json`: 마지막 정상 결과와 이전 결과 식별자.
- `source_preparation/13/` 및 `24/`: 공급자 준비 작업의 영속 기록.

조회 조건은 `지역 × 요청 마감월 × 13/24개월`이다. 요청 마감월과 각 지표의 실제 최신월은 다를 수 있다. 결과에는 계산 버전·생성 시각·입력 자료 지문을 남긴다. 같은 값·기간·상태이면 기존 결과 식별자를 재사용한다.

- `GET /api/regional-analysis?regionKey=...&months=13[&month=YYYY-MM]`
  - 저장 결과, 최근 작업, 갱신 정책, 저장 오류만 읽는다.
- `POST /api/regional-analysis/refresh`
  - `{regionKey, months:13, collectMissing:false}`: 이미 저장한 자료만 정리한다.
  - `{regionKey, months:13, collectMissing:true}`: 기존 공급자 잠금·예산 아래 미확보 자료를 준비한 뒤 정리한다.
- `POST /api/regional-analysis/policy`
  - `{regionKey, months:13, enabled, hour, minute, intervalHours}`.
  - 시간은 한국시간이다. `month` 생략 정책은 월이 바뀌면 직전 완료월로 이동한다.
  - 설정을 켠 순간 즉시 수집하지 않고 다음 실행 시각에 작업을 등록한다.

관리자·동일 출처·JSON 검증과 요청 제한을 적용한다. 수동 갱신도 기존 호출 예산과 잠금을 우회하지 않는다. 기존 체류·소비 자동 백필 범위와 일일 예산은 유지하고 수동 준비 요청의 기간 상한만 24개월로 확장했다.

방문자 전체지역 캐시 갱신은 응답에 들어 있는 실제 지역별로 변경을 알린다. 관광 분석 변경 알림은 선택적인 SQLite shadow Evidence 기록과 독립적이다. KOSIS·검색의 정상 갱신도 같은 작업 큐에 연결한다.

## 실패와 재시작

- 동시에 들어온 같은 조건은 진행 중인 작업을 재사용한다.
- 외부 자료를 갱신하던 작업은 재시작 후 `interrupted`로 남기며 자동 재수집하지 않는다.
- 저장 자료만 처리하는 미완료 작업은 안전하게 복구한다.
- 자료 오류·저장 실패 시 기존 결과를 유지한다. 일부 출처만 실패한 경우 이전 출처 자료를 보존하고 오래된 자료임을 표시한다.
- 마지막 파일을 읽을 수 없으면 보존된 이전 결과를 읽되 저장 오류 상태를 함께 전달한다.
- 저장 원본·기존 리포트는 삭제하지 않는다. 외부 API 키나 공급자의 원문 오류 메시지는 이 분석 결과에 저장하지 않는다.

## 다음 개발 범위

이번 구현은 공통 저장·갱신과 지표 화면의 기반이다. 다음 기능은 별도 개발한다.

1. 수요 전망·지역 비교를 선택 수집 결과에서 독립시켜 공통 저장 결과에 연결.
2. 특일정보와 주말을 묶은 연휴, 월·연도 경계, D-30/14/7 분석.
3. 이번 달 예상·다음 달 전망, 단순 기준 예측과 오차 검증, 전망 이력 저장.
4. SGIS 등 공간통계 확보 후 0~50km/50~100km 배후시장 집계.
5. 행동 제안·관리자 의견·실행 결과와 월간 리포트·인사이트 연결.

정확한 반경 집계나 검증된 자체 전망 수치가 준비된 것처럼 표시하지 않는다. 숙박 키워드 수집 워커·속도·차단 보호·예약 설정은 이 작업에서 변경하지 않는다.

## 검증

`npm run test:regional-analysis`는 저장소·표준화·HTTP·UI·공유 예산 검증 및 실제 로컬 앱 서버 검증을 실행한다. 실제 공급자 대신 합성 응답을 사용하고 로컬 앱의 외부 fetch는 차단한다.

주요 검증은 정상0/미확보/오류 구분, 개별 최신월 13개월, 검색 정규화 묶음 분리, 재시작 보존, 읽기 요청의 무작업성, 중복 작업, 한국시간 예약·월 변경, 자료 변경 중 계산의 게시 방지, 마지막 정상 자료 유지다.

`node scripts/test_regional_analysis_api.cjs --preview`는 합성 자료가 있는 로컬 검수 서버를 약 3분간 열고 종료한다. 출력되는 계정은 해당 임시 검수 서버 전용이며 운영 계정과 관계없다.

2초 목표는 운영 환경의 저장 결과 응답과 실제 화면 표시를 별도로 측정해야 한다. 로컬 합성 자료 테스트 결과를 운영 성능 달성으로 간주하지 않는다.

# 인사이트 업체DB 화면과 30일 수집 제한

## 적용 범위

일반 고객이 인사이트에서 등록한 내 매장 또는 경쟁업체의 30일 예약·추정매출 수집을 요청하는 기능이다. 데이터랩 관리자 수집, 기존 예약 일정, 워커의 요청 속도는 변경하지 않는다.

- 기준: 고객 **계정 전체 하루 1회**, 한국시간 00:00~23:59. 업체별 제한 여부는 질문 중이며 답변이 없어서 계정 기준으로 구현했다.
- 숙박 시작일 포함 30일 고정. HTTP 요청에서 기간을 바꿔도 거절한다. 기존 1~31일 보존 자료 조회는 유지한다.
- 데이유즈: 유무 확인(기본) / 숙박만 / 상세 수집.
- 기존 연동과 같이 AWS worker(`scheduled`)에 업체명·단일 플레이스 고유번호·상세 수집 조건을 전달한다. 성인 2명·전체 상품·대상 1개다.
- 같은 날 같은 업체·조건의 결과가 있으면 기존 자료를 연결한다. 고객 접수 횟수는 1회 사용하며 저장 자료 조회는 무제한이다.
- 정보 수정과 상품 검수 요청도 횟수 제한에 포함하지 않는다.
- 관리자 고객 미리보기 계정(`admin_preview`)은 일일 제한을 면제한다. 일반 고객 입력으로 해당 계정 유형을 지정할 수 없다.

## 중복 실행 방지와 실패 처리

기존 SQLite 접수 기록의 고객 ID·한국시간 관측일·collect 의도를 사용한다. 새 접수와 횟수 확인은 같은 `BEGIN IMMEDIATE` 트랜잭션에 있다.

- 동일 요청 키 재전송 또는 같은 날 동일 조건의 새 요청 키는 접수 기록을 재사용한다.
- 다른 업체·시작일·데이유즈 조건의 두 번째 요청은 `429 DAILY_COLLECTION_LIMIT`로 거절한다.
- 새로고침, 재로그인, 서버 재시작으로 횟수가 초기화되지 않는다.
- 접수 이후 실패·접근 제한·불명확한 결과가 되어도 당일 추가 접수는 허용하지 않는다. 기존 중단·관리자 확인 절차를 유지한다.
- 과거의 `prepare-data` 검토 요청(intent 없음)은 고객 직접 수집 횟수에 포함하지 않는다.
- 서버가 사용 가능 여부와 다음 요청 가능 시각을 내려주며, 확인 전·사용 완료·진행 중에는 화면 버튼을 비활성화한다.

## 화면 및 데이터 연결

상세 결과를 데이터랩 업체DB의 네 영역으로 구성했다.

| 영역 | 고객 화면 |
| --- | --- |
| A 업체 기본정보 | DB 검수 객실 총량, 이번 관측 수량, 상품 구성, 데이유즈·공유 여부, 상품별 날짜·가격·검수 요청 |
| B 예약 채널 | 네이버 및 직접 확인하고 적용한 외부 예약 채널, 확인 시각, 채널 링크 |
| C 최근 운영 관측 | 업체DB 통합 예약·추정매출, 공개 예약(녹색), 방막기 추정(보라색), 월간 달력, 날짜별 표, 누락·실패 이유 |
| D 누적 이력·관리 | 추정 리드타임, 키워드별 순위, 수집 시점별 예약·매출, 지난 숙박일의 월별 이력 |

`summarizeCompanyMasterDetail`의 기존 집계 결과를 고객용 명시적 필드 목록으로 투영한다. 상품 상세는 선택된 보존 회차, C·D는 업체DB의 통합 이력이며 각각 범위를 표시한다. 같은 이름의 다른 업체 자료가 섞이지 않도록 고객 조회는 식별자 일치 이력만 사용한다. 내부 관리 메모·영업 연락처·사업자 검토자료·타 업체 원문은 내보내지 않는다.

실제 결제 매출과 관측 기반 추정을 구분한다. 정상 응답 0을 유지하고 오류·누락 수량은 미확인으로 남긴다. 가격 또는 수량 검증이 부족하면 산출 보류로 표시한다. 공유 데이유즈 제외 수량과 DB 보정 우선순위를 유지한다. 수집 회차의 추정매출을 서로 더하지 않는다.

PC는 A·B를 나란히 표시하고 C·D를 전체 너비로 표시한다. 모바일은 한 열로 배치하며 달력만 내부 가로 스크롤을 사용한다. 라이트·다크 모드에 별도의 녹색·보라색을 적용했다.

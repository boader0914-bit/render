## 확인한 결함

### 1. P1 — 일부 날짜가 미확보인 자료도 전체 기간 판매율로 확정한다

개별 업체 계산은 날짜가 누락되면 판매율을 미확인으로 처리한다. 그러나 시장 브리핑의 합산 함수는 완전성 판단을 버리고 예약 합계 ÷ 기간 총량으로 다시 계산한다. 수집 실패가 낮은 판매율처럼 보이고 시장 판단 점수에도 영향을 줄 수 있다.

실제 `scripts/inventory_estimation.cjs`의 `applyInventoryEvidence()`와 프런트 계산 함수로 다음 조건을 재현했다.

```js
{
  weeklyDays: 3,
  weeklyProductDetails: [{
    date: "2026-09-20",
    name: "객실",
    stock: 5,
    bookingCount: 1,
    price: 100000
  }]
}
```

| 항목 | 실제 계산 결과 |
| --- | --- |
| 9/20 | 총량 5개, 예약 1개, 판매율 20%, 관측됨 |
| 9/21·9/22 | 각각 총량 5개 유지, 예약 내부 기본값 0, `missing:true`, 일별 판매율 미확인 |
| 자료 상태 | `complete:false`, `status:partial` |
| 개별 업체 판매율 | 미확인 (`NaN`) |
| 브리핑 합산 | 예약 1 ÷ 기간 총량 15 = 6.7% |

최대 객실수 5개와 3일 총량 15객실·박은 유지해야 한다. 미확보일의 내부 기본값 0을 실제 예약 0건으로 간주해 판매율을 확정하는 것이 문제다. 전체 기간은 ‘판매율 미확인’, 확보한 표본은 ‘20% · 3일 중 1일 확보’로 구분하는 방식이 적절하다. 날짜 응답을 정상 확보한 뒤 잔여 판매수량이 0인 상황과도 구분해야 한다.

근거: `web/app.js:4816`의 `summarizeSales()`, `web/app.js:13703`의 판매율 재계산 및 시장 점수 입력. 유사 합산 사용처도 함께 검토해야 한다. 이번 재현만으로 보관된 포천 회차의 14% 자체가 틀렸다고 판정한 것은 아니다.

함께 개선할 항목: 저장 회차 목록에도 완료·부분수집·차단 상태와 확보 비율을 표시한다. 현재 `scripts/glamping_app_server.cjs:4985`의 목록과 `web/app.js:39454`의 진입 카드에는 관련 품질 정보 전달·표시가 부족하다.

### 3. P2 — 관광 지표 갱신 실패를 ‘갱신 완료’로 안내한다

관광자원 수요·관광 다양성 갱신은 POST의 HTTP 성공 여부만 확인하고 본문의 `ok`, 실패 사유, 실패월 수를 버린다. 서버는 관측 실패도 HTTP 200 본문으로 전달할 수 있다.

실제 UI 함수를 사용해 `ok:false`, 12개월 모두 네트워크 실패 후 저장자료 GET만 성공하는 응답을 재현했다. 결과는 `error:false`, ‘공급기관 제공자료 없음’, ‘관광 지수 최근 12개월 갱신 완료’였다. 운영 갱신 버튼을 누르거나 공급기관 API를 호출하지는 않았다.

근거: `web/app.js:32675`, `web/app.js:32691`, `scripts/glamping_app_server.cjs:18090`, `scripts/tourism_collector.cjs:4052`.

수정 방향: 정상 응답이지만 자료 없음 / 일부 확보 / 호출 실패 / 기존 저장자료 유지 상태를 분리한다. 기존 체류·소비 갱신의 실패 구분 방식과 일관되게 맞춘다.

## 정상 확인과 UI 개선 제안

점검한 범위에서 다음 동작은 정상이다.

- 업종분석·지역분석 메뉴를 새로 누르면 시작 화면이 열린다. 과거 분석 결과를 자동으로 강제 표시하는 현상은 재현되지 않았다.
- 저장된 업종 자료를 선택하고 ‘분석 보기’로 상세 분석에 진입할 수 있다.
- 지역 현황 → 수요 전망 → 자료·출처 → 지역 지도 → 지역 비교에서 포천 선택이 유지된다. 지역 DB에서 분석으로 돌아오는 선택 지역도 유지된다.
- 지역분석의 5개 메뉴 이름과 순서는 데스크톱과 모바일에서 동일하다. 모바일에서는 본문 상단에 표시된다.
- 자료·출처의 제목·상태·공급기관·기간 열이 데스크톱에서 정렬된다. 밝은 테마와 어두운 테마의 카드 바탕과 글자가 일관되게 표시된다.
- 모바일 업종분석·지역 DB·수요 전망에서 페이지 전체의 가로 넘침은 관측되지 않았다. 지역 메뉴의 가로 스크롤은 별도 영역 안에서 동작한다.
- 비교 가능한 지역이 하나뿐인 경우 비교 부족 안내가 표시된다.
- 업체 수정 진입, 모달 닫기·초점 처리, 객실 근거 UI의 기존 검사는 통과했다. 실제 운영 저장 동작은 실행하지 않았다.

결함과 구분할 개선 제안:

1. 모바일 분석 화면의 큰 제목·소개·필터 영역을 줄이고 핵심 수치를 더 위에 배치한다. 하단 주요 메뉴와 분석 보조 메뉴가 동시에 있어 본문 가용 높이가 작다.
2. 데스크톱의 지역분석 하위 메뉴를 현재 사이드바 맨 아래가 아니라 ‘지역분석’ 바로 아래에 배치하면 소속을 쉽게 알 수 있다.
3. 지역 지도 카드의 `1,566/11,439실`처럼 기간 누적 수량을 객실수처럼 읽게 하는 표기를 정리한다. 실제 객실 총량, 기간 예약 추정, 기간 공급량(객실·박)을 분리한다.
4. ‘낮은 신뢰’, ‘판단 필요’, ‘보강’, ‘감수’의 의미가 겹치는 카드는 대표 상태 하나와 짧은 이유를 먼저 보여주고 세부 설명을 접는다.
5. 다른 회차를 열어둔 상태에서는 상단이 현재 회차만 보고 ‘수집자료 없음’으로 안내할 수 있다. ‘지역 전체 저장자료 없음’과 ‘현재 열린 회차에 이 지역 없음’을 명확히 구분한다.

## 후속 수정 및 배포 전 검증 — 2026-09-23

위 내용은 최초 읽기 전용 점검 기록이다. 이후 사용자가 수정·배포를 승인했고 운영 관리자 로그인도 확인했다. 최신 운영 포천 회차(2026-09-21 15:02, 31일)의 분석 화면을 읽기 전용으로 대조했다.

- 부분·차단·예약자료 미확보 회차에서는 전체 기간 판매율과 시장 판단을 보류한다. 관측된 표본의 예약 비율을 별도로 안내하며 최대 객실수·기간 총량·전화예약 추정·공유 데이유즈 계산은 유지한다. 고객용 하단 요약, 지도 권역 합산과 지역 후보에도 같은 조건을 적용했다.

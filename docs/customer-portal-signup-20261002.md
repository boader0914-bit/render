## 이용 흐름

로그인 화면의 회원가입 → 아이디 중복 확인·비밀번호 확인 → 연락처·이메일 → 내 매장 운영 중/매장 준비 중 → 필수 안내 동의 → 계정 생성 및 자동 로그인 → 내 매장/관심지역·경쟁업체 등록 안내.

- `/signup` 직접 접속과 `#signup` 모두 가입 화면을 연다. 가입 중지 상태에서도 가입 진입점과 중지 안내가 보이며 로그인 요청으로 바뀌지 않는다.
- 중앙 B2B 회원번호와 인사이트 고객번호를 연결한다. 회원 연락처·이메일·사업 상태·프로젝트 이름은 기존 중앙 회원 저장소에, 고객 설정·등록 대상·동의 및 변경 이력은 중앙 고객 SQLite에 저장한다.
- 데이터랩의 이용자 메뉴와 인사이트 이용자 관리에서 조회한다. 내 매장 연결은 관리자 확인 대기이며, 가입만으로 소유·운영 확인이나 실제 수집을 시작하지 않는다.
- 기본 내 매장 1곳, 경쟁업체 3곳, 관심지역 1곳 및 기존 관리자 한도 변경 구조를 유지한다.
- 입력 오류·중복 계정·예약된 관리자 아이디·과거 약관 버전·동의 누락·권한 필드 삽입을 거부한다. 서버에서 마지막 중복 검사를 하므로 동시 가입도 하나만 저장한다.
- 비밀번호는 기존 해시 방식으로 저장한다. 브라우저에는 서비스 토큰이나 세션 토큰 본문을 노출하지 않고 기존 HttpOnly 세션 쿠키를 사용한다.

## 가입 문서와 설정

- 인사이트 `/terms`, `/privacy`에 서비스 전용 문서를 제공한다. 중앙의 사업자·문의 정보를 사용하고 문서 버전은 `2026-10-02`다. 동의한 버전·경로는 중앙 회원과 고객 기록에 동일하게 남긴다.
- `INSIGHT_SIGNUP_ENABLED=1`일 때 가입을 허용한다. 기본값은 비활성이다. 기본 문서를 사용할 때 별도의 정책 URL·버전 환경변수는 필요하지 않다. 기존 명시 설정은 우선하며, 내부 문서 경로와 버전이 다르면 가입을 열지 않는다.
- 고객 화면이 문서를 렌더링할 때 서버 데이터를 이스케이프한다. 정책 조회와 아이디 검사는 서비스 인증이 있는 전용 경로만 사용한다.
- 정책 문구는 현재 구현 기능을 설명하는 초안이다. 이메일·연락처 소유 확인, 자동 비밀번호 복구, 자동 탈퇴·파기 기능은 아직 제공하지 않으며 문의 경로를 안내한다. 리포트 준비 상태와 유료 계약 미체결도 구분한다.
- Render 국외 처리 설명은 기존 데이터랩 안내와 [Render DPA](https://render.com/dpa), [Render 개인정보 안내](https://render.com/privacy)를 대조했다. 주 서버 리전만으로 모든 처리 장소가 한 국가라고 쓰지 않았다. 공개 문서 적용은 실제 운영 정책과 함께 확인한다.

## 운영 반영 순서

1. 운영 중인 수집·대기·예약과 중앙 서버의 현재 커밋을 확인한다.
2. 가입 플래그를 끈 상태에서 중앙 웹과 고객 웹에 호환 코드를 배포한다. 워커 코드는 변경하지 않았으므로 워커 배포는 불필요하다.
3. 고객 서버의 정책 조회, 인증 없는 접근 거부, 기존 로그인과 중앙 연결을 확인한다.

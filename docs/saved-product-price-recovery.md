# 저장 상품 근거를 이용한 금액 보완

이 정책은 특정 업체나 9월 전용 보정이 아니다. 수집 결과를 읽는 공통 객실 계산기와 업체별 월 집계를 통해 과거 재계산과 향후 수집에 동일하게 적용한다. 업체 번호와 상품 번호가 일치하는 저장 자료만 사용하며, 원본 CSV·응답·수집 이력·DB 검수값·기존 발행본은 수정하지 않는다.

## 수량과 가격의 우선순위

- 업체 객실 총량은 기존 DB 검수값을 우선하며, 검수값이 없으면 기존 최대 관측 기준을 유지한다.
- 상품별 검수 수량은 자동 추론보다 우선한다. 상품 최대수량의 합으로 업체 총량을 늘리지 않는다.
- 정상 응답의 0, 조회 오류·차단·누락의 0, 가격을 확인하지 못한 금액은 구분한다.
- 공개예약은 공개된 가격으로 계산한다. 이번 보완으로 가격 없는 공개예약을 다른 상품 가격이나 임의 평균으로 채우지 않는다.
- 숙박과 공유하는 데이유즈는 기존 공통 정책으로 먼저 제외한다. 런치·디너는 같은 객실군에서 재사용하며 매출에 중복 합산하지 않는다.

## 허용되는 추가 추정

`inventory_price_recovery_v1`은 실제 추가 금액이 발생한 날짜에 기록한다. 두 보완 모두 공개 재고나 예약수량을 변경하지 않고 타채널 추정 예약의 금액만 보완한다.

1. `catalog_single_room_identity_v1`: 고정 업체 총량과 고유한 개별 객실 상품 수가 정확히 일치하고, 상품 선언·목록과 해당 날짜의 응답이 완전한 경우에만 적용한다. 개별 객실 목록의 정상 재고 0은 그대로 두고, 상품별 가격 배분에 필요한 1실 단위의 추정 근거로만 사용한다. 실제 최대관측 객실수로 저장하지 않는다.
2. `uniform_current_catalog_price_v1`: 상품별 최대수량 합이 업체 총량보다 커서 객실 배분이 불분명해도, 해당 날짜의 완전한 정상 숙박 상품 목록에서 모든 단가가 같은 경우 잔여 수량에 그 공통 단가를 적용한다. 어느 특정 상품이 팔렸다고 기록하지 않는다. 단가가 다르거나 가격·응답·목록이 누락된 경우 적용하지 않는다.

가격 근거와 별도로 추정 수량임을 표시한다. `phoneValuation.recoveryPolicies`에 정책·수량·금액·상품 번호·적용 숙박일을 남긴다. 기존 공개예약 금액 및 기존에 정상 계산한 금액은 유지한다.

## 미확인 원인

날짜별 `priceUnknownCauses`는 `{code, channel, quantity, productKeys}` 배열이다. `channel`은 `public` 또는 `other`이고, 동일 미산정 객실을 여러 원인에 중복 집계하지 않는다. 수량이 없는 항목은 생략한다.

| 코드 | 의미 |
| --- | --- |
| public_product_price_missing | 공개예약 상품의 가격 미확인 |
| explicit_product_price_missing | 직접 확인한 방막기 상품의 가격 미확인 |
| inferred_product_price_missing | 상품별 부족분에 적용할 가격 미확인 |
| product_maxima_exceed_company_capacity | 상품별 최대수량 합과 업체 총량의 불일치 |
| proportional_price_evidence_incomplete | 비례 배분에 필요한 일부 상품 가격 누락 |
| company_capacity_unallocated_to_products | 업체 총량 중 어느 상품인지 배분하지 못한 객실 |
| dayuse_unverified | 해당 미산정 수량의 데이유즈 공유 확인 부족 |
| invalid_product_response | 해당 미산정 수량의 상품 응답 오류·누락 |

`other` 원인 수량 합은 `phoneMissingPriceBookings`와 일치해야 한다. 공개 미산정은 별도로 집계한다. 정상 분류 결과 `[]`와 진단 기능이 없던 구형 자료의 필드 부재는 다르다. 합계에는 `priceUnknownCauseCoverage`로 분류한 관측일과 아직 분류되지 않은 관측일을 함께 표시한다.

## 연결 및 재계산

- 신규 수집은 기존 결과 보관·업체 이력·통합 DB 경로에서 같은 계산기를 사용한다.
- 계산 코드 변경은 원본 변경 검사에 포함되어 관련 파생 월 집계를 갱신한다. 기존 정상 집계는 새 집계 검증 완료 전까지 보존한다.
- 인사이트는 중앙 업체 DB의 수량·금액·미확인 사유와 계산 근거를 허용된 필드만 받아 캐시 및 일별 검수 기록에 보관한다. 별도의 매출 계산을 하지 않는다.
- 과거 발행 리포트는 고정본으로 유지한다. 최신 복구 금액이 포함된 새 발행은 별도 사용자 지시가 있을 때만 수행한다.
- 다른 수집 회차의 가격을 자동으로 가져오거나, 미래에 관측한 가격을 과거에 이미 알았던 것으로 사용하지 않는다. 이런 근거는 별도 검증 없이는 미확인 상태로 남긴다.

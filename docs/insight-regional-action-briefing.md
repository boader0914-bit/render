# 인사이트 지역 연결과 현재 상황 브리핑

2026-10-02 구현. 기존 회원별 등록 구조와 데이터랩의 저장 자료를 사용한다.

## 계정별 제공 수량

- 관리자 고객 화면(`admin_preview`): 내 매장, 경쟁업체, 관심지역 및 30일 수집 요청의 일일 수량 제한 없음. 같은 업체·지역의 중복 등록 방지는 유지한다.
- 일반 고객: 내 매장 1곳, 경쟁업체·관심지역은 관리자가 지정한 한도. 30일 수집은 한국시간 기준 계정 전체 하루 1회다.
- 관리자 여부는 인증된 서버 세션으로 결정한다. 브라우저가 보내는 역할·수량으로 제한을 해제하지 않는다.
- 수집 차단 감지, 결과 검증, 중복 작업 재사용, 인증·요청 보호는 유지한다.

## 관심지역 연결

등록한 `regionKey` 및 확인된 내 매장의 실제 소재지로 권한을 확인한다. 임의 지역, 비활성 등록, 다른 고객 지역은 조회할 수 없다. 문자열 지역 이름으로 대체 지역을 추측하지 않는다.

읽기 전용 `GET /regions/{regionKey}/analysis?month=YYYY-MM`을 고객 BFF와 데이터랩 서버가 중계한다. 지역 분석은 데이터랩 월간리포트와 같은 `createMonthlyReportContext`를 사용한다.

- 인구·산업: KOSIS 저장 지표 7종과 실제 공표기간
- 검색 관심: 데이터랩에 저장된 네이버 검색 트렌드
- 관광: 방문 추이, 수요지수, 관광자원 수요, 관광 다양성의 선택 월 저장 자료
- 입지·고객층: 같은 지역의 입지 사전 문구와 클러스터 설명. 통계 수치가 아닌 참고 해석으로 표시한다.

기본 조회월은 직전 마감월이다. 연간 통계는 월간 수치인 것처럼 바꾸지 않는다. 정상 관측 0은 0으로, 자료 없음·오류는 미확인으로 표시한다. 조회 시 외부 API 수집을 수행하지 않으며 원본·DB를 수정하지 않는다. 내부 메모·검수자·인증정보는 반환하지 않는다. 입지 점수 보정, 관리자 검수 도구 전체를 고객 화면에 복제하는 기능은 포함하지 않는다.

## 리포트의 판단 구조

`GET /reports/briefing?ownId={registeredOwnCompanyId}`로 현재 저장 상태를 읽는다. 발행된 주간·월간 보고서와 구분한 **현재 상황 브리핑**이며 자동 발행·PDF·이메일 발송을 수행하지 않는다.

1. 현재 상황: 선택한 내 매장과 등록 경쟁업체별 객실 수, 유효 숙박일 수, 관측 시각, 추정 예약률·매출, 공개 예약·방막기 추정. 근거는 업체DB A/B/C/D 화면으로 연결한다.
2. 경쟁업체와의 차이: 같은 숙박일 및 같은 한국시간 관측일을 비교한다. 선택한 내 매장 이외의 다른 보유 매장은 포함하지 않는다.
3. 지역 수요 배경: 선택한 매장의 확인된 소재지와 명시적으로 등록한 관심지역만 포함한다. 지역 카드에서 해당 지역으로 바로 이동한다.
4. 다음 행동: 자료 확보·상품 조건 검토 등 각 행동에 판단 근거, 실행 단계, 실행 후 확인할 지표를 붙인다. 예약률 차이만으로 가격 인하 또는 인과관계를 단정하지 않는다.

### 지표와 비교 기준

- 예약 전망 범위: 오늘 포함 향후 30일. 실제 결제·투숙 실적이 아닌 저장된 예약·방막기 관측 기반 추정이다.
- 추정 예약률 = 유효 날짜의 예약 객실 수 합계 / 같은 날짜의 객실 공급 수 합계. 날짜별 비율의 단순 평균을 사용하지 않는다.
- 정상 수량 기준: 누락·부분·재고 충돌이 없고, 공급 수 > 0, 0 ≤ 예약 수 ≤ 공급 수, 공개 예약 + 방막기 추정 = 예약 수.
- 업체 간 비교: 최근 7일 이내 동일 관측일 및 공통 숙박일만 계산한다. 공통 숙박일 7일 미만이면 표본 부족으로 판단을 보류한다. 이는 제품의 최소 검토 기준이며 통계적 유의성이나 신뢰구간을 뜻하지 않는다.
- 가격 누락·부분 매출이 있는 집계는 매출 산출을 보류한다. 관측 0과 미확인을 구분한다.
- 업체별 요약은 각 업체가 확보한 날짜 범위다. 비교 표는 별도로 공통 날짜만 사용한다. 업체 매출을 서로 합산하지 않는다.
- 하루 단위 시각이 원자료에 남아 있으면 그대로 보존한다. 날짜만 있는 경우 날짜로만 비교하고 임의 시각을 생성하지 않는다. 상품 묶음에 기록된 시각은 그 묶음의 일별 자료에 연결한다.
- 데이터랩 DB 검수 객실 총량과 원자료 품질 경고를 유지한다. 통계 배경·검색 관심을 미래 예약률 예측값으로 변환하지 않는다.

## 검증 및 배포 경계

자동검증은 `test:insight-connection`에 지역 권한·제로/누락 구분·관측 시점·관리자 무제한·일반 고객 제한·BFF 연동·화면 응답 순서 검사를 포함한다. 실제 데이터랩 서버를 임시 저장소와 가상 업체로 실행해 지역 API 12종 반환과 새 수집 미실행을 확인한다. 관측 이력 집계와 기존 DB 보정 회귀 검증을 별도로 실행한다.

로컬 화면은 `customer-portal/dev-connected.cjs`의 가상 데이터다. API 캐시가 없는 검수 환경의 미확인 값은 운영 자료 상태를 의미하지 않는다.

배포 시 데이터랩 웹의 API를 먼저, 인사이트 BFF·화면을 다음으로 반영해야 한다. 이 변경은 수집워커 코드를 바꾸지 않는다. 운영 배포 및 실제 고객 자료 연결 검수는 로컬 개발 완료와 별도로 확인한다.

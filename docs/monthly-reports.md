# 월간 리포트

## 사용 흐름

관리자 좌측 `리포트 → 월간 리포트`에서 대상 월과 업체·키워드·지역을 선택한다. 저장된 수집 자료를 미리보기하고 제목·검토 메모를 붙여 초안으로 저장한다. `검토 중으로 저장` 후 자료의 제한을 확인하고 발행한다. 발행본에서 PDF를 내려받을 수 있다.

발행은 내부 보관함에 해당 버전의 수치와 근거를 고정하는 동작이다. 외부 공개 링크나 고객 메일을 만들지 않는다. 발행본의 제목·메모·수치도 변경하지 않는다. DB 보정 후에는 `수정본 만들기 → 저장 자료로 다시 집계 → 검토 → 발행`으로 새 버전을 만든다. 원본 발행본은 유지된다.

## 집계 기준

- 대상 월은 **숙박일** 기준이다. 한국시간의 관측 마감일을 사용하며 미래 마감일은 허용하지 않는다.
- 업체 고유번호를 기준으로 같은 업체·숙박일·상품 유형에서 최신 유효 관측 1건을 선택한다. 여러 키워드에 노출됐거나 반복 수집됐다고 합산하지 않는다. 숙박일 이후 관측은 과거 예약의 근거로 사용하지 않는다.
- DB 검토 객실 수를 우선 적용하고, 없으면 기존 최대 관측 객실 수 기준을 사용한다. 확인되지 않은 업체의 이름만 같다고 합치지 않는다. 같은 플레이스 번호가 여러 DB 업체에 연결돼 있으면 검토 전까지 제외한다.
- 숙박은 `실·박`, 일별 표는 `실`, 데이유즈는 `회`로 분리한다. 업체의 실제 규모인 `객실 수`는 기간 합계와 별도로 표시한다.
- 공개 예약은 녹색, 재고 근거의 방막기 추정은 보라색으로 표시한다. 전화·타채널 예약 등은 추정이며 직접 확인한 결제 매출이 아니다. 기존 공유 객실 보정을 거친 값을 사용하고 데이유즈를 숙박에 중복 합산하지 않는다.
- 정상 응답의 0과 오류·차단·누락은 구분한다. 가격 근거가 없는 금액은 0원이 아니다. 일부만 가격이 확인되면 확인 가능한 부분 금액을 별도로 남긴다.
- `complete/reused` 및 검증 가능한 부분 결과의 정상 업체 자료만 사용한다. 차단·실패·중단 및 상태가 불명확한 결과는 정상 수치로 합산하지 않는다. 부분 자료는 발행 전에 확인이 필요하다.
- 자료 충족률 100%는 모든 업체·숙박일의 유효 관측이 있다는 뜻이다. 숙박 당일 관측 수, 사전 관측 수, 관측 시차를 함께 표시한다. 사전 관측만으로 최종 예약이나 실제 매출이 확정되지 않는다.
- 예약·매출 증감은 동일 업체·숙박일의 비교 가능한 최초/최신 관측만 비교하고, 객실 기준이 바뀐 쌍은 제외한다. 이는 순증감이며 개별 예약·취소 거래량이 아니다.
- 순위는 해당 월에 관측된 키워드별 최초/최신 노출을 비교한다. 지역은 DB 보정 지역 또는 확인 가능한 실제 소재지를 사용한다.

## 지역 보조자료

업체의 소재지 또는 선택한 지역에 대해 기존 KOSIS·관광공사 저장 자료를 읽는다. 리포트 생성으로 API 갱신이나 크롤링을 시작하지 않는다. KOSIS는 공표 기준기간을 유지하는 참고 통계이며 월별 값으로 환산하지 않는다. 관광 지표는 대상 월과 일치하는 정상 저장값만 보여준다. 키워드와 실제 소재지가 다를 수 있으므로 키워드 리포트에 임의의 지역 통계를 붙이지 않는다.

## 키워드 검색시장과 추가 지표

키워드 리포트는 해당 키워드에서 관측한 표본의 검색시장 리포트다. 실제 소재지 기준 지역 전체 실적으로 표현하지 않는다. 숙박·예상매출은 숙박월, 순위는 한국시간 검색 관측월을 기준으로 한다. 당일 여러 순위 관측은 업체·키워드별 마지막 유효 순위 한 건을 사용한다. 평균·최고·최저 순위와 상위 3위/10위 비중은 관측된 날만 분모로 사용하고 미관측을 순위 이탈로 만들지 않는다.

지역 배경은 대상 업체의 실제 소재지별로 저장된 공공 지표를 연결한다. 여러 지역의 인구·관광 지표를 임의로 더하거나 키워드 이름의 지명으로 연결하지 않는다. 자료가 없는 지역은 미확보로 표시한다.

예약 시점은 동일 업체·숙박일·상품 유형의 연속 관측에서 공개예약과 방막기 추정의 증가·감소를 각각 계산한다. 실제 예약 생성 시각·취소 거래는 없다. 최초 관측에 이미 존재한 예약과 마지막 관측 뒤 변화는 발생 시점을 알 수 없다. 증가를 확인한 관측의 선행일수로 평균·중앙값·구간을 만들며 직전 관측까지의 발생 가능 범위도 표시한다. 공급 수량·근거, 공유 제외 수량·상태, 재고 근거 버전 등이 바뀐 관측 쌍은 제외한다.

예약 진행률은 D-14/D-7/D-3/D-1 당일 관측이 있는 업체·숙박일만 집계한다. 시점별 표본이 다를 수 있어 표본 충족률을 함께 표시하고 빈 구간을 보간하지 않는다. 요일별 예약률은 수량 합계/공급 합계로 가중한다. 공휴일·공휴일 전날은 정상 저장된 특일정보가 있을 때 분류하고, 연도 경계 자료가 없으면 미확인으로 둔다. 연휴 묶음 전체를 임의로 추론하지 않는다.

가격 효율은 가격이 확인된 동일 표본에서 예상매출/판매 추정 수량, 예상매출/공급 수량을 계산한다. 가격이 없는 관측은 분모에서도 제외한다. 실제 결제 기반 ADR·RevPAR로 표현하지 않는다.

시장 요약의 객실 기준 총량은 업체 DB 보정값 우선·최대 관측 추정값을 업체당 한 번 합한 규모이며, 월간 실·박 합계와 다르다. 기준값이 없는 업체 수와 일부 소계 여부를 표시한다. 분석에 사용한 수집일은 숙박월 이전을 포함한 유효 관측의 KST 날짜 수다. 가격대 분포는 금액 근거가 모두 있는 자료에서 업체별 예상매출/판매 추정 수량을 구한 뒤 업체 동일 가중치로 중앙값과 구간별 업체 수를 계산한다. 게시 요금이나 실제 결제 단가 분포가 아니다.

## 전월·공통 업체 비교

미리보기·초안 재집계 시 같은 대상의 전월도 저장 자료에서 읽는다. 관측 마감일은 전월의 대응 날짜로 맞추며 짧은 달은 말일로 제한한다. 전월 자료가 없으면 비교 불가로 표시하며 0원으로 처리하지 않는다.

`comparison.all`은 각 월의 관측 업체 전체 소계, `comparison.common`은 양월 모두 유효 숙박 관측이 있는 업체의 소계다. 신규 관측/미관측 업체 수는 표본 구성 변화이며 신규 개업·폐업·검색 순위 이탈이 아니다. 증감은 `comparison.common.matched`의 같은 업체·월중 날짜 중 공급·공유 기준과 관측 선행일수가 같은 쌍에만 계산한다. 가격 증감은 양월 모두 가격이 있는 같은 쌍만 사용한다. 전월 금액이 0이면 증감액은 표시할 수 있지만 증가율은 계산하지 않는다. 요일·공휴일 구성이 다른 한계와 양월 관측 충족률을 함께 표시한다.

추가 지표 근거와 전월 관측은 발행 스냅샷에 고정한다. 기존 발행본은 재계산하거나 덮어쓰지 않는다. 이전 버전에 추가 지표가 없어도 정상 조회·PDF 출력이 가능해야 한다.

## 저장 및 API

`DATA_DIR/monthly_reports/`에 리포트 JSON, `pdf/`에 최초 발행 PDF를 저장한다. 기존 업체 DB·수집 원본·예약 일정은 변경하지 않는다. 저장소는 운영 DATA_DIR의 영속 디스크에 포함돼야 한다.

| 요청 | 기능 |
| --- | --- |
| `GET /api/monthly-reports/options` | 업체·키워드·지역·월 선택지 |
| `POST /api/monthly-reports/preview` | 서버에서 집계 후 미리보기 토큰 발급 |
| `GET/POST /api/monthly-reports` | 보관함 목록 / 초안 생성 |
| `GET/PATCH /api/monthly-reports/:id` | 상세 / 제목·메모·검토 상태 변경 |
| `POST /api/monthly-reports/:id/publish` | 검토본 발행 |
| `POST /api/monthly-reports/:id/revise` | 발행본을 복제한 새 버전 초안 |
| `POST /api/monthly-reports/:id/rebuild` | 발행 전 저장 자료로 재집계 |
| `GET /api/monthly-reports/:id/pdf` | 발행본 PDF 다운로드 |

관리자 인증, JSON 입력, 동일 출처 확인, 수정 revision 검사를 적용한다. 브라우저에서 보낸 임의 수치를 저장하지 않는다. 미리보기 토큰은 15분간 유지되며 조건 변경 또는 만료 시 다시 생성한다. 초안 저장 이후에는 서버 재시작에도 보관된다. 발행본은 스냅샷 해시로 확인하고 PDF는 최초 생성한 바이트를 재사용한다.

동시 쓰기는 보고서별 잠금으로 보호한다. 쓰기 중 프로세스가 강제 종료되어 `.lock`이 남으면 읽기는 가능하지만 수정은 423으로 차단한다. 이때 운영 프로세스와 원본 JSON 상태를 확인한 뒤 해당 보고서의 잠금만 복구해야 한다. 시간만 보고 잠금을 자동 삭제하지 않는다.

## PDF와 검증

PDFKit 0.20.2 및 저장소의 Pretendard 한글 글꼴을 사용한다. A4 세로·밝은 배경에 발행 버전, 기간, 요약, 일별·업체별 표, 관측 변화, 출처와 산식을 담는다. 긴 표와 한글 메모는 페이지를 나누며 색상 외에도 라벨과 선 형태로 구별한다. 한글 글꼴이 없으면 생성 실패를 명시한다.

검증 명령: `npm run test:monthly-reports`, `npm run check`. 테스트는 격리된 모의 업체와 임시 DATA_DIR을 사용하며 실제 네이버 수집이나 외부 API 호출을 하지 않는다. 관리자/회원 권한, 중복 집계, 0과 결측, 관측 시차, 발행 불변성, 동시 수정, PDF 다운로드까지 포함한다.

이번 변경은 개발본이다. 배포 시 PDFKit 의존성 설치와 글꼴 포함 여부, 운영 영속 디스크 저장·관리자 화면을 확인해야 한다. 자동 수집 일정은 변경할 필요가 없다.

# 인사이트 2단계: 저장 근거를 운영 검토와 연결

리포트의 4번 영역을 `운영 전략과 다음 행동`으로 바꾼다. 기존 1단계의 업체별 확보일·공통 비교일·객실 기준·미확인 사유를 유지하고, 내 매장의 요일별 추정 예약 흐름에서 검토할 행동을 제안한다. 이번 범위는 인사이트 포털의 표시와 로컬 계산이다. 운영 배포는 별도 요청 시 진행한다.

## 입력과 보존

- 이미 권한이 확인된 `current_briefing`, `published=false` 보고서만 사용한다.
- 원본 업체 번호, 선택 숙박기간, 관측 기준일, 중앙의 `summaryQuality`·비교 자격을 확인한다.
- 중앙 `reservationSeries` 또는 `reservationPeriods`의 날짜별 투영을 사용한다. 두 형식이 함께 있으면 같은 날짜의 정상 수량을 대조하며 합산하지 않는다. 미확인 날짜의 보존 시각 차이는 정상 날짜를 무효화하지 않는다.
- 같은 업체·숙박일 중복, 기간 불일치, 수량 합계 충돌은 운영 제안을 보류한다. 정상 0과 미확인을 구분하고, 알려진 금액은 전체 매출로 표시하지 않는다.
- 회사·고객·권한별 조회 및 캐시 격리는 기존 흐름을 사용한다. 별도 전략 캐시·브라우저 저장소·외부 모델/API는 만들지 않는다.
- 원본·검수 객실 수·발행본·정기수집·기존 키워드 일정은 수정하지 않는다. 모델과 렌더러에는 통신·저장·수집 실행 기능이 없다.

## 표시와 판단

`web/operating-strategy.js`가 순수 표시 모델을 만들고, `operating-strategy-view.js`와 `.css`가 리포트에 표시한다. 업체 이름이나 업체 번호를 하드코딩하지 않아 다음에 들어오는 업체와 기간에도 같은 기준이 적용된다.

1. 선택기간의 수량 확보일, 공개 예약·타채널 추정 수량, 공급 대비 추정 예약률, 확인된 매출 소계를 표시한다.
2. 월~목 / 금~일의 예약률은 유효 날짜별 수량 합계 ÷ 공급 합계로 계산한다. 공휴일·지역 행사·계절 구분은 없다고 표시한다. 관측 공백은 분모와 0실로 대체하지 않는다.
3. 유효 숙박일 7일 이상, 각 요일군 2일 이상, 예약률 차이 15%p 이상일 때 상품 안내를 한 가지씩 시험할 검토 항목을 제안한다. 이는 검토용 규칙이며 통계적 유의성·가격 적정성·개선 효과를 주장하지 않는다.
4. 객실 기준에 도달한 관측 날짜는 청소·입실 운영과 안내를 점검하는 데 사용한다. 추가 판매나 초과 예약 근거로 사용하지 않는다.
5. 같은 지역·목적·시차 등의 중앙 비교 자격을 그대로 따른다. `actionable=false`인 비교는 차이가 커도 상품자료 검토 목록으로 제한한다. 타지역 비교에서 가격·상품 변경 실험을 권고하지 않는다.
6. 과거 근거는 다음 유사 숙박일을 위한 회고로 설명한다. 과거와 향후가 함께 선택되면 행동의 날짜 근거를 분리한다. 향후 관측값을 최종 실적으로 표현하지 않는다.
7. 내 매장 연결 대기나 최신 확인 지연은 `검토`, 계산 전 미리보기·불일치·객실 기준 문제는 `보류`로 표시한다. 자동 실행·자동 가격 변경·예상 매출 증가액·임의 신뢰도 점수는 제공하지 않는다.

각 카드는 `확인한 흐름 → 제안 행동 → 다음 확인 지표`로 구성한다. 접힌 `판단 근거와 한계 +`에서 사용한 날짜 전체를 확인하며, 날짜 목록이 길면 스크롤한다. 재조회 시 같은 카드의 펼친 상태를 보존한다.

## 갱신과 실패

보고서의 수치가 같아도 최신 확인 상태나 시각이 바뀌면 전략의 표시 상태를 갱신한다. 전송 실패 시 정상 저장 보고서를 보존하고 화면에서만 최신 확인 실패를 표시한다. 다음 정상 응답이 오면 다시 갱신한다. 실패 표시를 정상 캐시에 저장하거나 다른 업체·기간의 결과를 재사용하지 않는다.

기존 발행본은 `archive.js`의 별도 고정 렌더러를 유지한다. 현재 전략의 변경으로 과거 발행본을 재해석하거나 다시 발행하지 않는다.

# 지역 지표 원본 근거 검토

지역 DB의 **지역 자료 갱신 관리 → 원본 근거 검토**에 과거 지표의 보강 대상을 모은다. 운영 배포나 외부 API 재수집은 이 개발 기능과 별개다.

## 저장과 표시

- 지역 저장 분석을 계산할 때 `evidenceReview`를 함께 저장한다. 이전 정상 자료를 유지하는 경우에도 최종 보관 지표로 검토 목록을 다시 만든다.
- `compact-v1` 형식으로 지표·안전 코드 사전과 이미 계산된 상태를 저장한다. 반복 설명은 저장하지 않고, 화면에서 기존 지표 이름과 정적 안내 문구로 복원한다. 저장 형식·지역·기간·집계가 맞지 않으면 기존 관측으로 호환 목록을 만들고 ‘이전 저장자료 기준’으로 표시한다.
- 저장 결과가 있으면 같은 목록을 재사용한다. 이전 형식에는 이미 불러온 저장 관측으로만 호환 목록을 만든다. 화면 조회와 필터는 원본 파일 검사·원본 해시 계산·외부 요청·새 작업 등록을 하지 않는다.
- 이미 읽은 지역·지표 입력의 내부 변경감지 지문을 대조하여 관측 상태나 근거 진단이 달라진 목록을 저장 목록으로 재사용하지 않는다. 이 비보안 지문은 제공기관 원본의 SHA 검증이나 자료의 진실성을 입증하는 근거가 아니다.
- 지역, 지표, 실제 기준기간(월 또는 연도)을 기준으로 1건을 센다. 같은 기간의 요청 상태는 이미 있는 관측에 중복해서 더하지 않는다. 관측 구간 밖의 요청월은 별도 확인 대상으로 남긴다.
- 현재 선택 지역과 조회 기준을 유지한다. 연간 자료는 실제 연도 1건이며 월별로 복제하지 않는다. 검색 관심도는 별도의 검색어 참고 자료다.

## 관측과 근거를 구분

정상 관측의 0은 유지한다. 오류·누락·부분·비공개·명시적인 공표 대기는 정상 0으로 바꾸지 않는다. 수치가 있어도 원본 근거가 없으면 보강 대상으로 남긴다. 보관 실패가 있더라도 기존 정상 수치와 검증된 원본 근거를 임의로 없애지 않는다.

검증된 원본의 ID·기간·주기·행정 범위가 실제 관측에 연결됐을 때만 원본 검증 완료다. 기존의 응답 범위 확인과 불변 원본 보관은 다른 상태다. 최신월 근거를 과거 월이나 단순 요청월에 적용하지 않는다.

| 순서 | 분류 | 안내 |
| --- | --- | --- |
| 1 | 지역·기간·원본 검증 불일치 | 대상과 원본을 대조 |
| 2 | 원본 보관 실패 | 보관 상태 확인 |
| 3 | 관측 미확보·부분·오류·비공개 | 저장 관측 및 제공 상태 확인 |
| 4 | 정상 수치의 원본 근거 부족 | 보관 원본 근거 확인 |
| 5 | 명시적 공표 대기 | 공표 후 확인 |
| 6 | 원본 확인 완료·검색 참고 | 검토 대상에서 기본 제외 |

한 관측에 여러 사유가 있으면 모두 보존하되 가장 우선인 사유로 정렬한다. 같은 순서 안에서는 최근 기준기간부터 본다. 지표×기간 건수와 API 호출 수는 같지 않다. 보강 방법은 안내이며 자동 실행 명령이 아니다.

알려진 안전한 진단 코드만 쉬운 말로 표시한다. 진단이 없으면 ‘사유 미기록’으로 남긴다. 다른 월의 오류를 복사하거나 누락 이유를 공표 대기로 추정하지 않는다. 비밀번호·토큰·전체 URL·원본 경로·임의 오류 본문은 목록에 넣지 않는다.

## 화면 구성

- 수치 확보와 원본 근거 확보를 별도 집계한다.
- 검토 목록과 개별 사유는 기본 접힘이다. 상태·자료 종류·기준기간 필터와 20개씩 더 보기를 제공한다.
- 필터·펼침·갱신 설정 초안은 같은 지역의 상태 확인 후에도 유지한다. 새 지역이나 조회 기준으로 이동하면 이전 필터를 초기화한다.
- 필터와 더 보기는 외부 요청이나 작업 등록 없이 동작한다. 기존 ‘저장자료 정리’와 ‘즉시 갱신’은 계속 별도 명시적 동작이다.
- 목록은 지역 DB 관리에만 추가하여 지역 흐름·비교의 최초 표시와 재사용 경로를 늘리지 않는다.

## 검증

`npm run test:regional-evidence-review`로 순수 분류·저장 연결·관리 UI·원본 재사용 회귀를 확인한다. 정상 0과 오류 0, 쓰기 실패 동반, 근거 미보관, 거절·중복·기간 불일치, 명시적 빈 근거, KOSIS 비공개·연간, 검색 참고, 유지한 과거 정상 그룹, 상태 확인 중 필터 보존을 검증한다.

실제 운영 자료의 보관 사본은 로컬 검수에 사용할 수 있다. 그 화면과 측정 시간은 운영 서버 검수 결과로 보고하지 않는다. 운영 배포 이후 새 저장 결과의 재사용과 실제 화면 표시 시간은 별도로 확인한다.

2026-10-17 개발 검증은 집중 회귀시험 168개와 별도 실제 앱 서버의 저장 결과 재사용 API 시험을 통과했다. API 시험은 격리된 합성 자료이며 외부 요청·수집·갱신·예약 실행은 0회다. 실제 산청·사천·천안 저장자료 사본에서는 압축 저장·엄격 복원 결과가 모두 같고 원본 파일이 유지됐다. 값·기간·상태 변조나 행 누락은 기존 관측과 대조해 저장 목록으로 인정하지 않는다.

검토 모형은 9,472~9,792 bytes로 설명을 반복 저장한 개발 초안 대비 약 93% 작다. 기능 추가 전 운영 버전 대비 응답이 줄었다는 뜻은 아니다. PC와 모바일의 라이트·다크, 기본 접힘, 월·연도 분리, 같은 지역 상태 확인 후 필터·펼침 유지, 키보드 선택 초점, 외부 요청 없는 필터를 로컬에서 확인했다. 운영 배포 및 실제 운영 조회의 2초 목표 재측정은 아직 수행하지 않았다.

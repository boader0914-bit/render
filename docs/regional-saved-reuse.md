# 지역 비교·흐름의 저장 결과 재사용

지역 현황의 흐름 자료와 지역 비교가 같은 저장 결과를 사용한다. 화면을 열 때 마지막 키워드 수집 회차를 읽거나 새로운 수집을 시작하지 않는다. 기존 지역분석의 5개 메뉴와 공통 선택 지역은 유지한다.

## 조회와 표시

- 지역 현황의 지표, 자료·출처, 지역 DB 관리, 지역 비교는 `RegionalAnalysis.savedResults`를 공유한다. 조건은 계정·지역·명시한 자료 기준월·13개월이다.
- 지역 비교는 기준지역 외 최대 3개 지역을 선택하며 저장된 결과를 병렬로 읽는다. 같은 조건의 진행 중 GET은 하나로 공유한다.
- 화면에 보관된 값이 있으면 먼저 표시한다. 서버에서 변경을 확인하는 동안 이전 결과를 유지하고, 확인 실패·저장 오류는 마지막 정상값과 함께 표시한다. 확인되지 않은 자료를 정상 0으로 바꾸지 않는다.
- 같은 결과 번호의 지역 흐름에서는 지표의 전체 DOM을 다시 만들지 않는다. 상태와 작업 정보만 갱신해 접힘 상태와 읽던 위치를 보존한다.
- 지역 화면의 진입과 늦은 초기 응답은 관련 화면만 갱신한다. 업체 DB·전체 숙박 수집 회차·이력의 초기 읽기는 실제로 필요한 화면으로 이동할 때 재개한다.
- 지역 현황의 기본 화면과 자료·출처 진입은 구형 전체회차 프로필을 자동으로 재구성하지 않는다. 숙박 관측의 상세 탭이나 기존 저장 이력 새로고침 버튼을 선택할 때 해당 근거를 조회한다.
- 광역지역 선택은 유지하되 시·군·구 저장 지표 조회를 잘못 요청하지 않는다. 지역 비교의 대상 목록에는 활성 시·군·구만 표시한다.
- 조회만으로 저장 자료를 재계산하거나 관광·검색·KOSIS API를 갱신하지 않는다. 기존 지역 DB의 수동 정리·갱신·예약 기능은 유지한다.

## 비교 기준

관광 흐름은 지표별로 정상 자료가 함께 있는 최근 월을 찾고 단위·제공처가 일치할 때 표시한다. 공통 월이나 비교 근거가 없으면 사유를 표시한다. 각 지표의 최근 정상월이 달라도 임의로 같은 월로 바꾸지 않는다.

검색 관심도는 서로 다른 정규화 응답을 지역별 절대 수요로 비교하지 않는다. 지역별 저장 묶음 안의 추이와 조회기간을 참고한다. 인구·산업은 월간 수요 흐름과 분리하고 실제 월·연간 공표기간을 유지한다.

## 시간 계측

`#regionalAnalysisSummary`의 `data-ra-display-*`, `#regionCompareDashboard`의 `data-rc-display-*`는 메뉴 진입 또는 지역·기간 선택부터 실제 결과가 두 프레임을 거쳐 표시될 때까지를 기록한다. 캐시 표시와 서버 변경 확인 완료는 별도 기록이다. 준비 문구나 이전 요청의 완료 표시를 새 결과의 표시 완료로 계산하지 않는다.

2초 목표는 저장 결과의 조회·표시 기준이다. 최초 자료 확보·집계와 비전면 탭의 브라우저 그리기 대기는 구분한다. 실제 API 응답 시간과 로컬 검수 화면의 표시 시간을 별도로 기록하며, 로컬 결과를 운영 화면의 측정값으로 표현하지 않는다.

## 검수와 운영 반영

`npm run test:regional-saved-reuse`로 공유 GET, 기간·계정 분리, 오류 보존, 느린 응답·화면 전환, 실제 앱의 격리 저장 조회를 검사한다. `scripts/test_regional_saved_reuse_api.cjs --actual <보존한 운영 응답 JSON> --preview`는 실제 저장 결과를 복사한 별도 검수 서버를 연다. 원본 자료를 수정하지 않으며 외부 요청은 차단한다.

운영 배포와 운영 화면의 최종 속도 측정은 개발 검수와 구분해 기록한다. 숙박 수집 워커, 차단 보호, 요청 속도, 예약 설정과 인사이트 서비스는 이번 변경 대상이 아니다.

### 2026-10-17 개발 검수

- 운영의 저장 GET 응답을 보존해 격리 검수 서버에 복사했다. 산청의 `2026-09/13개월` 스냅샷 전체와 결과 번호가 일치하며, 천안·사천은 저장 결과 없음 상태를 유지했다. 합성 API 계약 자료와 실제 자료는 분리했다.
- 운영 API의 최초 읽기는 세 지역 각각 19.3ms, 72.3ms, 10.6ms였다. 이는 운영 브라우저 표시 시간이 아니다.
- 최종 전면 Chrome 검수에서 지역 흐름 첫 표시 223ms, 재진입 5회 62~68ms였다. 흐름에서 공유한 저장값으로 비교 첫 표시 73ms, 비교 재진입 5회 51~57ms였다. 메뉴 진입부터 두 프레임 뒤 표시까지 측정했다.
- 비교 대상에 자료 없는 천안을 추가한 경우 77ms에 부분 자료로 표시했다. 산청의 최근 정상값과 실제 기준월은 유지하고, 공통월 직접 비교는 미확인으로 표시했다.
- 상태 확인 뒤 열린 지표가 유지됐고, 브라우저 오류와 구형 전체회차 프로필 자동 요청·쓰기 요청이 없었다. 원본 파일과 복사한 저장 결과의 해시 불변을 확인했다.
- 관련 테스트 190건, 기본 검사 81개 명령, API 통합 3종이 통과했다. 라이트·다크 색상 기본 검사도 통과했다. 모바일의 실제 브라우저 속도를 측정했다는 뜻은 아니다.

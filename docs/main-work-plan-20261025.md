# 데이터랩 목적에 따른 구현 현황과 개발 순서 · 2026-10-25

목적은 숙박 운영자와 창업 준비자가 내 매장·경쟁업체·지역을 같은 근거로 비교하고, 검토한 행동을 실행하도록 돕는 것이다. 수집 횟수 자체를 사업 성과로 취급하지 않는다.

이번 확인의 코드 기준은 `9c628f9219b7690ed613185d0b029dea4f7fe941`이다. 해당 버전의 별도 작업 사본에서 개발한다. 아래 **기존 구현**은 코드·기존 시험 근거이며 현재 운영의 모든 화면·자료·성능을 다시 검수했다는 뜻이 아니다. 10/20 계획과 과거 완료 기록은 이 문서로 소급 변경하지 않는다.

## 구현된 기능과 남은 확인

## 이번 개발: 분석 → 월간 리포트 → 인사이트 제공

1. **분석 근거 연결**: 확인된 실제 소재지의 반경 배후시장 저장 결과만 읽는다. 연간 통계/경계 연도, 기준점, 결과 ID, 계산 버전, 공개 부분합, 보호·누락을 리포트에 고정한다. 원본 격자 재조회·외부 호출·재계산·작업 등록을 시작하지 않는다.
2. **검토할 실행 계획**: 저장된 요약·품질·공통 표본·지역·업종·전망·배후시장 근거에서 항목을 선택한다. 관리자 의견, 할 일, 담당, 기한, 상태, 결과 메모를 저장한다. 근거가 바뀐 재집계는 계획을 자동 연결하지 않고 재검토한다. 발행본은 원래 스냅샷 해시와 함께 고정한다.
3. **발행본 제공**: 관리자가 발행 PDF 전체를 확인하고 특정 활성 고객에게 명시 배정한다. 고객은 자기 배정본만 열고 같은 발행 PDF를 받는다. 신규 수집·재집계·자동 발행·이메일·외부 공개 링크는 만들지 않는다. 고객 JSON은 허용 필드만 제공하며 원본 관측행·내부 경로·관리자 메모는 제외한다. PDF는 명시 배정한 원래 발행물 전체이므로 발행 해설과 근거를 포함한다.

전달 기능의 기본값은 비활성이다. `INSIGHT_REPORT_DELIVERY_ENABLED=1`은 검수가 끝난 뒤 별도 운영 적용에서 결정하며 이번 작업에서 운영 환경변수를 바꾸지 않는다. 중앙 웹 변경과 인사이트 중계/화면 변경은 각각 배포·실제 로그인 검수가 필요하다.

## 보존 범위

- 기존 정규 수집 시간·순환 순서·키워드·워커 배정, 수집/예약 이력, 원본·객실 검수값을 변경하지 않는다.
- 기존 하트비트/중복 방지/차단/실행권/계정 권한·리포트 revision 잠금을 유지한다. 시간이 지났다는 이유로 잠금을 자동 해제하지 않는다.
- 부분·실패·누락은 정상 0으로 바꾸지 않는다. 공개 예약, 타채널 추정, 실제 결제 실적을 구분한다.
- 기존 발행본은 소급 재계산·덮어쓰기하지 않는다. 새 근거와 계획 수정은 새 수정본으로 검토한다.

## 검증과 다음 단계

격리된 임시 디렉터리·합성 자료로 저장 자료 읽기, 근거 연결, 발행 불변성, 고객 A/B 분리, 세션 철회 중 응답 차단, PDF 고정 바이트, 화면의 정상 0/미확인 구분을 검증한다. 로컬 예시 화면과 PDF는 실제 운영 실적이 아니다. 운영 수집·공급자 API·배포를 검증 방법으로 사용하지 않는다.

로컬 통합 검수 뒤 남은 순서는 **운영 적용 범위 검토 → 중앙/인사이트 각각 적용·인증 화면 검수 → 실제 저장 자료로 월간 초안 생성·관리자 내용 검토 → 명시 발행·고객 배정 → 실제 활용 결과 누적**이다. 실제 초안/발행/배정은 개발 시험으로 대신 완료 처리하지 않는다. 주간 리포트·연휴 분석·성과 인과 검증은 별도 후속 범위다.

운영 적용 전에는 보존한 실제 자료 사본의 동일 조건으로 본문·PDF·고객 투영 수치, 최초/반복 생성 시간과 RSS를 확인해야 한다. 새 모듈도 기존 계산 버전 지문에 포함되므로 첫 미리보기에 저장 집계를 다시 계산할 수 있다. 이번 합성 자료 통과를 운영 성능이나 실제 통계 정확도로 일반화하지 않는다.

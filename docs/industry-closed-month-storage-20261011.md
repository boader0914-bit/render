# 업종분석 마감월 저장

## 사용 기준

- 한국시간으로 숙박월이 끝나면 마감월로 취급한다. 자료가 일부인 월도 달력상 마감월일 수 있으며, 마감과 자료 확보 완료는 별개다.
- 기본 관측 기준일은 `오늘과 월말 중 먼저인 날짜`다. 예를 들어 9월 조회는 10월 11일·12일 모두 9월 30일의 동일한 저장 결과를 사용한다.
- 월말보다 이른 관측 기준일을 직접 지정한 경우에는 별도 결과를 유지한다. 월말 이후의 기준일은 월말로 정리한다. 미래 관측 기준일은 계속 거부한다.
- 업종·실제 소재지·숙박월·관측 기준일·계산 버전별로 한 번 계산한 결과를 저장한다. 조회일 변경이나 서버 재시작만으로 같은 마감월을 다시 계산하지 않는다.
- 처음 선택하는 지역·업종의 조건은 최초 계산이 필요하다. 이번 작업은 새로운 조건의 최초 계산 시간을 줄이는 작업과 구분된다.

## 변경과 보정

- 서버의 수집 저장·실패·복구·관측 추가·업체 저장 이벤트는 전체 마감월을 곧바로 다시 계산하지 않는다. 입력 확인이 필요하다는 기록을 먼저 저장하고, 연속 저장은 1.5초 동안 모아 확인한다.
- 월별 입력 기록을 비교해 영향을 받는 월만 갱신한다. 관측의 숙박월과 검색 순위의 수집월을 각각 반영한다.
- 객실 검수값, 업체 식별·병합·삭제·주소·업종 변경, 과거 관측 보완 및 수집 품질·상품 상세 수정은 해당 자료를 사용하는 월을 갱신한다.
- 영향 범위를 확정할 수 없는 자료나 공통 기준 변경은 보수적으로 전체 집계를 갱신한다.
- 계산 중 입력이 바뀌면 해당 월의 이전 계산 결과를 최신 결과로 게시하지 않는다. 실패 시 마지막 정상 결과와 실패 상태를 유지한다.
- 입력을 읽는 중 파일 교체가 발생하면 자료 손상으로 고정하지 않고 재검사한다. 입력 확인 실패 상태에서는 새 계산 결과를 정상 결과로 덮어쓰지 않는다.
- 마감월의 정상 결과가 보정되면 직전 정상 결과를 `industry_analysis/revisions/<조건 키>/<이전 버전>.json`에 보관한 뒤 현재 결과를 갱신한다. 원본 수집 이력은 수정하지 않는다.

## 기존 저장 결과

이전 버전에서 오늘을 기준일로 저장한 과거 월은 새 월말 조건과 다른 파일이다. 기존 파일을 보존하고, 새 월말 조건으로 최초 한 번 계산한다. 기존의 오늘 기준일 작업은 자동 갱신 대상에서 제외해 중복 계산을 만들지 않는다.

## 화면

정상 저장된 마감월은 **마감월 저장 집계**로 표시한다. 계산시각·관측 기준일·자료 확보율은 계속 표시하며, 갱신 대기·진행·실패 안내를 정상 저장 표시로 덮지 않는다.

## 적용 범위

STAYDATALAB 업종분석의 저장 및 조회 구조를 변경한다. 업체별 통합 DB·발행된 월간리포트·인사이트의 저장 정책은 이번 작업에 포함하지 않는다. 운영 배포·실제 수집·외부 API 갱신·일정 변경은 이번 개발에서 수행하지 않는다.

## 로컬 검증

- 업종 계산·저장·입력 변경·UI 테스트 76개 통과.
- 외부 통신을 막은 로컬 서버에서 다른 월 수집자료 추가 및 재시작 후 기존 마감월의 계산시각·결과 버전·수치가 유지되는 것을 확인했다.
- 같은 서버에서 객실 검수값 변경의 과거 월 반영, 관리자 권한·수동 재준비 검사, 원본 이력 보존을 확인했다.
- 업체 통합 DB와 월간리포트 HTTP 통합 검사, 기본 코드 검사 76개 명령 통과.
- 운영 배포 및 운영 서버의 시간·메모리 측정은 아직 수행하지 않았다.

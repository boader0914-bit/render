# 2026-09-22 자동 수집 부하 조정 및 시간 비교

사용자 요청: 다음 날 요청 부담을 낮춰 수집하고 기존 소요시간과 비교한다.

## 적용 범위

- 시작일: 2026-09-22, 매일 한국시간 14:00 자동 수집.
- 기존 13개 키워드 순서, precision/revenue_detail, 상세 1~20위, 전체 상품, 관측일 포함 31일 유지.
- 업체 1개씩 처리, 상품 일정 최대 2개 동시 처리, OTA 보조 조회 동시 1개.
- 크롤러 안의 네이버 HTTP 요청은 전체 최대 2개 동시, 요청 시작 간격 최소 200ms. 이 간격은 네이버가 제시한 허용 기준이 아니라 비교 실험을 위한 부하 상한이다.
- 다음 요청은 이전 요청의 응답 본문 수신까지 포함한 동시 처리 수를 확인한다. 네이버 외 요청에는 이 제한을 적용하지 않는다.
- IP 변경, 사용자 행동 위장, 캡차 해결을 추가하지 않는다. 접근 제한 시 추가 네이버 요청을 멈춘다.
- 비교 후 별도 지시가 있기 전까지 낮춘 설정을 유지한다. 자동으로 이전 속도로 복귀하지 않는다.
- 이 실험에서는 키워드 간 자료 재사용을 추가하지 않는다. 요청 속도 변경과 수집 범위 변경의 영향을 섞지 않기 위해서다.

조회 수가 같고 요청 시작 간격이 200ms라면 날짜별 예약 조회만으로 약 5시간 59분이 필요하다. 이는 계산상 하한에 가까운 참고값이며, 실제 총 소요시간은 응답 지연·보조 요청·업체 및 상품 수에 따라 달라진다. 내일 실제 기록으로 비교한다.

## 운영 설정과 읽기 전용 비교

```sh
node scripts/configure_daily_collection.cjs --low-load-from 2026-09-22 --data-dir /var/data
node scripts/configure_daily_collection.cjs --status --data-dir /var/data
node scripts/compare_daily_collection.cjs --baseline 2026-09-21 --trial 2026-09-22 --data-dir /var/data
```

설정 명령은 자동 수집 활성 상태를 보존하고 요청 속도 프로필만 추가한다. 수집을 시작하거나 기존 실행 기록을 초기화하지 않는다. 미래 시작일의 설정은 과거 날짜의 설정 지문을 변경하지 않는다.

비교에서는 전체 경과시간과 실제 키워드 실행시간 합계, 키워드별 시간, 완료·부분·실패·차단 수, 상세 업체 및 날짜별 관측 수를 함께 제시한다. 양쪽 수집 범위와 완료 품질이 맞는 키워드만 시간 증감을 비교한다. 실제 HTTP 요청량·대기 시간·최대 동시 요청은 새 계측값이 있는 날짜만 보고한다.

날짜가 다르면 요일, 검색 결과, 객실 상품 수, 네이버 응답 속도가 달라질 수 있으므로 소요시간 차이를 속도 설정만의 효과로 단정하지 않는다. 미완료를 완료로 보고하거나 실패를 0객실로 해석하지 않는다.

이 작업의 자동 점검은 비교가 끝날 때까지 15:30·18:30·21:30·23:30에 읽기 전용으로 확인한다. 정상 진행 중에는 조용히 기다리고, 최종 비교 결과는 한 번 보고한다. 비교가 끝나면 기존 매일 15:30 점검으로 복원한다.

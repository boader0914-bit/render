# 인사이트 내 매장·경쟁업체 자료 재조회

내 매장과 경쟁업체의 A 기본정보, B 예약채널, C 통합관측은 마지막 정상 조회 결과를 먼저 표시하고 저장자료 GET으로 변경 여부를 확인한다. 데이터랩의 원본·통합 DB와 수집기 설정은 변경하지 않는다.

## 저장과 복원

- 인사이트 서버의 기존 영속 디스크에서 `/var/data/insight-company-cache`를 사용한다. `INSIGHT_COMPANY_CACHE_DIR`로 전용 절대 경로를 지정할 수 있으며, `DATA_DIR`가 있으면 그 아래에 만든다. 로컬은 경로를 명시하지 않으면 파일을 만들지 않는다.
- 서버 주소, 고객/관리자 화면, 현재 확인한 고객 계정, 업체, 요청한 숙박월과 현재 등록·업체 버전을 구분해 저장한다. 공개 지역지표처럼 다른 계정의 결과를 공유하지 않는다.
- 현재 고객 표시용으로 정리된 결과의 허용 필드만 저장한다. 로그인 세션·쿠키·토큰·비밀번호·CSRF·현재 권한·수집 대기 요청·사용 한도·보정 입력은 저장하지 않는다. 저장본은 원본 DB를 대체하지 않는다.
- 시작 시 저장된 결과의 형태·크기·체크섬·확인 시각을 검증한다. 새 `/me`와 업체 GET은 중앙 로그인·이용 상태·등록 관계·현재 업체 버전을 다시 확인한 뒤에만 일치하는 저장본을 연결한다. 등록 해제·로그인 만료·권한 거절·검수값 변경에 맞지 않는 결과는 복원하지 않는다.
- 내 매장과 경쟁업체의 허용된 자료를 `/me`에 함께 넣어 새로고침 후 즉시 표시한다. 첫 업체 GET은 저장본을 반환하면서 실제 최신 결과를 뒤에서 확인한다. 복원 때문에 수집 POST를 실행하지 않는다.
- 기본 숙박월과 명시한 숙박월을 구분한다. 월이 바뀌어도 지난달 결과를 이번 달 값으로 표시하지 않는다. 통합관측이 준비 중이거나 수집이 진행 중인 자료는 정상 완료 저장본으로 만들지 않는다.

## 시각과 실패 처리

- 원래 정상 확인 시각부터 최대 7일 동안 복원한다. 복원·재조회만으로 확인 시각이나 만료 시각을 연장하지 않는다. 실제 최신 결과를 받으면 일반 메모리 캐시로 전환한다.
- 저장소는 표시 규칙과 중앙 서버별 최대 128건·16MiB, 한 파일 최대 2MiB로 제한한다. 이는 저장 캐시의 용량 보호이며 수집할 상품·객실 수를 제한하지 않는다. 32MiB 이상의 디스크 여유를 보호하고, 임시 파일 동기화 뒤 원자적으로 교체한다. 늦은 이전 응답이나 실패한 쓰기가 마지막 정상 파일을 덮거나 삭제하지 않도록 한다.
- 서버와 브라우저 사이의 작은 시계 차이는 최대 60초 허용하되 실제 확인·만료 시각은 그대로 사용한다.
- 최신 조회가 일시 실패하면 유효한 마지막 정상 결과와 확인 실패 안내를 함께 표시한다. 7일을 넘었거나 손상됐거나 사용할 수 없는 저장본은 중앙 저장자료 조회로 돌아간다. 권한 오류는 일시 연결 오류와 구분한다.
- 정상 0실, 미확인·오류·누락, 부분 매출과 가격 누락을 유지한다. 저장·복원으로 미확인 수량이나 금액을 0으로 바꾸지 않는다.
- 저장 상품 원본으로 복구한 관측은 중앙에서 발급한 `sourceRecovery`의 업체·수집·숙박일·상품종류·관측시각과 SHA-256 연결값만 보존한다. 원본 payload·경로·인증정보를 캐시에 추가하지 않으며, 원래 `runQuality=unknown`도 그대로 둔다. 연결 범위가 맞지 않으면 복구 증명을 버리고 일반 화면 자료만 표시한다.
- 중앙이 제공한 가격 미확인 객실수·대체단가 적용 객실수·금액(`phoneMissingPriceBookings`, `phoneFallbackBookings`, `phoneFallbackRevenue`)은 안전한 비음수 숫자 또는 `null`로 보존한다. 없는 필드를 추정하거나 `null`을 0으로 채우지 않는다.
- 기존 정상 표시 캐시의 지문은 유지한다. 디스크 복원 자체로 신규 검수 기록을 만들지 않고 실제 최신 중앙 응답을 확인한 경우에만 보관 연결을 수행한다. 새 검수는 추가 기록이며 이전 일별 검수·발행 리포트의 본문과 체크섬은 바꾸지 않는다.
- 브라우저에는 로그인된 페이지의 메모리만 사용한다. 개인별 결과를 localStorage·sessionStorage 등에 저장하지 않는다.

## 운영 검수

단위 검수 외에 서로 다른 인사이트 서버 인스턴스를 같은 임시 영속 디렉터리로 시작해 내 매장·경쟁업체 복원, 계정/관리자/주소별 분리, 현재 권한, 숙박월, 검수값 변경, 원래 확인 시각, 진행 중 조회와 늦은 응답, 일시 실패, 정상 0·미확인을 검증한다. 운영에서는 두 업체의 정상 결과를 저장한 뒤 인사이트만 재시작하고 첫 표시 시간과 저장본 복원 여부를 확인한다.

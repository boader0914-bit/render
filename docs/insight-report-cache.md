# 인사이트 리포트 재조회와 서버 재시작 복원

리포트의 현재 상황·경쟁 비교·지역 배경·다음 행동은 마지막 정상 조회 결과를 먼저 표시하고, 저장자료 GET으로 변경 여부를 확인한다. 발행된 보고서를 만들거나 수집을 실행하는 기능이 아니다.

- 기존 인사이트 영속 디스크의 `/var/data/insight-report-cache`에 고객 표시용 허용 필드만 보관한다. `INSIGHT_REPORT_CACHE_DIR`로 전용 절대 경로를 지정하거나 `DATA_DIR` 아래에 만들 수 있다. 로컬은 경로를 지정하지 않으면 파일을 만들지 않는다.
- 중앙 서버, 인사이트 주소, 관리자/고객 화면, 현재 고객 계정, 선택 내 매장, 한국시간 기준 숙박기간을 구분한다. 회사·경쟁업체·관심지역의 등록 관계, 현재 업체 검수값과 버전, 자료 준비 상태가 바뀌면 이전 조건의 저장본을 연결하지 않는다.
- 각 리포트 GET과 새로고침의 `/me`는 중앙 로그인과 현재 등록·조회 권한을 다시 확인한다. 허용된 저장본은 `/me`의 `reportViews`에 넣어 첫 화면부터 표시한다. 세션·비밀번호·쿠키·토큰·CSRF·현재 권한·보정 입력·수집 요청·이용 한도는 파일에 저장하지 않는다.
- 기준 내 매장을 명시한 조회와 기본 선택 조회를 구분한다. 현재 리포트는 한국시간 오늘부터 30일이므로 시작일·종료일·일수가 정확히 일치할 때만 재사용한다. 날짜가 바뀌거나 조회 도중 자정을 넘으면 지난 기간의 자료를 오늘의 결과로 표시하지 않는다. 지역 배경의 마지막 기준월도 같은 기간 규칙으로 확인한다.
- 원래 `generatedAt`과 정상 확인 시각을 보존한다. 파일의 고정 유효기간은 최대 7일이며, 조회만으로 연장하지 않는다. 현재 리포트 기간과 맞지 않는 파일은 유효기간 안이어도 복원하지 않는다. 작은 브라우저 시계 차이는 최대 60초 허용한다.
- 재시작 후 첫 GET은 일치하는 저장본을 반환하면서 중앙 저장자료를 뒤에서 확인한다. 같은 조건의 진행 중 요청은 공유하며, 화면의 후속 GET도 횟수를 제한한다. 최신 결과를 실제로 확인한 후에만 확인 시각을 갱신한다. 일반 화면 메모리 캐시는 30분이며 브라우저 저장소는 사용하지 않는다.
- 실패·권한 거절·손상 파일·용량 부족·늦은 이전 응답이 마지막 정상 리포트를 덮지 않도록 한다. HTTP 200이라도 업체 조회 실패나 지역 지표의 명시적 오류가 들어 있으면 정상 저장본으로 취급하지 않는다. 유효한 이전 결과가 있으면 지연 안내와 함께 유지하고, 없으면 조회 실패를 알린다. 정상 0과 누락·미확인 null, 실제 부분 관측은 그대로 보존한다.
- 저장은 임시 파일 동기화 후 원자적으로 교체한다. 전용 저장소의 건수·용량·파일 크기·남은 공간을 제한하고, 이전 확인 시각과 체크섬·표시 규칙을 검증한다. 원본 DB나 기존 월간 집계는 수정하지 않는다.

검수는 새 인사이트 프로세스의 실제 저장소 복원, 현재 중앙 권한, 계정·주소·관리자 구분, 기본/명시 매장, 날짜 전환, 원래 확인 시각과 생성 시각, 경쟁업체·지역·검수값 변경, HTTP 200 내부 오류, 정상 0·미확인, 늦은 응답과 동시 저장을 포함한다. 운영에서는 정상 리포트를 저장한 뒤 인사이트만 재시작하고 첫 표시 시간·복원 수치·백그라운드 확인을 기록한다.

# 인사이트 리포트 재조회와 서버 재시작 복원

리포트의 현재 상황·경쟁 비교·지역 배경·다음 행동은 현재 권한과 조건이 일치하는 마지막 검증 결과를 먼저 표시하고, 저장자료 GET으로 변경 여부를 확인한다. 전체 자료를 확인한 결과와 일부 자료만 확인한 결과를 구분한다. 발행된 보고서를 만들거나 수집을 실행하는 기능이 아니다.

- 기존 인사이트 영속 디스크의 `/var/data/insight-report-cache`에 고객 표시용 허용 필드만 보관한다. `INSIGHT_REPORT_CACHE_DIR`로 전용 절대 경로를 지정하거나 `DATA_DIR` 아래에 만들 수 있다. 로컬은 경로를 지정하지 않으면 파일을 만들지 않는다.
- 중앙 서버, 인사이트 주소, 관리자/고객 화면, 현재 고객 계정, 선택 내 매장, 한국시간 기준 숙박기간을 구분한다. 회사·경쟁업체·관심지역의 등록 관계, 현재 업체 검수값과 버전, 자료 준비 상태가 바뀌면 이전 조건의 저장본을 연결하지 않는다.
- 각 리포트 GET과 새로고침의 `/me`는 중앙 로그인과 현재 등록·조회 권한을 다시 확인한다. 허용된 저장본은 `/me`의 `reportViews`에 넣어 첫 화면부터 표시한다. 세션·비밀번호·쿠키·토큰·CSRF·현재 권한·보정 입력·수집 요청·이용 한도는 파일에 저장하지 않는다.
- 기준 내 매장을 명시한 조회와 기본 선택 조회를 구분한다. 현재 리포트는 한국시간 오늘부터 30일이므로 시작일·종료일·일수가 정확히 일치할 때만 재사용한다. 날짜가 바뀌거나 조회 도중 자정을 넘으면 지난 기간의 자료를 오늘의 결과로 표시하지 않는다. 지역 배경의 마지막 기준월도 같은 기간 규칙으로 확인한다.
- 원래 `generatedAt`과 검증한 `checkedAt`을 보존한다. 부분 결과의 확인 시각은 그 부분 결과를 조회한 시각이며, 모든 자료를 확보했다는 뜻이 아니다. 파일의 고정 유효기간은 최대 7일이며, 조회만으로 연장하지 않는다. 현재 리포트 기간과 맞지 않는 파일은 유효기간 안이어도 복원하지 않는다. 작은 브라우저 시계 차이는 최대 60초 허용한다.
- 재시작 후 첫 GET은 일치하는 저장본을 반환하면서 중앙 저장자료를 뒤에서 확인한다. 같은 조건의 진행 중 요청은 공유한다. 리포트 화면은 최대 195초 동안 후속 GET을 8회까지 확인하여 3분 내 계산 완료를 반영하며, 최신 확인 성공이나 실패가 확인되면 중단한다. 지역분석의 기존 확인 시간은 변경하지 않는다. 최신 결과를 실제로 확인한 후에만 확인 시각을 갱신한다. 일반 화면 메모리 캐시는 30분이며 브라우저 저장소는 사용하지 않는다.
- 중앙 HTTP 200의 구조·현재 권한·대상·기간이 모두 맞으면 일부 업체나 월 자료가 없어도 HTTP 200으로 확인된 부분을 표시한다. `dataQuality.status='partial'`, 업체·지역의 `sourceStatus/sourceIssues`, `responseCache.state='partial'`와 `partial=true`를 유지한다. 이때 `refreshFailed=false`는 연결과 응답 검증이 성공했다는 뜻이며 모든 원자료가 있다는 뜻이 아니다. 일부 지표의 빈 달을 나타내는 `missing/partial`와 실제 `error/failed/blocked/unavailable`는 구분한다.
- 전체 확인 결과는 기존 `report-*` 저장소, 부분 결과는 별도 `report-partial-*` 저장소와 `quality='partial'` 봉투로 보관한다. 부분 결과는 마지막 전체 확인 파일을 덮어쓰지 않는다. 재시작 후 같은 권한·선택·기간의 검증된 두 결과 중 `checkedAt`이 최신인 결과를 복원하며, 시각이 같으면 전체 확인 결과를 우선한다. 부분 결과는 `/me.reportViews`와 반복 GET에서도 부분 표시를 유지하고, 전체 자료를 확인한 다음 응답이 와야 전체 확인 결과로 바뀐다.
- `dataQuality.issues`와 업체·지역별 `sourceIssues`에는 허용한 `scope`, 업체·지역 ID, 이름, 월, 기간, 코드, 한글 사유, 선택적인 지표 키·이름만 전달한다. 회사 문제의 ID와 기간은 해당 업체 및 리포트의 30일 범위를 벗어날 수 없다. 지역 문제는 현재 조회가 허용된 지역이어야 한다. 원본 예외 메시지·스택·토큰·계정 정보는 전달하거나 저장하지 않는다. UI는 정상인 업체 값을 함께 보여 주고 확인하지 못한 업체·기간·사유를 별도 표로 표시한다.
- 실제 HTTP 오류·권한 거절·손상 파일·용량 부족·늦은 이전 응답은 부분 결과로 가장하지 않는다. 이미 표시 가능한 결과가 있으면 원래 수치와 확인 시각을 유지하고 `refreshFailed=true`를 표시한다. 진행 중 확인인 `refreshing=true`는 과거 실패 기록보다 우선하여 제한된 후속 GET을 계속하며, 진행하지 않는 실패가 확인되면 자동 확인을 중단한다. 401·403·404 및 범위 불일치에서 이전 자료를 부활시키지 않는다. 지역 `networkAttempted`는 명시적으로 `false`여야 하며, 미확인·외부 호출 결과를 허용하지 않는다.
- 정상 0과 누락·미확인 null을 구분한다. 일부 월이 없더라도 다른 정상 월의 예약·금액은 보존하며, 미확인 값을 0으로 채우거나 부분 결과를 전체 결과로 저장하지 않는다. 부분 결과의 조회가 빨라도 월별 집계의 `pending/updating`이나 실제 지표의 최신 확보월이 완료·현재 월로 바뀌는 것은 아니다.
- 저장은 임시 파일 동기화 후 원자적으로 교체한다. 전용 저장소의 건수·용량·파일 크기·남은 공간을 제한하고, 이전 확인 시각과 체크섬·표시 규칙을 검증한다. 원본 DB나 기존 월간 집계는 수정하지 않는다.

검수는 새 인사이트 프로세스의 실제 저장소 복원, 현재 중앙 권한, 계정·주소·관리자 구분, 기본/명시 매장, 날짜 전환, 원래 확인 시각과 생성 시각, 경쟁업체·지역·검수값 변경, HTTP 200의 부분 자료·진단 사유, 정상 0·미확인, 늦은 응답과 동시 저장을 포함한다. 전체 확인 파일이 부분 갱신 후에도 보존되는지, 별도 부분 파일과 사유가 재시작 후에도 부분 상태로 복원되는지, 전체 자료 회복 시 새 전체 확인 결과가 선택되는지도 검증한다. 운영에서는 첫 표시 시간과 백그라운드 재확인 완료를 따로 기록한다.

## 새 리포트의 저장자료 우선 표시

현재 권한·등록 업체·선택 매장·오늘부터 30일 조건의 완성 리포트가 아직 없으면 중앙 `GET /reports/briefing?savedOnly=1`을 조회한다. 이 조회는 이미 저장된 업체 월별 집계와 지역 결과만 조합하며, 원자료 전체 조회·월별 재계산·외부 지표 호출·수집을 실행하지 않는다. 인사이트 내부의 이 빠른 조회는 재시도를 포함해 최대 3초로 제한하고, 실제 리포트 계산의 기존 180초 한도와 구분한다. 중앙이 아직 이 조회를 지원하지 않는 명시적 400/404일 때에만 기존의 일반 조회로 호환 연결한다. 인증 거절·요청 제한·손상 응답은 호환 연결을 핑계로 우회하지 않는다.

저장된 값은 `calculation.mode='saved_only'`, `responseCache.state='preview'`, `preview=true`, `calculationStatus='pending'`, `refreshing=true`로 먼저 표시한다. 이어 같은 조건의 일반 리포트 GET을 뒤에서 한 번만 실행한다. 이때 `generatedAt`은 저장자료를 조합한 시각이고 `checkedAt`은 현재 조건과 응답 구조를 확인한 시각이다. `oldestSourceCalculatedAt/latestSourceCalculatedAt`이 실제 저장된 업체 월별 계산시각의 범위이므로 세 시각을 최신 계산 완료로 섞어 표시하지 않는다. 저장자료 자체에 빈 달이나 업체가 있으면 `dataQuality.partial`과 `sourceIssues`를 그대로 유지하며, 숫자가 없는 부분은 null이다.

미리보기는 `report-preview-*`와 `quality='preview'` 봉투로 별도 보관한다. 기존 `report-*` 및 `report-partial-*`의 형식과 지문 버전은 바꾸지 않아 배포 전 저장본을 그대로 복원한다. 같은 현재 조건의 검증된 완성/부분 리포트가 있으면 그 결과를 미리보기보다 항상 우선하며, 완성·부분끼리는 기존 최신 확인시각 규칙을 유지한다. 명시적 새로고침도 저장 결과를 먼저 표시하고 뒤에서 계산한다. 늦게 도착한 저장자료 미리보기가 먼저 끝난 실제 계산 결과를 덮어쓸 수 없다.

실제 일반 GET이 성공하면 수치와 부분 여부가 미리보기와 같더라도 `calculationStatus='complete'`로 전환하고 저장자료 전용 `calculation` 표식을 제거한다. 자료가 일부 없는 실제 결과는 여전히 부분 리포트다. 일반 GET에 미리보기 표식이 있으면 완성 결과로 승격하거나 완성 저장소에 기록하지 않는다. 미리보기 화면은 계산이 끝나기 전에는 경쟁 차이의 판단과 다음 행동 추천을 확정해서 보여 주지 않는다.

계산에 실패하면 미리보기와 원래 확인시각을 유지하며 `calculation.status='failed'`, `calculationStatus='failed'`, `refreshFailed=true`, `refreshing=false`를 표시한다. 오류는 `REPORT_CALCULATION_TIMEOUT` 또는 `REPORT_CALCULATION_FAILED`와 고정된 안전 문구만 전달하며, 중앙 예외 메시지를 기록하지 않는다. 실패 상태도 별도 미리보기 저장본에 보존하므로 재시작이나 자동 후속 GET이 계산을 끝없이 다시 시도하지 않는다. 사용자가 명시적으로 다시 확인하면 오류 표식을 지우고 pending 상태로 한 번 재시도한다. 계정·업체·기간·권한·한국 날짜가 달라지면 이 미리보기도 재사용하지 않는다.

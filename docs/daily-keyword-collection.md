# 매일 주요 거점 상세 수집

운영 웹 서버의 기존 단일 수집 큐를 사용한다. 별도 유료 작업 서버나 PC 실행은 필요하지 않다. 배포만으로 수집을 시작하지 않으며, 운영 디스크의 설정 파일을 명시적으로 활성화한다.

- 시작: 매일 한국시간 14:00, 서버 점검 간격 때문에 최대 약 60초 차이. 기존 수동 수집이 있으면 그 작업이 끝난 뒤 시작한다.
- 순서: 경남글램핑 → 대구글램핑 → 부산글램핑 → 경북글램핑 → 충남글램핑 → 전남글램핑 → 전북글램핑 → 대전글램핑 → 서울근교글램핑 → 경주글램핑 → 여수글램핑 → 가평글램핑 → 포천글램핑.
- 상세 수집: precision / revenue_detail, 순위 1–20, 전체 상품, 관측일을 포함한 향후 31일. 실제 검색 결과가 20개 미만이면 가용 결과를 수집한다.
- 한 건 완료 후 다음 키워드를 시작한다. 같은 날 자동 재시도는 하지 않는다.
- 14시 이후 서버가 재시작되면 당일 미시작 키워드만 이어간다. 과거 날짜는 소급 수집하지 않는다. 실행 중 재시작된 키워드는 결과 불명(interrupted)으로 표시하고 자동 재실행하지 않는다.
- 매 건 시작 전 사용 가능한 디스크가 200MiB 이상인지 확인한다. 부족, 디스크 확인 실패, 네이버 메인/예약 조회의 명시적 403·429, 관리자 수집 취소는 그날의 남은 자동 수집을 중단한다. 기존 파일 삭제나 저장공간 자동 증설은 하지 않는다.
- 완료/부분/실패는 manifest 집계와 날짜별 예약 응답의 HTTP 상태·오류·재고값 존재 여부를 확인한다. 상품의 실제 판매정책이나 가격 정확성까지 검증했다는 뜻은 아니다. 불완전한 예약 수집 원본은 보관하며 업체 기준정보·분석 이력·shadow DB 반영을 보류한다.

## 운영 설정

확인된 운영 서비스는 `srv-da9q6don74is738t7id0`, 사이트는 https://staydatalab.kr 이다. 운영 Render Shell에서 실행한다.

```sh
node scripts/configure_daily_collection.cjs --enable --data-dir /var/data
node scripts/configure_daily_collection.cjs --status --data-dir /var/data
node scripts/configure_daily_collection.cjs --disable --data-dir /var/data
```

설정은 `/var/data/config/daily_keyword_collection.json`, 날짜별 실행 기록은 `/var/data/history/daily_keyword_collection_state.json`에 저장한다. 비활성화하면 진행 중인 한 건은 마저 저장하고 다음 건부터 시작하지 않는다. 즉시 중지는 기존 관리자 수집 중지 기능을 사용한다. 상태 파일을 삭제하거나 당일 항목을 초기화하면 중복 방지 기록이 사라지므로 하지 않는다.

관리자 로그인 후 `GET /api/collection-schedule`에서 정책, 다음 실행 시각(UTC), 오늘 키워드별 진행 상태·runId·걸린 시간·수집 집계·중단 사유를 확인할 수 있다. API는 읽기 전용이다.

## 용량과 운영 확인

2026-09-20 배포 전 확인한 여유 공간은 572,100,608 bytes이다. 이전 36회 결과 평균 7.89MB를 단순 적용하면 13회 약103MB/일이며, 200MiB 보호 여유를 남기면 며칠 안에 공간 부족으로 멈출 수 있다. 실제 증가량은 상세 기간·검색 결과·분석 이력 크기에 따라 달라진다. 첫 수집 이후 실제 소요시간, 결과 크기, 부분 실패를 확인해 보관·증설 정책을 정한다.

테스트는 시간과 크롤러를 대체하거나 임시 데이터 폴더를 사용한다. 운영 수집을 시험 목적으로 앞당겨 실행하지 않는다.

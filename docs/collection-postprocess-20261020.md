# 수집 완료와 중앙 후처리 분리

## 확인된 지연

2026-10-20 BG 전남글램핑 예약(`rotation_2026-10-20_2`)은 수집과 원본 게시가
11:26:39.358 KST에 끝났지만 예약 완료 영수증은 11:32:47.905에 저장됐다.
중앙 처리 구간은 368,547ms(6분 8.547초)다. 당시의 단계별 계측은 없어 특정 API가
이 시간 전부를 사용했다고 단정하지 않는다.

기존 완료 경로는 원본 게시/품질 확인 뒤에도 `appendHistoryForRun`을 기다렸다.
전역 쓰기 잠금 안의 `loadRun`은 검색광고·데이터랩 지표 조회, 상품 가공,
업체 마스터 갱신을 수행하고, 관측 이력 전체 읽기와 중복 제거까지 진행했다.
그 다음 시간 기록, 업종 변경 표시, 회원 이력 준비를 마쳐야 예약 완료가 저장됐다.
외부 지표 조회에는 명시적 요청 시간 제한도 없었다. 잠금 재진입 자체의 교착은 아니다.

## 새 완료 경계

1. 기존 게시·수집 품질 검증을 그대로 수행한다.
2. 원본 manifest SHA와 안전한 후처리 입력을 디스크에 저장한다.
3. 수집 요청과 예약 완료를 같은 runId로 확정한다. 공동 예약은 SQLite commit 뒤에만
   후처리 held를 해제한다. 이후 UI의 기존 갱신 주기에 완료가 표시된다.
4. 업체 DB·관측 이력·분석 변경·회원 이력·shadow DB 전송은 별도 작업에서 처리한다.
   이 자동 처리에는 `skipExternal:true`를 사용한다. 지역/검색 지표 갱신은 기존 기능을 이용한다.

수집 complete와 업체 DB 반영 held/queued/running/complete/failed는 다른 상태다.
아직 반영하지 않은 관측 수를 0으로 만들지 않는다. 후처리 오류는 이미 검증된
수집 결과를 숨기거나 차단/부분 자료를 complete로 바꾸지 않으며 재수집을 실행하지 않는다.

## 저장·재시작·장애

- `history/collection_postprocess/queue.json`: 최근 요약과 대기열.
- `runs/<runId SHA>.json`: 회차별 멱등 영수증. 과거 요약이 정리돼도 재처리하지 않는다.
- `pending/<runId SHA>.json`: 입력 journal. record/index 저장 사이에 종료돼도 미처리 입력을 찾는다.
- 파일 임시 저장·fsync·rename을 사용하며 Linux에서는 부모 디렉터리도 fsync한다.
- 한 번에 하나씩 처리한다. 중앙 수집 중에는 새 후처리 진입을 미룬다. 실패는 제한된
  대기로 최대 3회 처리하며, 해당 시도는 저장 자료 가공이며 공급자 재수집이 아니다.
- 재시작으로 중단된 작업만 복구한다. held는 정확한 완료 slot/runId가 확인될 때만 해제한다.
  불확실한 예약·수집 보호·기존 일정은 변경하지 않는다.
- 후처리 시 SHA와 품질을 다시 확인한다. 이력 추가 및 시간 기록은 동일 회차 중복을 방지한다.
- 보관함/예약/수집 이력은 후처리 상태를 별도로 표시한다. 큐를 읽지 못해도 보관된 결과는
  유지하고 `업체 DB 반영 상태 확인 필요`로 표시한다.
- 인사이트 연결부는 수집 완료와 DB 반영 대기를 구분하고, DB 반영 후 기존 업체·범위 검증을
  수행한다. 고객 페이지나 인사이트 서비스 자체를 변경하지 않는다.
- 대기열에 등록된 결과의 화면 조회는 업체 갱신·관측 backfill·검색지표 조회를 중복 실행하지 않는다.

관리자 GET `/api/collection-postprocess?runId=...`에서 상태·재시도·갱신시각·단계별 시간을
확인한다. context, 비밀번호, 쿠키, lease, 토큰은 공개하지 않는다. 오류는 허용된 코드만 남긴다.
`collection_postprocess_stage` 로그는 검증/이력/시간기록/업종/회원 이력 시간을 분리한다.

## 검증 및 운영 적용

`test:collection-completion`과 `test:collector-recovery`를 실행한다. 모든 수집은 합성 자료와
로컬 HTTP worker로 모사하고 실제 공급자 요청/실행을 금지한다. 완료 순서, 지연·실패·재시작,
저장 중간 실패, 원본 보존, 권한, 보관함 조회, 기존 선택 월/통합카드 유지 회귀를 확인한다.

운영 배포 시 중앙 웹 서버 변경이 필요하다. BG worker 실행 코드와 공급자 속도/보호/예약 설정은
이번 변경 대상이 아니다. 배포 뒤 다음 정상 예약의 게시시각→예약 완료시각과 DB 반영 시간을
분리 측정한다. 로컬 시험 시간을 운영 지연 보장으로 표현하지 않는다.

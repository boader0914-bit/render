# 반경 50km·100km 인구·산업 배후시장

2026-10-21 개발 기록. **로컬 구현이며 운영 미배포**다. 공식 코드집 확보에 이어 사용자 승인한120개 항목을 복원하고 **요청번호89375·승인**을 확인했다. 신청내역은1건이고 접수 상세120행이 제출 전 목록과 모두 일치했다. 실제 통계값·경계의 다운로드·반입은 미완료다. [자료 확보 상태](regional-catchment-acquisition-20261021.md). 모의 격자의 계산·API·화면 검수는 실제 지역의 인구·산업 수치 검증과 구분한다.

## 화면과 집계 기준

관리자 `지역분석 → 지역 현황 → 기본 입지`에 **지역 배후시장 · 연간 기초자료**를 둔다. 기존 관광 흐름과 KOSIS 행정구역 통계는 유지한다. 대표점은 숙소 위치와 다르므로 확인한 중심점 명칭·좌표·출처를 별도로 저장한다. 기존 지도용 가상 배치 좌표나 오래된 행정경계의 중심점을 자동 채택하지 않는다. 광역 전체는 단일 기준점 반경으로 해석하지 않는다.

| 표시 | 포함 조건 | 해석 |
| --- | --- | --- |
| 0~50km | 중심점에서 직선거리 50km 이하 | 안쪽 배후시장 |
| 50km 초과~100km | 50km 초과, 100km 이하 | 바깥쪽 배후시장 |
| 누적 100km | 위 두 구간의 합 | 앞의 두 값과 다시 더하지 않음 |

WGS84 경위도에서 구면 거리식을 사용하고 격자 **중심점 포함**으로 배정한다. 주행거리·시간이나 정확한 지오데식 측량이 아니다. 경계와 걸치는 격자 수와 해상도를 함께 기록하며, 격자 내부의 실제 분포를 면적비례로 가정하지 않는다. 기본 자료 준비는 1km 격자를 권장한다.

인구는 거주지, 사업체·종사자는 사업장 기준이다. 인구와 종사자를 더해 고유 고객 수라고 제시하지 않는다. 산업분류 차수·선택 범위를 자료 묶음별로 저장하며 다른 분류·연도·단위 행을 한 묶음에서 혼합하지 않는다. 현재는 선택한 산업 범위의 사업체·종사자 총량이며 여러 산업의 구성비를 자동 비교하는 기능은 후속 범위다.

## 자료 확보와 품질

[공식 출처·준비 절차](regional-catchment-sources.md)에 SGIS CSV/SHP, 대안 자료와 좌표변환·열 매핑을 기록했다. 준비 도구는 `scripts/prepare_catchment_grid.cjs`다. 실제 코드집으로 명시한 열·항목 매핑만 사용하며 외부 요청을 보내지 않는다.

- 통계연도와 경계연도, 산업분류, 원본 CSV·원본 경계·변환 도형·매핑 해시를 분리한다.
- 입력 CSV와 WGS84 GeoJSON을 격자 ID로 연결한다. 지표행이 경계와 연결되지 않거나, 중복/혼합 연도/잘못된 좌표가 있으면 반입을 거부한다.
- SGIS 공개0은 `protected_zero`, 비공개는 `suppressed`, 빈 값은 `not_acquired`다. 다른 출처가 명확하게 제공한 정상0만 `observed_public:0`으로 표현할 수 있다.
- 보호0·비공개·누락 또는 잘린 범위가 있으면 전체 반경값은 `null`이다. 알려진 공개 부분합과 상태별 격자 수를 따로 표시한다.
- `completeFrame`과 확보 범위는 **관리자 반입 선언**이다. 직사각형 범위가 원 전체를 포함하더라도 파일 내부의 누락 없는 공간범위를 서버가 독립 확인했다는 뜻이 아니다. 범위가 불완전하거나 해당 구간에 격자가 없으면 전체 합계로 제시하지 않는다.
- 입력 원본 파일은 보존한다. 공식 원본과 변환 자료의 해시를 같은 것으로 취급하지 않는다. 공급기관 출처 URL은 참조용이며 서버가 그 URL에 접속해 진위를 확인하지 않는다.

## 저장과 재사용

별도 `${DATA_DIR}/regional_catchment/` 아래에 저장하므로 기존 업체·관광·수집 원본 저장 형식은 바꾸지 않는다.

| 파일 | 역할 |
| --- | --- |
| `datasets/{fingerprint}.json` | 정규화 격자, 불변 저장 |
| `results/{resultId}.json` | 반경 산출값과 방법·출처·품질, 불변 저장 |
| `state.json` | 반입 메타데이터, 지역 중심점/자료 선택, 결과 포인터와 작업 상태 |

저장키는 계산 버전·중심점·통계/경계연도·해상도·산업분류·자료 내용 및 출처 해시를 구분한다. 같은 입력이면 결과 ID와 계산시각을 유지한다. 새 중심점/새 자료 버전에는 새 결과를 만들고, 늦게 끝난 이전 중심점 작업은 현재 지역에 게시하지 않는다. 실패한 새 계산은 이전 불변 결과를 삭제하지 않는다.

GET은 저장된 작은 결과만 읽고 원본 전체 검사·외부 API·새 계산을 시작하지 않는다. 원본 격자가 없어도 이미 저장한 결과를 조회할 수 있다. 계산은 관리자가 명시적으로 요청하며 같은 조건의 중복 요청은 작업 하나를 공유한다. 계산 대기열은 한 번에 하나를 처리하고 격자 스캔 중 이벤트 루프를 양보한다. 이 제한은 신규 반경 계산에 적용하며 기존 앱 전체의 모든 무거운 작업을 직렬화한다는 뜻은 아니다.

재시작 시 기존 결과는 그대로 재사용한다. 중단된 계산은 자동 재실행하지 않고 중단 상태를 안내한다. 관리자 명시 요청으로 재시도할 수 있다. 화면은 계정·지역별 저장 결과를 먼저 표시하고 서버 결과를 확인한다. 다른 지역의 늦은 응답, 입력 중 기준점, 열린 상세 영역을 보호한다.

## 관리자 API

저장 결과에는 포인터·판본별 내용 SHA를 기록한다. 조회 시 SHA와 구간·지표·단위·결측 상태·합계 관계를 검사하므로 손상된 결과를 정상 수치로 노출하지 않는다. 현재 결과가 손상되면 같은 중심점·자료에 속한 검증된 이전 판본만 경고와 함께 재사용한다. 원본의 진위를 독립 인증하는 기능과는 다르다.

| 경로 | 동작 |
| --- | --- |
| `GET /api/regional-catchment?regionKey=…` | 저장 설정·결과·작업 상태만 조회 |
| `POST /api/regional-catchment/datasets` | 정규화 JSON 반입. 동일 ID의 다른 자료는409 |
| `POST /api/regional-catchment/configure` | 지역·확인한 중심점·자료 ID 저장 |
| `POST /api/regional-catchment/refresh` | 저장 자료 계산 요청 또는 동일 결과 재사용 |

관리자 세션·동일 출처·JSON·쓰기 횟수 제한을 적용한다. 반입은 최대50,000셀·8MiB다. 다른 API의 기존1MiB 본문 제한은 확대하지 않는다. 전국 고해상도 자료는 이 경로에 그대로 넣지 않는다. 큰 자료를 지원하려면 별도 스트리밍 색인/영속 작업 구조를 먼저 확장해야 한다.

`unqueried`는 기준점 미설정, `missing`은 설정 후 산출 자료 미확보, `partial`은 일부자료, `stale`은 이전 결과 유지, `failed`는 실패다. 저장소/응답 오류를 자료 없음으로 바꾸지 않는다. `networkAttempted:false`를 통해 조회·계산에서 공급자 호출이 없음을 기록한다.

## 검수와 남은 작업

2026-10-21 로컬 검수: 최초 신규 시험68/68에 이어 CP949·부분 반입 보완 후 관련 시험 **75/75**, 기존 지역분석 회귀 **26/26** 통과. 전체 앱의 모의 격자 시험에서 서버 재시작 후 결과 ID·계산시각이 유지됐고, GET 파일 변경0·외부 요청0을 확인했다. 인코딩 메타데이터 보완 후 저장 GET5회는 **14.0~16.1ms**, 앞선 로컬 모의 산청 카드의 앱 표시 계측은 **108.8ms**였다. 두 애니메이션 프레임 뒤 카드 표시를 앱이 기록한 시간이며 운영 실제자료 성능이 아니다.

라이트·다크 실제 브라우저 화면에서 공개 부분합과 전체값 미확정, 통계연도·산업분류·출처를 확인했다. 같은 지역의 재표시 후 편집 중 기준점과 커서1번 위치가 유지됐다. 미설정 천안은9개 지표 모두 빈 값이며0으로 표시되지 않았다. 모바일 레이아웃은 CSS로 대응했으며 이번 브라우저 실물 검수는 PC에 한정한다. 증빙은 `C:/Users/User/.codex/visualizations/2026/10/21/regional-catchment-development/`의 `api-verification.json`, `ui-verification.json`, `light-synthetic-cards.png`, `dark-synthetic-cards.png`에 있다.

신규 단위시험은 경계 배정·결측·비밀보호·원본 보존·동시 요청·재시작 재사용·무결성·관리자 권한·반입 제한·늦은 응답·입력 유지와 CSV/도형 준비를 검증한다. 별도 전체 앱 시험 `scripts/test_regional_catchment_api.cjs`는 임시 데이터 폴더와 명확한 모의 격자로 실제 서버를 두 번 기동한다. 저장 GET의 파일 불변·외부 요청0·재시작 후 동일 결과를 확인한다.

로컬 속도와 모의 화면은 운영 실제자료 성능으로 해석하지 않는다. 실제 자료 반입 후 좌표변환 표본, 격자 키/항목/기준연도, 반경 범위와 보호값을 대조하고 저장 조회 및 화면의2초 목표를 측정해야 한다.

다음 순서: **승인된 통계·경계 다운로드와 확인한 기준점 확보 → 다중 원본 추적·공간범위 대조 → 반입·실제 수치 검수 → 운영 배포 요청 시 배포·실측 → 월간 행동 리포트 연결**. 코드집 확보·신청 승인은 통계값·경계 확보와 구분한다. 기존 `spatialCatchment:false` 기능 플래그는 실제 자료 확보/리포트 연결을 완료했다고 오인하지 않도록 아직 유지한다. Insight·수집/보호/예약 설정은 이 개발에서 변경하지 않는다.

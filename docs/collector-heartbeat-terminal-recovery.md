# BG 워커 통신 복구와 종료 확인

하트비트 통신이 한 번 끊겼다는 이유로 정상 실행을 즉시 실패 처리하거나, 서버에 종료가 저장됐지만 응답을 놓쳐 결과를 알 수 없게 되는 경우를 줄인다. 수집 요청 자체를 다시 실행하는 기능은 추가하지 않는다.

## 하트비트

- 일시적 통신 오류와 HTTP 408/429/5xx만 최초 요청을 포함해 최대 3회 시도한다. 남은 실행권 안전시간이 부족하면 일찍 중단한다.
- 안전시간은 정상 응답을 확인한 요청의 시작 시점을 기준으로 계산한다. 응답 대기·실패·재시도는 실행권 시간을 늘리지 않는다.
- 인증 오류, 실행권 거절, 취소, 잘못된 응답은 보호 중단한다. 409 이후 원장을 조회할 때도 수집기는 먼저 멈춘다.
- 공급자 차단의 즉시 보고와 수집 중단, 종료 신호 처리, 비밀정보를 제외한 로그를 유지한다.

## 서버 원장으로 종료 확인

`POST /api/collector-worker/jobs/:id/terminal-status`는 기존 bearer 인증과 본문의 `workerId`, `leaseToken`을 모두 확인한다. 별도 scheduled 워커 경로에도 같은 규칙을 적용한다.

조회는 초기화가 끝난 브로커의 디스크 원장 또는 보관 영수증을 읽는다. 실행권 만료 처리, 저장, 보호 해제, 새 작업 발급, 공급자 호출은 하지 않는다. 원장 64MiB·영수증 4MiB 읽기 상한을 두고 링크·중복 ID·잘못된 JSON은 확인 불가로 처리한다.

- `failed`는 실패가 저장되고 실행권이 해제됐음을 확인한다. 수집 실패는 그대로 유지하며 다음 작업으로 진행하지 않는다.
- `cancelled`도 실행권 해제와 유효한 종료 시각이 저장돼 있어야 종료 증거로 인정한다.
- `completed`는 정상 형태의 완료 manifest와 품질 기록이 있어야 한다. 워커가 제출한 같은 `runId`와 파일 경로·크기·SHA256 집합이 저장된 완료 키와 일치해야 응답 유실을 복구한다. 차단·실패 결과는 성공으로 바꾸지 않는다.
- `leased`, `queued`, `committing`, `interrupted`, 누락·불완전·인증 불일치는 정상 완료로 바꾸지 않는다. 확인되지 않으면 기존 보호 대기를 유지한다.

확인 API가 없는 이전 서버에서도 확인 불가는 보호 대기로 남는다. 기존 실패 작업을 다시 예약하거나 실행권을 발급하는 우회 경로는 없다.

## 격리 검증

`npm run test:collector-heartbeat-recovery`로 통신 복구 집중 검증을, `npm run test:collector-recovery`로 일정·회차 및 기존 복구 경계를 포함한 검증을 실행한다. 새 HTTP 시험은 실제 브로커와 워커를 loopback으로 연결하고 수집기 자식만 fixture로 대체한다. 외부 주소로의 요청을 거부하며 임시 디렉터리의 일정·원본·예약 이력·보호 설정 사본 바이트를 전후 비교한다.

이 시험은 응답 유실·중복 실행 방지의 검증이다. 운영 수집 실행, 운영 자료 전체 보존 감사, 월집계 성능·RSS·4GiB 한도 검증을 대신하지 않는다. 운영 배포와 기존 보호 해제는 수행하지 않는다.

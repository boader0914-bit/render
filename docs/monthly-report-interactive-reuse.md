# 월간 리포트 재사용 조회의 배경 작업 경합 개선

## 목적

저장 집계가 있는 월간 미리보기는 새 배경 원본 재구성과 경합하지 않도록 우선 처리한다. 원본 변경 검사는 매번 유지하며, 아직 계산되지 않았거나 원본이 바뀐 조건을 정상 재사용으로 표시하지 않는다.

## 처리 방식

- `monthlyReportService.preview()` 전체를 공용 원본 스케줄러의 `runInteractiveRead()`로 감싼다. 근거 읽기와 승인용 미리보기 보존까지 우선권을 유지하고 성공·실패 모두 해제한다.
- 새 배경 원본 읽기는 잠시 기다린다. 진행 중인 배경 읽기는 JSON 해석 전, 객실 기준 처리, 이력 256행, 업체 16곳, 저장 자료 재보정 경계에서 `checkpoint()`로 양보한다.
- 양보 중에도 원본 읽기의 기존 직렬 슬롯과 객실 기준 잠금을 유지한다. 원본 전체 읽기를 두 개 시작하거나 작업을 취소하지 않는다.
- 원본이 바뀌어 사용자 요청에 실제 재구성이 필요하면 대기 중인 배경 읽기를 재개한 뒤 사용자 읽기를 순차 처리한다. 자기 대기 교착을 피한다.
- 첫 사용자 우선권부터 최대 2.5초 뒤에는 배경 작업을 진행시킨다. 중첩 요청은 이 시간을 연장하지 않으며 기존 4:1 공정성을 보존한다. 이는 요청 취소 시간이나 절대 응답 보장 시간이 아니다.
- 업종 조건 목록을 만드는 원본 읽기도 배경 우선순위로 등록한다. 원본 전체를 반환받은 뒤의 동기 압축 단계에는 새 양보 지점을 넣지 않아 대용량 객체를 중복 보유하지 않도록 한다.

## 계측

기존 시간에 다음을 추가한다. 경로·계정·원문 내용은 계측에 포함하지 않는다.

- 원본 검사 대기 시간과 실제 검사 시간
- 검사 횟수와 파일·디렉토리·항목 수
- 미리보기 중 이벤트 루프의 실행·대기 시간과 최대 지연
- 승인용 미리보기 JSON 보존까지의 전체 시간

`generation.runtime.eventLoopMaxDelayMs=null`은 표본이 확보되지 않은 상태이며 지연 0이라는 뜻이 아니다.

## 검증과 한계

`scripts/test_interactive_report_reuse.cjs`는 실제 임시 저장파일과 정식 검사·집계 모듈을 사용해 재사용, 새 배경 작업 보류, 원본 변경 재계산을 검증한다. 모의 자료의 시간은 운영의 2초 달성을 증명하지 않는다.

운영 배포 후 같은 실제 업체군·숙박월·관측 마감일의 재사용 응답과 브라우저 표시 시간을 측정한다. 배포 직후 최초 계산은 재사용과 구분한다. 이미 실행 중인 단일 JSON 해석·객체 복사·동기 집계 구간은 중간에 중단하지 않는다. 이 구간의 지연이 남으면 추가 계측을 근거로 분리 범위를 결정한다.

# 워커별 독립 운영 (2026-10-10)

사용자 지시에 따라 2Gweb_worker(`web`), BG worker(`manual`), AWS worker(`scheduled`)의 실행 판단을 분리한다. 이전 문서의 전 워커 공통 차단 및 같은 키워드의 워커 간 자동 공유 정책을 대체한다.

## 실행과 보호

- 접근 제한을 감지한 워커만 보호 상태로 유지한다. 해당 워커의 대기 작업을 중단하고, 감지한 작업은 차단 결과를 보존할 수 있도록 종료·전송 절차를 마친다.
- HTTP 403/429, HTTP 200의 공급자 오류 및 CAPTCHA 감지, 신규 요청 중단, 결과 검증은 유지한다.
- 다른 워커의 실행·대기·예약·보호 상태를 변경하지 않는다. 실패한 작업을 다른 워커로 자동 이동하거나 재시도하지 않는다.
- 보호 해제 API는 지정한 워커만 검사하고 해제한다. 다른 워커의 보호를 함께 해제하지 않는다. 오늘 유지하기로 한 BG의 `reviewHold`는 보존한다.
- 날짜 변경이나 배포로 보호를 자동 해제하지 않는다.

관리자 API `POST /api/collector-review-hold`는 `{confirm:"hold-after-review",heldWorkerKey:"manual",holdThrough:"YYYY-MM-DD"}`로 선택 워커만 오늘 보류한다. `POST /api/collector-reset-halt`는 기존 `confirm:"resume-after-review"` 및 `workerKey`로 해당 워커만 해제한다. 인증·동일 출처·JSON 검증을 유지한다. 구형 다중 해제 `/api/collector-review-release`는 410으로 종료하여 실수로 다른 워커의 보호까지 변경하지 않는다.

## 당일 재수집

- 한국시간 날짜, 키워드, 워커를 기준으로 진행 공유·완료 결과 재사용·미완료 검토를 판단한다.
- 같은 워커에서 같은 범위의 진행 작업은 함께 기다리고, 검증된 완료 결과를 재사용한다. 같은 워커의 실패·부분·차단 이력은 검토 대상이다.
- 다른 워커의 결과 때문에 실행을 보류하거나 해당 결과를 자동으로 재사용하지 않는다. 워커를 특정할 수 없는 오래된 자료는 다른 워커를 차단하는 근거로 사용하지 않는다.
- `COLLECTION_REVIEW_REQUIRED`는 공급자 차단이 아니라 실제 수집 전의 재수집 검토 요청이다. 화면에 미실행 상태를 구별한다.

## 저장과 적용

결과는 기존 중앙 서버의 보관함으로 모으고 워커·작업·관측 시각을 유지한다. 동일 업체의 매출을 단순 합산하지 않으며 기존 결과 검증과 공통 저장 잠금은 유지한다. 디스크 부족·자료 복구 중의 저장 보호도 유지한다.

중앙 웹의 배정·상태·중복 판정 및 화면 변경이므로 중앙 웹만 배포한다. 원격 워커의 수집 엔진·속도·토큰·일정은 변경하지 않는다. 배포 검수에서 수집 API를 실행하거나 기존 작업을 재수집하지 않는다.

검증은 외부 통신과 실제 크롤러를 금지한 모의 통합 테스트로 진행한다. 서로 다른 워커의 같은 키워드 실행, 같은 워커의 중복 방지, 차단 전파 방지, 선택 보호 해제, 차단 결과 보존과 정상 자료 반영 제한을 확인한다. 이 검증은 네이버의 실제 접근 허용 여부를 입증하지 않는다.

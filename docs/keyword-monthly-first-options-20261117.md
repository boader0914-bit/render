# 키워드 월별 첫 목록 조회 개선

## 확인한 지연

운영 커밋 `30dd217a3d60a49b6edd79123c261ddd721b5abb`의 첫 목록 요청에서 HTTP 전체 7,333.742ms, 서버 `read` 7,184ms가 관측됐다. 같은 trace `f44cf83706aa1f1a7d28c113`의 작업 기록은 대기 43ms, 실제 작업 7,134ms다. 입장 대기나 응답 직렬화가 주된 원인은 아니다. 파일 I/O와 JSON 파싱의 세부 비중까지 분리한 계측은 없다.

목록은 공개 준비본의 pointer와 catalog를 읽은 뒤 모든 partition의 index를 검증하고, 반환 전에 같은 index와 pointer를 다시 검증한다. 기존 두 index 검증 단계가 모두 순차 실행됐다.

## 수정 범위

- 목록의 두 index 검증 단계에만 최대 4개의 제한된 동시 파일 읽기를 적용한다. 내부 설정은 정수 1~8만 허용한다.
- 각 batch의 시작된 작업이 모두 끝난 뒤 descriptor 순서대로 결과를 반영한다. 첫 오류 뒤에도 이미 시작한 읽기를 정리하고 다음 batch는 시작하지 않는다.
- 파일 크기·경로·심볼릭 링크·링크 수·읽기 전후 상태·SHA·최종 pointer 검증을 유지한다. 금융 자료 조회와 재계산의 읽기 순서는 변경하지 않는다.
- 기존 메타데이터 캐시의 8MiB/64개 한도, 메모리 입장 보호와 계산 버전을 유지한다. 최대 동시 인코딩 버퍼 한도는 총 JS 메모리나 RSS 상한을 뜻하지 않는다.
- 닫힌 ‘업체 선택 · 전체 평균 비교’의 중복 모델 계산과 표 구성만 첫 펼침으로 늦춘다. 기본 대시보드·지표·그래프는 즉시 구성한다. 조건 변경, 로그아웃, 숨김 복귀 후 오래된 화면에 작업하지 않도록 현재 자료와 화면 수명을 확인한다.

수집 요청 속도·워커·예약·원본·발행본·계산식은 변경하지 않는다.

## 검증 및 운영 적용 기준

로컬 회귀 검증 238개를 통과했다. 동시 읽기 1/4/8의 결과·순서 동일성, 부분 실패, 최종 오류의 sibling 정리, index 변조·pointer 변경, 저장 자료 조회와 금융 경로 격리, 화면 조건 복원과 숨김 복귀를 포함한다. 기존 경로 보호 검증과 새 동시성 검증의 범위는 구분한다.

운영 파일 대조는 수집·DB 반영·키워드 집계의 중요 작업이 없고 실제 메모리 여유가 확보된 창에서만 한다. 같은 pointer·catalog·모든 index·고정 시각으로 독립된 reader를 비교한다. 공개 메타데이터만 읽고 원본·금융 projection 본문이나 공급자는 호출하지 않는다. 이 대조는 OS의 물리적 cold나 운영 HTTP 입장 보호, UI 2초 목표를 입증하지 않는다.

배포 후에는 원본·발행본·보호 상태·중지된 인사이트 정기수집을 배포 전후로 비교한다. 일반 수집 회차가 추가한 자료와 배포로 인한 변경을 구분한다. 진행 중인 정상 수집이나 집계를 끊어 배포하지 않는다.

## 실제 화면 시간의 판정

새로고침의 새 문서에서 실제 지표 표시와 독립된 표시 후 버전 조회 완료를 각각 측정한다. 같은 조건, 응답의 pointer·입력 지문·지표, 화면 마커와 직접 검토한 프레임을 연결한다. HTML·API 응답 시간이나 두 번의 animation frame만으로 실제 화면 표시를 대신하지 않는다. 실패·측정 미확인 자료도 보존한다.

저장된 준비 결과의 최신 발행 버전 확인과 원본 자료의 재검증·집계 완료는 별개다. 후자가 진행 중이거나 실패했다면 상태와 한계를 함께 표시하고, 단순한 version 일치를 원본 최신성 완료라고 보고하지 않는다. 첫 조회와 같은 로그인 상태의 재조회, OS cache cold 여부도 구분한다.

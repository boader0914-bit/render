# 고객 리포트 목록 검증 비용 개선

기준 `4d1273c`의 실자료 사본 검수에서는 목록을 40번 읽을 때 배정된 발행본 전체를 매번 JSON으로 해석하고 스냅샷을 다시 문자열화했다. 재시작 후 목록에는 40개 발행본이 있어 총 1,600회의 큰 본문 검증이 발생했다. 이번 변경은 그 반복 해석을 줄이며 운영 수집·분석 수식·발행본·고객 배정 기록 형식을 바꾸지 않는다.

## 변경한 경로

- `monthly_reports.getPublishedListSummary`는 목록 전용 내부 읽기다. 실제 파일의 **전체 바이트 SHA256을 매 요청 다시 계산**한다. mtime이나 TTL만으로 내용을 신뢰하지 않는다.
- 처음 확인하거나 내용 SHA가 바뀌면 기존 보고서 파싱·스냅샷 해시·발행 상태·실행 계획 근거를 모두 확인한다. 확인한 raw SHA와 작은 허용 필드 요약만 프로세스 LRU에 보관한다.
- 목록은 현재 배정 원장의 snapshotHash·전체 발행 metadata binding·버전을 다시 대조한다. 고객별 배정 시각은 현재 원장에서 합치며, 세션·활성 계정은 응답 전후 확인한다. 고객 권한 결과를 캐시하지 않는다.
- 상세 및 PDF는 기존 전체 발행본 읽기와 인증 재검증을 유지한다. 발행본이나 원본 분석 자료를 소급 수정하지 않는다.

## 한도와 실패 처리

- 프로세스 캐시는 최대 128개 / 직렬화된 요약 합계 2MiB다. 전체 스냅샷·원문·PDF는 캐시에 보관하지 않는다. 반환값은 별도 객체다. 이 한도는 JS heap/RSS 전체 상한을 뜻하지 않는다.
- 파일 스트리밍 버퍼는 첫 읽기에만 생성하며 128KiB 하나를 직렬 공유한다. 동시 요청이 같은 버퍼를 덮어쓰지 않는다.
- 이 목록 경로의 단일 저장 보고서 상한은 128MiB다. 초과·빈 파일·링크·파일 교체·읽는 중 변경은 오류이며 빈 목록/정상 0으로 바꾸지 않는다. 기존 상세/PDF 경로에 이 크기 제한을 추가하지 않는다.
- 저장소 realpath, `O_NOFOLLOW`, 열린 파일과 경로의 dev/ino/nlink/size/mtimeNs/ctimeNs를 읽기 전후 확인한다. symlink·hardlink와 읽기 경계의 교체를 거부한다. 전체 내용 SHA가 캐시 hit의 필수 조건이므로 mtime 복원이나 다른 프로세스의 재저장도 내용이 다르면 무효화한다.
- 목록 페이지 분할, 자동 배정·발행, 정규 수집, 보호 해제, 운영 기능 플래그 활성화는 이번 변경에 포함하지 않는다.

## 검증 범위

임시 파일 시험에서 내용 변조·복원된 mtime·다른 프로세스 쓰기·삭제·링크·읽기 도중 교체·인증 철회·LRU 한도와 반환값 독립성을 확인한다. 기존 HTTP/BFF·월간 리포트·PDF 회귀를 함께 확인한다.

별도 새 실자료 회차는 **기준도 기존 전달 기능을 포함한 `4d1273c`**로 고정한다. 기준·후보가 같은 40조건의 발행·배정·고객 목록/상세/PDF 작업을 수행하며 최초와 재시작을 구분한다. 전체 스냅샷·실행 계획·근거·배후시장·고객 요약의 결과 일치, 업무시간·커널 최대 RSS·실제 4GiB cgroup peak/events를 비교한다. 캐시·OS 파일 캐시·측정 경계의 한계를 별도 보고한다.

저장 배후시장 실수치가 없는 원사본은 missing으로 유지한다. 이번 변경과 합성 자료 통과만으로 운영 성능·전체 재집계·배후시장 수치·실제 고객 UI가 검증됐다고 표현하지 않는다. 실자료 측정과 격리 화면 검수 결과는 별도 영수증에 기록하며 통과 전 운영 반영을 하지 않는다.

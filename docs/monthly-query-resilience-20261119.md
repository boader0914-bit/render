# 저장 목록과 월별 조회의 실행 경합 보완

2026-11-19 운영 검수의 두 오류를 구분한다. 10:44:46의 금융 자료 조회는
`KEYWORD_MONTHLY_ANALYTICAL_BUSY`로 8ms 안에 거절됐다. 같은 시간의
`source-options`는 31.187초였고 월 목록 조회 단계는 23.291초였다. 당시
상세 readGuard를 확보하지 못했으므로 정확한 실행 소유자 분기를 단정하지
않는다. 10:48:43의 catalogue 조회는 서버 상태 조회의 5초 제한을 넘어
5.237초에 종료됐다. 파일 I/O와 보호 확인의 내부 지연은 별도 계측한다.

## 수정 범위

* 업종 화면의 일반 진입과 복귀는 저장된 조건 목록과 집계를 읽는다.
  조회만으로 원본 목록 재구성이나 새 업종 집계를 시작하지 않는다.
  저장 자료가 없는 경우 준비 필요를 표시하고 명시적 준비 동작으로 연결한다.
  이전 관측 마감일의 같은 업종·월·지역 저장본을 표시하면 실제 마감일과
  요청 마감일, 최신 확인 전 상태를 구분한다.
* 역사 인덱스의 정확한 월 목록은 원본 식별값·인덱스 식별값·동일 SQL에
  연결된 작은 파생 캐시로 재사용한다. 시작 시 인덱스 무결성 검사와 조회
  전후 원본·인덱스 검사를 유지한다. 값이 없거나 손상되면 기존 읽기 전용
  Worker와 동일 SQL을 사용한다. 격리된 원본 복사본의 주입 경로는 유지한다.
* catalogue의 파일 경로 검사는 같은 전후 검증을 제한된 병렬 I/O로 수행한다.
  파일 열기·식별값·해시·하드링크·상위 디렉터리 검사를 생략하지 않는다.
* 서버는 목록 조회의 보호 확인·메모리 입장·파일 열기·재검증과 실제 작업
  종료를 분리 기록한다. HTTP 시간초과 뒤 남은 작업도 같은 진단 번호로
  추적하고 상태용 조회 수명과 금융용 조회 수명을 구분한다. 민감한 요청
  본문이나 계정·키워드·쿠키·파일 경로는 진단에 남기지 않는다.
* 브라우저 임시 저장이 불가능하면 범위·크기·해시 계산·저장소 등 고정된
  실패 사유 코드를 표시한다. 크기·기간·동일 세션·민감 필드 제한은 유지한다.

## 유지 및 운영 검수

원본 관측과 기존 발행본, 계산 기준 7개 파일, 수집·예약·속도 설정, 보호
임계값과 실행 허가 정책은 변경하지 않는다. 인사이트 정기수집은 중지 상태로
유지한다. 검수를 위한 외부 수집·재수집·강제 재계산·보호 해제는 하지 않는다.

관련 회귀 검증과 독립 검토 후 같은 커밋을 운영 배포한다. 운영 코드 지문,
설정·보호·원본 메타데이터·발행본 및 중지 상태를 전후 비교한다. 첫 목록
응답, 새 문서의 실제 핵심 지표 표시, 표시 뒤 최신 저장본 확인을 따로
기록한다. 정상 조회와 월·상품 전환, 다시 불러오기에서 발생한 오류도
보존한다. 준비 완료와 실제 화면 프레임, 최신 저장본 확인을 혼동하지 않는다.
2초 초과 또는 503이 남으면 전체 통과로 보고하지 않는다.

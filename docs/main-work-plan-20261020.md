## 운영 적용: 예약 배정표의 DB 반영 표시

수집 완료와 업체 DB 반영은 별도 상태다. 보관함과 수집 실행의 수집 기록에는 DB 반영 표시가 있지만, 공동 순환예약 배정표에서는 누락돼 있었다. 또한 `upcomingItems`만 우선 표시하면 이미 완료된 오늘 배정이 숨겨져 상태를 확인하기 어렵다.

표시 개선 범위:

- 오늘의 실제 배정과 향후 배정을 함께 표시하고 같은 slot ID는 오늘의 실제 상태를 우선한다.
- `업체 DB 반영 대기 / 중 / 완료 / 실패 / 상태 확인 필요`를 수집 상태 아래에 별도로 표시한다.
- 실패해도 검증된 수집 완료·보관 결과는 유지한다. 후처리 기록 없는 과거 회차를 임의로 완료 처리하지 않는다.
- 편집안 미리보기는 저장된 실제 배정과 섞지 않는다. 초안·선택값·조회 주기·API 호출 수·예약 조건을 유지한다.
- 실제 수집·보호 해제·예약 변경·데이터 수정 없이 로컬 UI 회귀를 검증한다.

이 변경은 `caa616a`에서 로컬 개발·검수한 뒤 `0ebdaa3` 운영 배포에 포함했다. 기존 10/21 실예약 검수를 새 수집으로 대체하지 않으며 실제 완료 반영·DB 후처리 시간은 예정된 검수에서 확인한다.

로컬 검수 완료: UI·예약 스케줄러·수집 완료 경계 54개 통과, 문법/공백 검사 통과, 라이트·다크 합성 화면 확인. 실제 운영 수집·예약·보호·원본·객실 기준은 변경하지 않았다.

## 완료: 지역 카드 운영 적용·실측

기존 지역 현황 기본 카드가 미조회 프로필을 `관측 없음·0/12`로 표시하던 결함은 공통 저장 결과 연결로 로컬 수정했다. 미조회 확보월수는 `null`, 정상 조회 뒤 snapshot이 없는 경우는 `0/13`과 수치 `null`로 구별한다. 지표별 최신 정상월·실제 수치·원본 근거 상태를 유지하고, 같은 조건의 동시 GET을 공유한다. 화면 재진입 순번을 분리해 이전 측정값·늦은 응답이 현재 카드에 적용되지 않게 했다.

로컬 전체 앱의 실제 저장 응답 검수에서 저장 GET 표시 367.2/383.7/1,262.0/1,269.8ms, 캐시 표시 38.4/60.5ms였다. 라이트 71개·다크 25개 표면 대비의 최저값은 4.73이고, 원자료 SHA가 유지됐다. 공급자 원본을 다시 검증하거나 운영 네트워크 성능을 측정한 작업은 아니다. [상세 결과와 한계](regional-shared-card-results-20261020.md).

`0ebdaa3`의 Render Live·health와 실제 인증 화면에서 카드 27개·지역 흐름 27개의 수치·월·결과 ID, 미조회/미확보 구별, 앱 표시 557~604ms를 확인했다. 현재 live GET의 snapshot SHA가 이전 실제 보관 본문과 같음을 검증한 뒤 대조했으며 이전 raw 응답을 현재 raw 응답으로 취급하지 않았다. 원본·설정 359개 내용 해시와 결과 5,407개 메타정보·예약 정의·보호·저장 snapshot이 유지됐다. 결과 내용 전체의 독립 해시 검수는 아니다. [운영 검수와 한계](regional-card-release-0ebdaa3-20261020.md).

## 공통 검수 기준

- 정상 0, 미확인, 오류, 차단, 부분 자료를 구별한다. 미확인을 0으로 채우지 않는다.
- 관리자 DB 검수 객실 총량을 우선한다. 월명 16실 등 기존 검수값·원본을 이 계획 점검에서 바꾸지 않는다.
- 선택한 업체·월·관측 마감일과 통합카드 수치는 늦게 도착한 상세 자료가 덮어쓰지 않는다.
- 2초 목표는 **정상 저장 결과의 실제 표시**로 측정한다. API 시간·화면 표시·최초 계산·자료 확보 시간을 구분한다. 모든 화면이 달성했다고 일반화하지 않는다.
- 재사용 GET은 원본 전체검사·공급자 호출·DB 갱신을 새로 시작하지 않아야 한다. `/api/runs/:id` 등 오래된 상세 경로의 읽기 부작용은 별도 개선 후보이며 검수용 목록 읽기와 구분한다.
- 무거운 작업이 함께 있을 때 응답·메모리·이전 정상 결과 보존을 확인한다. 자료를 쌓기 위해 임의의 워커 동시 실행이나 보호 해제를 하지 않는다.
- 인사이트 개발·배포와 데이터랩 개발·배포는 구분한다. 회원 입력 실제 매출을 수집 원본에 자동 덮어쓰지 않는다.
- 지표/API 자동 갱신 기능의 존재와 실제 지역 정책의 활성화는 별개다. 추가 자료 수집·정책 변경은 해당 작업 범위를 정한 뒤 진행한다.
- SNS·서드파티 노출량과 업종별 검색어 확대는 출처·권한·동일 비교기준을 먼저 정하는 후속 설계 후보이며 현재 확보 지표로 보고하지 않는다.

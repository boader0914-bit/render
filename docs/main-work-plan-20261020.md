# 메인 개발계획·진행 현황 · 2026-10-20

## 기준과 목적

운영 확인 기준은 STAYDATALAB 웹의 `e3edf2f95d1f`다. 2026-10-20 20:07:58 KST에 Render Live를 확인했고, 이번 계획 점검에서도 공개 health의 같은 커밋을 확인했다. 중앙 웹의 배포 확인은 별도 인사이트 서버의 최신 버전·모든 기능 검수까지 의미하지 않는다.

메인 작업의 연결은 다음과 같다.

> 키워드 수집 원본 보존 → 업체별·숙박월별 통합 DB → 업종·지역 분석 → 이번 달 예상·다음 달 전망 → 관리자 검토·월간 발행 → 인사이트 고객 제공 → 행동과 실행 결과 확인

지역분석은 **기초·배후시장 / 월별 흐름 / 검색 관심 / 수요 전망**으로 구분한다. 연간 인구·산업을 월별 관광 흐름으로 해석하지 않는다. 지표의 최신 공식월·공통 비교기간·원본 근거·미확인 상태를 함께 보존한다.

이 문서의 `구현됨`은 코드에 기능이 있다는 뜻이다. 운영 실제 자료의 충분한 확보, 모든 화면의 2초 목표, 전망 정확도까지 일괄 완료로 판단하지 않는다. 과거 문서의 ‘배포 전’·‘다음 개발’ 문구도 후속 커밋과 함께 읽는다. 일정은 아래의 완료 조건으로 진행하며 근거 없는 완료율이나 확정 개발 일수를 사용하지 않는다.

## 이번 다음 작업: 예약 배정표의 DB 반영 표시

수집 완료와 업체 DB 반영은 별도 상태다. 보관함과 수집 실행의 수집 기록에는 DB 반영 표시가 있지만, 공동 순환예약 배정표에서는 누락돼 있었다. 또한 `upcomingItems`만 우선 표시하면 이미 완료된 오늘 배정이 숨겨져 상태를 확인하기 어렵다.

표시 개선 범위:

- 오늘의 실제 배정과 향후 배정을 함께 표시하고 같은 slot ID는 오늘의 실제 상태를 우선한다.
- `업체 DB 반영 대기 / 중 / 완료 / 실패 / 상태 확인 필요`를 수집 상태 아래에 별도로 표시한다.
- 실패해도 검증된 수집 완료·보관 결과는 유지한다. 후처리 기록 없는 과거 회차를 임의로 완료 처리하지 않는다.
- 편집안 미리보기는 저장된 실제 배정과 섞지 않는다. 초안·선택값·조회 주기·API 호출 수·예약 조건을 유지한다.
- 실제 수집·보호 해제·예약 변경·데이터 수정 없이 로컬 UI 회귀를 검증한다.

이 변경은 로컬 개발·검수 후 다음 배포 후보로 보관한다. 아래 `e3edf2f` 실예약 검수를 이유 없이 다른 배포로 교체하지 않는다. 운영 배포를 완료했다고 보고하려면 별도 Render Live·health·인증 화면 증거가 필요하다.

로컬 검수 완료: UI·예약 스케줄러·수집 완료 경계 54개 통과, 문법/공백 검사 통과, 라이트·다크 합성 화면 확인. 실제 운영 수집·예약·보호·원본·객실 기준은 변경하지 않았다.

## 공통 검수 기준

- 정상 0, 미확인, 오류, 차단, 부분 자료를 구별한다. 미확인을 0으로 채우지 않는다.
- 관리자 DB 검수 객실 총량을 우선한다. 월명 16실 등 기존 검수값·원본을 이 계획 점검에서 바꾸지 않는다.
- 선택한 업체·월·관측 마감일과 통합카드 수치는 늦게 도착한 상세 자료가 덮어쓰지 않는다.
- 2초 목표는 **정상 저장 결과의 실제 표시**로 측정한다. API 시간·화면 표시·최초 계산·자료 확보 시간을 구분한다. 모든 화면이 달성했다고 일반화하지 않는다.
- 재사용 GET은 원본 전체검사·공급자 호출·DB 갱신을 새로 시작하지 않아야 한다. `/api/runs/:id` 등 오래된 상세 경로의 읽기 부작용은 별도 개선 후보이며 검수용 목록 읽기와 구분한다.
- 무거운 작업이 함께 있을 때 응답·메모리·이전 정상 결과 보존을 확인한다. 자료를 쌓기 위해 임의의 워커 동시 실행이나 보호 해제를 하지 않는다.
- 인사이트 개발·배포와 데이터랩 개발·배포는 구분한다. 회원 입력 실제 매출을 수집 원본에 자동 덮어쓰지 않는다.
- 지표/API 자동 갱신 기능의 존재와 실제 지역 정책의 활성화는 별개다. 추가 자료 수집·정책 변경은 해당 작업 범위를 정한 뒤 진행한다.
- SNS·서드파티 노출량과 업종별 검색어 확대는 출처·권한·동일 비교기준을 먼저 정하는 후속 설계 후보이며 현재 확보 지표로 보고하지 않는다.

## 후속 실행 지침

> 이 문서를 현재 통합 기준으로 삼아 순서대로 진행한다. 기존 후속 점검 `automation-2`가 2026-10-21 두 예약의 완료·보관함·예약 이력·DB 후처리를 읽기 전용으로 검수하도록 유지한다. 정상 대기에는 반복 알림하지 않고 최종 결과와 처리 시간을 한 번 보고한 뒤 해당 점검만 중지한다. 10/20 순서 2의 실제 저장 자료 검토는 마쳤다. 다음에는 발견된 지역 현황 기본 카드의 공통 저장 결과 연결을 보완한 뒤 순서 3의 배후시장으로 진행한다. 자료 확보·원본 근거·동일 조건의 발행본 부재를 완료로 숨기지 않는다. 완료된 기능을 다시 만들거나 성능 개선만 무기한 반복하지 않는다. 각 작업 후 변경 내용·검증 범위·미확인 사항·운영 적용 여부·다음 작업을 보고한다. 수집/보호/일정/원본/인사이트는 승인한 범위 밖에서 변경하지 않는다.

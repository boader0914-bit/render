# 함덕펜션 보존 결과 복구

2026-09-28 운영 웹 요청 `07a7721f-71d9-4b7e-aa7f-d946db6199d1`은 지역값이 요청에서는 빈 문자열, 결과에서는 `함덕`으로 기록되어 `COLLECTOR_SCOPE_MISMATCH`로 실패했다. 수집을 반복하지 않고 보존 결과를 검증해 게시한다.

관리자 `POST /api/collector-web-recover`에 `confirm: recover-retained-web-result`, `requestId`, `retainedJobDirectory`, 원본 `manifestSha256`, 전체 `expected` 조건을 전달한다. 복구는 외부 호출이나 수집 자식 프로세스를 실행하지 않는다.

- 실패 요청 영수증과 중복 확인 장부의 원 수집 조건·시간을 대조한다.
- `web / manual / admin_search`, 일반 키워드 검색의 빈 지역값을 수집기가 키워드의 지역 부분으로 채운 경우만 허용한다. 날짜·순위·인원·데이유즈·수집 종류 등 다른 조건 불일치는 거절한다.
- 운영 웹의 기존 파일 경로·파일 목록·실행 식별자·접근 제한 보호·품질 검증을 그대로 통과해야 한다. 차단·부분 응답은 복구할 수 없다.
- 파일별 SHA-256과 원본 manifest를 별도 복구 영수증에 남기고 복사본만 게시한다. 원본·실패 장부·수집 시각은 보존한다.
- 게시한 manifest의 지역값만 원 요청의 빈 값으로 맞추며 기존 지역값과 변경 사유를 `recovery`에 남긴다. 원본 관측·가격·수량은 변경하지 않는다.
- 결과 보관함, 업체 DB, 누적 이력을 기존 서버 쓰기 경로로 반영한다. SQLite shadow 모드이면 동기화를 등록한다. 요청 카드는 `복구 완료`로 표시하며 원 오류와 종료 시각을 보존한다.
- 같은 복구를 반복하면 기존 게시 자료와 해시를 검증하고 이력은 중복 추가하지 않는다. 보호 해제나 수집 재실행은 하지 않는다.

검증: `node scripts/test_operating_web_recovery_integration.cjs`. 실제 HTTP 경계에서 외부 통신·자식 프로세스를 금지하고 보관함·업체 DB·누적 이력·요청 상태 복구와 반복 실행의 멱등성을 검사한다.

이 변경은 복구 경로만 추가한다. 일반 수집의 지역 판정 로직과 검증 기준은 바꾸지 않는다.

## 활성화와 자료 보존 확인

18:54:20 KST 확인에서 웹 수집기에 기존 `COLLECTOR_PROVIDER_BLOCKED` 보호가 남아 있었다. 공동 예약 활성화 API가 HTTP 409로 거부했으며 저장 상태는 `enabled=false`이다. 보호를 자동 해제하지 않았고, 이번 배포로 실제 수집을 실행하지 않았다. 조건 저장을 실행 예약 완료로 표현하면 안 된다.

같은 확인에서 모든 수집기의 실제 실행과 대기는 없었고, 원본 결과 폴더 수는 배포 전후 208개로 같았다. 사용 가능한 공간은 8,233,349,120바이트(약 7.67GiB)였다. 이는 당시 관측값이다. 보호 해제와 최종 활성화는 사용자의 후속 결정이 필요하다.

## 운영상 제한

원격 미인수 대기는 공동 예약에서 120초 이내로 제한한다. 실행 여부가 불명확한 상태는 자동 재시도·워커 교체·보호 해제를 하지 않는다. 재시작 당시 실행 중 영수증은 확인 필요로 보존하며, 이를 관리자가 원격 작업·보관함 결과와 대조해 해결하는 복구 UI는 별도 개선 대상이다.

## 후속 변경: 21일 조건과 명시적 중단 해제

같은 날짜 사용자가 조회기간을 21일로 변경하고 워커 수집중단 해제를 명시적으로 지시했다. 20:01 KST 사전 확인에서 웹만 `COLLECTOR_PROVIDER_BLOCKED`였으며 BG는 정상 대기 상태였다. 모든 수집기의 실제 실행과 대기는 없었다.

- 매일 한국시간 09:00 웹, 11:00 BG, 13:00 웹, 15:00 BG.
- 첫날 키워드는 경남·대구·부산·경북 글램핑 순서이며, 이후 13개 목록을 계속 순환한다.

# 키워드별 간격 예약

운영 예약은 기존 BG worker의 한 묶음을 유지하면서 `keywordIntervalMinutes`로 키워드 시작 간격을 지정한다. 기본값 0은 기존처럼 앞 작업 완료 후 다음 작업을 시작한다. 60은 키워드별 최소 한 시간 간격이다. 즉시수집에는 이 간격을 적용하지 않는다.

## 예정 시각과 실행

- 한국시간의 시작 날짜·시각에 키워드 순번 × 간격을 더해 예정 시각을 만든다.
- 앞 작업이 끝나지 않으면 다음 작업을 시작하지 않는다. 지연된 작업 뒤에도 최소 시작 간격을 유지하며 밀린 작업을 연달아 실행하지 않는다.
- 예약 일시정지·서버 종료·접근 제한·날짜 만료 시 남은 작업을 실행하지 않는다. 재시작 후 진행 여부가 불명확한 기존 예약은 자동 재수집하지 않는다.
- 기존 원본과 영수증은 보존한다. 상태 응답의 예정 시각과 실제 시작·종료 시각을 구분한다.
- HTTP 요청 속도, 상세 수집 범위, 차단 감지 및 결과 검증은 변경하지 않는다.

## 2026-10-10 요청 일정

기존 BG worker의 키워드 순서와 수집 조건을 유지한다. 시작 시각은 기존 예약의 11시를 기준으로 한다.

| 한국시간 | 키워드 |
|---|---|
| 11:00 | 경남글램핑 |
| 12:00 | 포천글램핑 |
| 13:00 | 가평글램핑 |
| 14:00 | 서울근교글램핑 |
| 15:00 | 경주글램핑 |
| 16:00 | 충남글램핑 |
| 17:00 | 전남글램핑 |

숙박만, 상세 1~20위, 관측일 포함 31일, 워커 기본 요청속도 조건이다. 설정 저장과 실행 가능 여부는 별도 검증한다. 기존 `COLLECTOR_PROVIDER_BLOCKED` 보호 상태를 예약 저장만으로 해제하지 않는다. 보호가 남아 있으면 실행 보류임을 명시한다. 이 문서 자체는 예약 등록 증거가 아니다.

# 수집 화면 전체 구성 개선

상태: 로컬 개발·검증. 운영 배포와 실제 운영 화면 검수는 별도이며 이 문서는 그 완료를 의미하지 않는다.

## 화면 순서

1. **수집 운영 / 바로가기**: 정기 수집 현황, 실행·예약 설정, 수집 기록, 결과 보관함으로 이동한다.
2. **정기 수집 현황**: 선택일의 배정과 합계를 먼저 확인한다. 수집·품질·동일 실행의 DB 반영을 각각 표시하고, 상세에서 시각과 연결 근거를 확인한다. 주간표와 주간 합계는 선택일 합계와 명확히 구분한다.
3. **실행·예약 설정**: 기존 공동 순환예약과 워커별 입력 폼을 유지한다. 바로가기는 스크롤·초점만 이동하며 폼을 다시 만들거나 입력을 초기화하지 않는다.
4. **수집 기록**: 기존 기간·키워드·상태 필터와 펼침 기능을 사용한다. 기록 바로가기는 접힌 기록만 펼친다.
5. **결과 보관함**: 기존 보관함 진입 경로를 이용한다. 기존 자동 목록 조회와 조회 조건·선택 결과 보존 계약을 변경하지 않는다.

## 상태 표시 원칙

- 계산 예정과 실제 저장 배정을 구분한다. 예상 6회만으로 실제 실행·완료를 표시하지 않는다.
- 정상 완료에는 기존 수집·품질·같은 run/slot의 DB 반영 연결 검증을 적용한다.
- 일반 응답 미확보는 원래의 부분·실패 상태를 유지하고, 저장된 판정이 확인될 때만 다음 배정 진행 허용을 보조 표시한다. 현재 예약 활성 상태와 구별한다.
- 캡차·호출 제한·저장 실패·실행 불명에 대한 기존 보호는 유지한다. 알 수 없는 값은 미확인으로 남긴다.
- DB 완료를 월별 집계 발행 완료로 바꾸어 표시하지 않는다. 현재 정기 현황 API에서 제공하지 않는 월별 연계 상태는 추정하지 않는다.

## 범위와 검증

생산 코드 변경은 화면 HTML/CSS/JS에 한정한다. 수집기·스케줄러·API·호출 한도·보호 설정·원본·이력과 KOSIS 보류는 변경하지 않는다. 외부 저장소는 별도 방향 문서만 준비한다.

기존 모니터·워커·보관함 UI 회귀 검증과 새 바로가기 동작 검증을 수행한다. 로컬 브라우저에서는 실제 UI 모듈에 모의 저장 응답을 제공하고 데스크톱 및 모바일 폭에서 상태·필터·상세·입력 보존·가로 넘침을 검증한다. 모의 화면은 운영 캡처와 구분하여 표시한다.

## 정기수집·직접수집 구분 및 운영 반영 준비

사용자 후속 승인에 따라 정기수집 설정과 직접수집의 제목·설명·바로가기를 분리했다. 화면 순서는 정기 현황 → 정기 설정 제목 → 공동 순환예약 → 직접수집 제목 → 워커별 폼 → 수집 기록이다. 기존 워커별 개별예약은 한 번·매일·평일 반복을 지원하므로 직접수집 전체를 고정적인 1회 실행으로 표시하지 않는다. 각 폼에는 선택한 실행 방식에 따라 ‘직접수집 · 지금 한 번’ 또는 ‘워커별 개별 예약수집’을 동적으로 표시한다.

실행 방식의 내부 값(now/schedule), 반복 값(once/daily/weekdays), 기존 입력·저장 payload와 활성화 경계는 유지했다. 관련 테스트 187개가 통과했고 PC·360/390/768px 모의자료 화면에서 순서·바로가기·표시 전환·기존 21일 선택·가로 넘침을 검증했다. 실제 운영 반영과 보존 상태·관리자 화면 검수는 `staydatalab-collection-workspace-release-20261114`의 별도 배포 근거에서 확인한다.

# 보관 원본의 지역 범위 검증 근거 연결

2026-10-17 개발·검수 기준. 배포 또는 운영 자료 재정리 완료 기록이 아니다.

## 목적과 적용 범위

보관된 공급자 응답에서 실제 지역 범위와 기간을 다시 검증해 저장 지표에 연결한다. 요청값이나 과거 매핑을 응답 증거로 바꾸지 않는다. 새 지역에도 같은 원장·공급자별 코드·행정구역 수준·출처·단위·주기 기준을 적용한다. 특정 지역명이나 코드에 따른 예외는 두지 않는다.

외부 API 조회나 네이버 숙박 수집은 이 작업에 포함되지 않는다. 기존 정상 관측값, 실제 0, 공백, 공표 대기, 오류, 비공개 상태를 보존한다. 원본 응답과 이미 생성한 결과·리포트 파일은 수정하지 않는다.

## 증거 연결 기준

| 검사 | 통과 조건 |
| --- | --- |
| 파일 | 허용된 자료 폴더 안의 지정 원본이고 크기·행 수가 제한 안에 있어야 한다. 경로 이탈, 심볼릭 링크 이탈, 손상·잘못된 JSON을 허용하지 않는다. |
| 식별 | 공급자, 원본 ID, 저장된 해시, 응답 방식·버전, 지표 또는 operation이 일치해야 한다. 해시는 기존 저장 방식과 같은 의미를 사용한다. |
| 지역 | 원장의 요청 식별자와 공급자 코드 체계를 분리한다. 실제 응답 코드·이름·행정구역 수준이 연결 지역에 맞아야 한다. 요청 region을 되돌려준 것만으로 통과하지 않는다. |
| 기간 | 검증한 월·연도·operation에만 근거를 붙인다. 최신월 증거를 이전 월 전체에 복사하지 않는다. |
| 관측 | 기존 파서로 원본을 정리한 값·단위·정상/누락 상태가 해당 저장 관측과 일치해야 한다. 충돌·중복·불완전 페이지·미확보 값을 정상 관측으로 승격하지 않는다. |

관광 방문자는 원본 날짜·지역·방문자 분류와 월간 계산 결과를 함께 확인한다. 체류·소비와 관광자원·다양성 지수는 operation별 근거를 구분한다. 전체 응답에 여러 지역이 포함된 정상 원본은 대상 지역을 정확히 추출한 뒤 검사하며, 다른 지역 행이 있다는 이유만으로 대상 값까지 부정하거나 다른 지역의 값을 대신 사용하지 않는다.

KOSIS는 표별 보관 메타데이터의 지역명·상위 지역 관계와 실제 응답의 C1, 표·항목·분류·기간·단위를 함께 검사한다. 정리된 cache.rows에서 C1을 재생성하는 것은 원본 검증이 아니다. 필요한 메타데이터 또는 실제 응답이 보관되지 않은 과거 자료는 범위 미확인으로 남긴다. 정식 원장 식별자로 연결되는 기존 별칭은 허용하되, 같은 이름의 다른 시·도는 허용하지 않는다.

## 저장과 조회

검사는 명시적 저장 자료 재정리 또는 기존 배경 계산에서 수행한다. 지역 흐름·지역 비교의 일반 조회는 저장 결과를 재사용하며 큰 원본 전체 검사, 공급자 호출, 자동 재수집을 시작하지 않는다.

검증 근거에는 검사 방식 버전, 공급자, 대상 기간·지표, 원본 ID·해시, 실제 코드, 검증 시각 등 추적 가능한 안전한 필드를 연결한다. 인증키, 원본 URL의 비밀값, 임의 로컬 경로를 화면·오류·리포트에 내보내지 않는다. 동일 원본의 중복 검사는 제한된 작업 내에서 공유하고 원본의 변경 시 재검증한다. 검증 시각만 바뀐 경우 새 결과를 무한 생성하지 않는다.

증거가 추가되면 기존 값이 같아도 결과의 입력 지문에 의미 있는 변경으로 반영되어 새 결과를 저장한다. 이전 결과는 그대로 보관한다. 실패한 검사는 이전 정상값을 삭제하거나 0으로 바꾸지 않으며, 검증 실패 사유와 범위 미확인 상태를 구분해 남긴다. 원본이 다른 지역임이 확인된 경우는 일반 관측·전망 입력에 사용하지 않고 기존 공통 계약의 참고값 처리 규칙을 적용한다.

## 비교와 화면

지역 비교는 지표별 같은 출처·단위·주기·행정구역 수준의 정상값을 대상으로 기간별 근거를 검사한다. 모든 선택 지역에서 검증된 최신 공통월 또는 공통연도만 직접 비교한다. 최신월에 증거가 없으면 더 이전의 검증된 공통월을 선택하고 제외된 최신월을 알린다. 비교할 월이 없으면 참고값과 기준기간·제한 사유를 유지한다.

독립적으로 정규화된 검색 관심도는 이 작업으로 지역 간 절대 비교 가능 상태가 되지 않는다. 연간 통계를 월별로 나누거나 반복하지 않는다.

## 완료 기준

1. 격리된 보관 원본으로 방문자 지표의 검증 성공·실패를 외부 통신 없이 재현하고, 원본이 없는 관광지수·KOSIS는 미확인으로 유지함을 검사한다.
2. 원본이 없거나 손상됐거나 해시·지역·기간·operation·값이 다르면 정상값과 공백을 보존하고 직접 비교를 허용하지 않는다.
3. 여러 지역·월 중 일부만 검증된 사례에서 기간별 근거가 전파되지 않고, 실제 0은 검증된 정상 관측으로 남는다.
4. 새 지역 fixture에서도 같은 기준이 작동하며, 동명이인 지역과 시·도/시·군·구 혼합·하위 구 임의 합산을 차단한다.
5. 명시적 재정리로만 새 결과가 생기고 과거 결과·원본은 바뀌지 않는다. 증거 추가는 새 결과를 만들고 같은 증거의 재검사는 동일 결과를 재사용한다.
6. 실제 지역 자료의 재정리 전후 정상 관측 수·금액·수량·기간과 파일 보존을 대조하고, 확대된 비교 지표·공통월·남은 제한을 따로 기록한다.
7. 일반 재사용 조회는 원본 검사나 공급자 요청 없이 동작한다. 운영 배포 후 실제 표시 시간을 별도로 측정해 2초 목표를 평가한다.

## 이번 구현의 범위

- 방문자 일평균·월간 누계 2개 지표에 대해 원본이 남아 있는 월부터 비교 근거를 복원한다. 원본의 동일 중복 행은 한 번만 계산하고 충돌 중복·누락 날짜·잘못된 값은 통과시키지 않는다.
- 체류·소비, 관광자원 수요, 관광 다양성의 기존 저장본은 정리된 값만 가지고 있어 `TOURISM_ORIGINAL_RESPONSE_NOT_STORED`로 남긴다. KOSIS 기존 자료는 실제 getMeta/getList 원본을 보관하지 않아 `RAW_RESPONSE_NOT_RETAINED`로 남긴다. 저장값과 정상 0은 유지한다.
- 결과 정리용 `buildSnapshot`은 기본적으로 `restoreStoredEvidence:true`를 관광 이력 조회와 KOSIS 조회에 전달한다. 점검 도구는 이를 false로 끌 수 있다. 일반 관리자 GET은 이 함수를 호출하지 않는다.
- 기존 지역 DB의 **저장자료 정리** 또는 관리자 `POST /api/regional-analysis/refresh`의 `collectMissing:false`로 새 파생 결과를 만든다. 이 POST는 관리자 인증·동일 출처·JSON 및 기존 대기열 조건을 따른다. 서버 배포만으로 기존 결과를 덮어쓰거나 일괄 재정리하지 않는다.
- 기간별 `spatialContract.storedProvenance`에 원본 번호·해시·검사 버전·해당 월·검사 항목·검증 시각을 남긴다. 경로·URL·비밀값은 저장 결과의 공개 근거에서 제외한다. `storedEvidenceVerification`은 복원·기존 검증·근거 부족·검증 실패를 구별한다.
- 지역 현황과 지역 비교의 기존 **공통 기준** 펼침 영역에 보관 원본 재검증과 근거 부족 사유를 표시한다. 표시할 공통월의 근거를 사용하며, 최신월 근거로 대체하지 않는다.

## 실행과 후속 검수

`npm run test:regional-stored-evidence`로 원본 검증, KOSIS 미복원, 결과 저장·재사용·비교·화면 연결을 검사한다. `test:regional-common-criteria`에도 새 테스트를 포함한다.

운영 배포 이후 저장 자료만 재정리하고, 원본·기존 결과 해시와 값·기간을 대조한다. 실제 확대된 비교 지표 수와 공통월을 확인하고 조회 화면의 2초 목표를 다시 측정한다. KOSIS와 관광지수의 향후 실제 응답 원본 보관은 별도 후속 개발이며 이번 변경으로 새 외부 API를 호출하거나 그 원본을 생성하지 않는다.

### 2026-10-17 로컬 검증 기록

- 공통 기준·원본 검증·KOSIS·저장·비교·화면·HTTP 테스트 186개 통과.
- 전망·전망 검증·자료 준비·저장 결과 UI·지표 관리 테스트 94개 통과. 두 묶음 합계 280개이며 재실행 횟수를 더하지 않았다.
- 실제 앱 서버를 격리된 자료와 가상 제공처로 실행한 regional-analysis API 및 saved-reuse API 검증 통과. 외부 fetch 금지, 원본·이전 결과·예약 설정 보존과 일반 조회의 재계산 없음 확인. 이 결과는 운영 속도나 실제 지역 전체의 원본 복원 완료를 뜻하지 않는다.
- 첫 앱 API 검사에서 전망 발행 뒤 평가 작업을 기다리는 기존 조건이 한 차례 시간 초과했고, 동일 검사를 재실행해 통과했다. 대기 조건은 완화하지 않았으며 이번 변경에서 발행·평가 작업 순서를 수정하지 않았다. 운영 배포 검수에서는 동시 발행 후 평가 완료도 별도로 확인한다.
- 마지막 요약 보완 후 저장·원본 근거 통합 테스트 25개를 재실행해 통과했다. `git diff --check` 정상.
- 운영 배포·운영 자료 재정리·신규 공급자 수집은 이 개발 검증에서 실행하지 않았다.

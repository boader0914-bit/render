# 워커별 수집 카드

2026-09-24 개발. 운영 배포 및 실제 네이버 수집은 이 개발 검수에 포함하지 않는다.

## 표시와 역할

| 내부 키 | 새 화면 이름 | 기존 실행 서비스 | 결과 도착지 |
| --- | --- | --- | --- |
| web | 2Gweb_worker | 운영 웹 서버의 명시적 직접 실행 | 2G 운영 서버 |
| manual | BG worker | 기존 0922 Background Worker | 2G 운영 서버 |
| scheduled | AWS worker | 기존 0923 수집 서비스 | 2G 운영 서버 |

AWS worker는 사용자가 지정한 표시명이다. 이 변경은 AWS 인프라 이전이나 Render 서비스명 변경을 수행하지 않는다. 내부 키와 과거 실행 기록은 유지한다.

각 워커는 독립적인 접이식 카드, 입력 초안, 실행 상태를 갖는다. 데스크톱은 3열이며 좁은 화면은 순서대로 쌓인다. 입력 조건은 키워드(여러 개는 한 줄씩), 조회할 숙박일(당일/7/14/31일/직접 지정), 순위, 기본·상세수집, 데이유즈, 즉시·예약이다. 인원·속도 조절은 노출하지 않는다. 기존 워커의 기본 속도와 접근 제한 감지·전파·결과 검증을 유지한다.

## 데이유즈의 범위

| 값 | 표시 | 동작 |
| --- | --- | --- |
| inspect | 유무확인 | 신규 기본값. 상품목록에서 존재 여부 확인, 데이유즈 날짜별 일정 조회 생략 |
| lodging_only | 숙박만 | 숙박의 상세일정만 수집하고 데이유즈 제외 범위를 기록 |
| detail | 상세수집 | 상세정보 수집에서 숙박·데이유즈의 날짜별 일정 수집 |

기본정보 수집에서는 데이유즈 상세일정을 조회하지 않는다. 존재 확인과 객실 공유 여부는 별도이며 공유를 확정하지 않는다. 목록 오류·미확인은 ‘없음’으로 변환하지 않는다. 미조회 수량·매출은 정상응답의 0과 구분하며, 데이유즈 공유 여부나 수량을 확인하지 못한 경우 전화예약 추정을 보류한다. 기존 완전 수집 자료의 dayUseMode 누락은 과거 detail 방식으로 해석한다. 기존 예약 조건도 이를 유지하고 새 예약의 기본값만 inspect로 둔다.

## 날짜·예약

사용자에게 보이는 기간은 숙박일의 포함 범위다. 당일 수집의 API 체크아웃은 다음 날이지만 bookingRangeDays=1로 고정한다. 실행 날짜·시각은 이 숙박일 범위와 별도이며 한국시간이다. 지난 1회 예약은 등록하지 않는다.

세 워커 모두 예약을 지원한다. `/api/worker-schedule`와 하위 `/enabled`, `/run-now`에 `?workerKey=web|manual|scheduled`를 사용한다. 생략하면 기존 scheduled이다. 조건 저장과 예약 활성화는 별도이다. 각 카드의 즉시수집은 저장된 예약 조건이나 다음 예약을 바꾸지 않는다.

기존 scheduled 설정/기록 경로는 그대로 두며, web/manual은 `config/keyword-worker-schedule-{key}.json`, `history/keyword-worker-schedule-{key}/`에 각각 저장한다. 기본값은 비활성이다. 예약 대기 작업이 실행일을 넘으면 시작하지 않으며, 일시정지는 해당 워커의 아직 시작하지 않은 예약에 적용한다.

## 중앙 보관

원격 두 워커는 기존 인증된 broker 전송 경로로 결과 파일과 manifest를 보낸다. 웹 직접 실행도 별도 임시 경로에서 검증한 뒤 같은 운영 서버 `OUTPUTS_DIR`로 게시한다. 파일 경로·해시·조건·품질 검증을 통과해야 정상 결과로 게시하며 `/api/runs`와 `/api/runs/{runId}`에서 조회한다. 정상 결과의 업체 DB·플레이스 고유번호 연결과 관측 이력 반영 경로를 공유한다. 불완전 자료는 정상 매출 자료로 합치지 않는다.

실행 기록은 워커·키워드·실행일·상태로 함께 조회한다. 당일 중복 확인은 워커별로 분리하지 않는다. 유무확인 자료를 데이유즈 상세자료로 재사용하지 않도록 수집 범위에 dayUseMode를 포함한다.

## 검수

`npm run test:worker-cards`는 카드 입력·날짜·예약·모드 검증, 예약 파일 격리, 세 워커의 실제 로컬 HTTP 접수/전송/보관함/업체 DB 연결을 검사한다. 실제 crawler와 외부 통신은 모의 구현으로 차단한다. 별도 crawler contract 검사에서 숙박 7일 범위를 유지하면서 데이유즈 일정 조회가 inspect/lodging_only/detail 각각 0/0/7회인지 확인한다.

로컬 미리보기는 운영 데이터와 분리된 모의 서버이며 실제 네이버 연결 성공을 뜻하지 않는다.

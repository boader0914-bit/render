# 지역 DB → 월간리포트 자료 준비

지역 DB의 **지역 자료 관리 → 선택 지역 상세 → 리포트 자료 준비**에서 보고월과 관측 마감일을 정한다. **지역 지표 일괄 수집**으로 자료를 준비한 뒤 **리포트로 보내기**를 누르면 같은 지역·보고월·마감일로 월간리포트 작성 화면이 열린다. 미리보기·초안 저장·검토·발행은 기존 리포트 흐름에서 진행한다.

## 수집과 저장

- 대상은 행정구역 원장에 등록된 활성 시군구 한 곳이다. 기존 관리 화면의 지역키를 공식 지역키로 정확히 연결하며, 연결 실패 시 다른 지역으로 대체하지 않는다. 광역 전체의 지표를 시군구 지표의 합으로 만들지 않는다.
- 보고월 기본값은 직전 마감월, 관측 마감일은 보고월 말일과 오늘(한국시간) 중 빠른 날이다. 사용자가 변경할 수 있다. 관측 마감일은 숙박 자료 선택 조건이고 공공 지표의 공표 기준기간과 별개다.
- 관광 4분야(지역 방문자, 체류·소비, 관광자원 수요, 관광 다양성)는 **선택한 월 1개월**의 저장 자료부터 검사한다. 정상 자료는 재사용하고 부족한 항목만 `collectMissing:true`, `force:false`, 동시 1, 페이지 최대 1로 조회한다. 현재 진행 월은 API를 호출하지 않고 공표 대기로 남긴다. 과거 월에 응답 자료가 없다고 0으로 만들거나 공표 대기로 단정하지 않는다.
- KOSIS 인구·산업의 7개 통계는 각자의 월간/연간 공표기간을 유지한다. 모든 정상 저장 자료가 30일 이내이면 재사용하고, 누락·부분·갱신 필요 시 기존 KOSIS 갱신 서비스를 호출한다. 연간 값을 월간으로 환산하지 않는다.
- 기존 관광 저장소 및 KOSIS 저장소에 저장하므로 지역분석과 리포트에서 함께 읽는다. 공급자 오류가 정상 저장값을 덮어쓰지 않는 기존 정책을 유지한다.
- 수집은 서버에서 비동기로 순차 처리한다. 같은 지역·보고월의 진행 중 요청은 같은 작업으로 합친다. 다른 지역의 준비 작업도 병렬 실행하지 않는다. 기존 관광 수동 갱신과 실행 잠금을 공유하고 체류·소비 조회의 기존 일일 예산 예약·정산을 그대로 사용한다.
- 준비 기록은 `DATA_DIR/regional_report_preparation/jobs.json`에 원자적으로 저장한다. 서버 재시작으로 끝나지 않은 작업은 중단으로 표시하며 자동 재실행하지 않는다. 재시도는 관리자가 상태를 확인한 뒤 버튼을 눌러 실행한다.

## 화면 상태

여섯 분야의 완료/일부 자료 준비/실패/자료 없음/공표 대기/중단, 실제 기준기간, 저장 시각을 표시한다. 진행률은 성공률이 아니라 처리한 항목 수다. KOSIS 세부 통계의 기준기간은 각각 확인한다. 정상 응답의 수치 0과 누락·오류는 구분한다.

준비된 자료가 일부라도 있으면 누락 안내와 함께 리포트 화면으로 이동할 수 있다. 지역·월·마감일을 명시적으로 전달하고 기존 다른 대상의 미리보기는 지운다. 지역이나 날짜가 유효하지 않으면 다른 값으로 임의 대체하지 않는다. 보고서 생성은 저장 자료만 읽으며 공급자 API를 호출하지 않는다. 기존 발행본은 변경하지 않는다.

상태는 진행 중일 때만 2초마다 조회하고 화면을 벗어나거나 끝나면 조회를 멈춘다. 화면 재진입은 상태 조회만 수행한다. 시작 응답을 잃어버린 경우 상태 확인 전까지 중복 실행을 막는다.

## 관리자 API

- `GET /api/regional-report-preparation?regionKey=…&month=YYYY-MM`: 저장된 `job` 또는 `null`. 외부 조회와 새 수집을 시작하지 않는다. 재시작 후 미완료 기록은 중단 상태로 복구한다.
- `POST /api/regional-report-preparation`: `{regionKey,month,cutoffDate}`. 영속 기록 후 `202 {job}`을 반환한다. JSON·동일 출처·관리자 권한을 검사하고 시작 요청은 계정별 시간당 6회로 제한한다. 외부 API 주소/인증키/임의 force 옵션은 받지 않는다.

작업 기록에는 상태·기간·시간·안전한 오류코드만 저장하며 비밀번호, 인증키, 쿠키, 공급자 원문 오류는 담지 않는다. 숙소 크롤링·워커 일정·예약 일정은 이 기능과 독립적이다.

## 검증

`npm run test:regional-report-preparation`, `npm run test:monthly-reports`, `npm run test:region-analysis`, `npm run check`.

새 통합 검증은 격리된 임시 저장소와 모의 관광/KOSIS/검색 트렌드 응답을 사용한다. 실제 공급자 호출을 금지한 상태에서 인증·중복 실행·영속 기록·정상 0·6분야 준비·캐시 기반 리포트 연결을 검증한다. 운영 데이터와 운영 수집 일정은 변경하지 않는다.

## 검색 트렌드

- 여섯 번째 항목은 네이버 DataLab 공식 검색어 트렌드 API다. 기준 검색어는 지역명+글램핑이며, 중구·고성 등 혼동되는 지역은 상위 지역명으로 구분한다. 다른 업종이나 지역 전체 검색량을 의미하지 않는다.
- 선택한 보고월을 포함한 12개월을 월 단위로 한 번 조회한다. 현재월은 한국시간 전일까지의 부분 자료이며, 매월 1일 현재월은 공표 대기다. 2016년 이전은 조회하지 않는다.
- 정확한 지역·검색어·기간·조회조건으로 캐시를 분리하여 DATA_DIR/regional_search_trends에 보관한다. 정상 저장 자료는 24시간 재사용하며 같은 요청은 하나로 합친다. 429 응답은 반복 재시도하지 않는다. 실패 시 기존 정상 자료와 실제 저장 시각을 유지한다.
- 키 설정과 실제 응답 성공을 구분한다. GET 준비 상태의 searchTrendConnection은 설정 여부·최근 검사·최근 성공·안전한 오류코드만 반환한다. 인증값은 반환하지 않는다.
- 조회기간 내 최대100인 상대지수이며 절대 검색량이 아니다. 독립된 검색어 또는 기간의 지수를 합산하지 않는다. 정상 응답 0과 오류·누락을 구분하고, 기간·검색어·응답 형식이 맞아야 저장한다.
- 월간 리포트와 지역 입지현황은 저장 자료만 읽는다. 지역 입지현황은 현재월 또는 직전 마감월의 준비된 기준 검색어 자료를 읽으며 화면 이동이 공급자 조회를 실행하지 않는다.
- 공식 문서: https://developers.naver.com/docs/serviceapi/datalab/search/search.md
- 2026-09-27 운영 UI의 연결 테스트에서 DataLab 정상 / SearchAd 정상 실응답을 확인했다. 새 지역 수집 경로의 검증은 별도 모의 통합검증이며 운영 배포 완료를 뜻하지 않는다.

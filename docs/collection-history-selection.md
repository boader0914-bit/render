# 수집 이력 선택

`수집 · 이력`에서 키워드를 검색하고 수집 시작일·종료일을 지정한 뒤, 저장된 회차를 고른다. 날짜 필터는 한국시간의 **수집일** 기준이다. 예약 조회기간은 선택한 회차 안에 따로 표시한다. 같은 날 수집한 여러 회차는 시간·워커·결과 번호로 구분한다.

선택한 결과의 업체 목록, 완료 상태, 예약 응답 수, 오류 근거는 동일한 결과 번호를 사용한다. 요청을 빠르게 바꾸면 이전 응답은 화면에 반영하지 않는다. 상세 자료 조회에 실패하면 다른 회차를 대신 표시하거나 정상 0건으로 표시하지 않는다.

키워드 누적 지표는 전체 보존 이력이다. 관측일별 추이는 최근 10개 관측일의 합계이며 개별 회차와 구분한다. 누적 업체 추이는 변동폭이 높은 6곳을 표시한다. 원본 결과 선택에는 최근 날짜 제한이 없다. 수집시각이 파일 시각으로만 남은 구형 자료는 ‘수집시각 미확인’으로 표시하고 날짜 검색에서는 제외한다.

관리자 전용 `GET /api/history/runs/{runId}`는 저장 파일과 현재 업체 DB의 검수 기준을 읽는다. 객실 검수값이 있으면 기존 계산 규칙에 따라 적용하며 화면에 적용 여부를 표시한다. 원본 파일·업체 DB·관측 이력은 변경하지 않고, 네이버·관광 API를 호출하지 않는다. 기존 분석 페이지의 `GET /api/runs/{runId}` 동작과 독립된 경로다.

운영 배포는 중앙 웹에만 적용한다. 키워드 사이에 수집 프로세스가 없어도 예약 배치가 다음 시각을 기다리고 있으면 재시작으로 남은 작업이 중단될 수 있다. 워커 대기열뿐 아니라 예약 스케줄의 진행 여부와 당일 영수증의 남은 항목을 확인하고 배치 종료 후 배포한다.

# 지역별 이번 달 예상 · 다음 달 전망

2026-10-16 개발본. 로컬 검증은 운영 배포나 실제 제공기관 자료 갱신 완료를 뜻하지 않는다.

## 화면과 사용

**지역분석 → 수요 전망** 상단에서 공통 선택 지역의 이번 달·다음 달을 나란히 본다. 대표 값은 일평균 방문자, 체류지수, 소비지수, 검색 관심도다. 방문자·체류소비·관광자원 수요·관광 다양성·검색의 세부 지표는 종류별로 접고 펼친다. 기존 5개 지역 메뉴와 선택 지역은 유지한다.

- 화면 진입·상태 확인은 저장 결과와 작업 상태만 조회한다.
- **저장자료로 계산**은 이미 확보한 지표와 공휴일 자료만 사용한다.
- **자료 갱신 후 계산**은 기존 지역 자료 준비 기능의 잠금·공유 예산과 특일정보의 연간 캐시·실패 재시도 간격을 적용한 뒤 계산한다.
- 자동 갱신은 기존 **DB → 지역 DB → 지역 자료 갱신 관리**에서 명시적으로 켜는 정책을 사용한다. 지역 지표 갱신 완료·자료 변경은 현재 전망의 저장자료 재계산으로 연결된다. 이 재계산은 외부 API를 호출하지 않는다. 공휴일 캐시 갱신도 현재 전망을 갱신한다. 미확보 공휴일은 수동 ‘자료 갱신 후 계산’으로 확보한다.
- 한국시간 월이 바뀌면 이미 관리하는 지역에 한해 새 월의 전망을 저장자료로 준비한다. 과거 발행 전망은 후속 관측값으로 고치지 않는다.

## 산출 대상과 기준

매출·숙박 예약률을 관광지수로 직접 환산하지 않는다. 인구·산업의 연간/정적 통계도 월별 예측 대상에서 제외한다. 월간 관광지표와 네이버 데이터랩 검색 관심도를 각각의 원 단위로 예상한다.

지표별 최근 정상 자료를 사용한다. 기본 표시 창은 13개월이며 조회 경로가 지원하는 범위에서 이미 저장한 관광 이력은 최대 36개월까지 검증에 활용한다. 검색은 하나의 정규화 응답 묶음(24/13/12개월)만 사용하고 다른 조회기간의 상대지수를 붙이지 않는다. 전망 가능한 목표 수·최신 정상월·확보 월 수를 비교해 묶음을 선택하므로 불완전한 24개월 자료가 정상 13개월 자료를 가리지 않는다. 공급자 조회는 직전 완료월까지 하므로 미완료 월을 완성된 관측으로 취급하지 않는다.

정상 월 6개 이상이 필요하며 최신 정상월로부터 3개월을 넘으면 전망을 보류한다. 정상 응답 0은 유효값이다. 오류·차단·누락·중복월은 0으로 바꾸지 않는다. 관광지수에는 임의의 100 상한을 적용하지 않으며 네이버 상대지수만 0~100 범위로 표시한다.

전년 같은 달 또는 최근 수준을 기준으로 삼고, 최근 추세는 과거 시점을 순서대로 가린 검증에서 기준 대비 오차가 10% 이상 줄었을 때 채택한다. 비교 검증에는 최소 3개 원점이 필요하다. 평균 절대오차(MAE)와 가중 절대비율오차(WAPE)는 과거 검증 결과이며 미래 오차의 보장 구간이 아니다. 검증 이력이 적으면 이를 함께 표시한다.

방법 참고: [Forecasting: Principles and Practice — 시계열 교차검증](https://otexts.com/fpp3/tscv.html).

## 특일정보와 연휴

[한국천문연구원 특일정보](https://www.data.go.kr/data/15012690/openapi.do)의 `getRestDeInfo` 응답 중 `isHoliday=Y`인 공휴일만 공식 휴일로 센다. 기념일·절기·잡절을 공휴일로 세지 않는다.

공휴일과 토·일의 합집합에서 연속 3일 이상을 연휴로 본다. 주말과 공휴일이 겹쳐도 중복 계산하지 않으며 월말·연말 경계를 이어 확인한다. 징검다리 평일은 후보로만 표시한다. 공휴일 자료가 없으면 ‘미확인’이며 정상 빈 응답의 0일과 구별한다. 이전 정상 캐시는 보존하고 최신 변경 미반영 가능성을 표시한다.

연휴에 무조건 일정 비율을 더하지 않는다. 수치 보정은 정상 월 24개 이상, 전년 비교 12쌍, 휴일 구성 차이가 있는 비교쌍 6개 이상, 과거 검증 3회 이상과 기준 대비 오차 10% 이상 개선을 모두 충족한 지표에 한한다. 근거가 부족하면 휴일 일정·최장 연휴·보정 보류 사유를 표시하고 기본 전망을 유지한다. 현재 최대 24개월 이력만 제공하는 조회 경로는 충분한 과거 검증을 구성하지 못해 보정이 보류될 수 있다. 이는 연휴의 인과효과가 입증되었다는 뜻이 아니다.

## 저장과 변경

`DATA_DIR/regional_outlook/` 아래 작업 큐, `results/<조건지문>/<결과번호>.json`, `latest/<조건지문>.json`을 영속 저장한다. 조건은 지역·기준월·이력 창·저장 버전이다. 결과에는 모델 버전, 관측 기준, 입력 지문, 지표별 산출법·검증오차·연휴 보정 사유를 남긴다.

입력값·상태·휴일·산출 버전이 같으면 기존 결과번호를 재사용한다. 조회일·자료 수신시각만 달라진 경우 다시 발행하지 않는다. 실제 값·공휴일·출처 상태가 바뀌면 현재 월의 관련 지역만 새 결과로 저장하며 이전 결과 파일도 보존한다. 원본 자료나 숙박 업체 DB를 수정하지 않는다.

- `GET /api/regional-outlook?regionKey=...&months=13[&month=YYYY-MM]`: 저장값만 조회. 과거 기준월 조회 가능.
- `POST /api/regional-outlook/refresh`: `{regionKey, months:13, collectMissing:false|true}`. 현재 기준월만 계산 가능.
- 전망 전용 외부 갱신 예약 API는 추가하지 않는다. 기존 지역 자료 관리의 정책을 사용한다.

관리자 인증·동일 출처·JSON·범위·요청 빈도 검증을 적용한다. 같은 조건의 진행 중 작업은 재사용한다. 응답 유실 후 상태부터 확인하며 외부 갱신을 자동 재전송하지 않는다. 실패나 지표가 전부 사라진 경우 이전 정상 전망을 유지한다. 계산 중 입력 변경은 오래된 결과 게시를 막고 새 입력으로 계산한다. 월이 바뀌면 대기·복구·실행 중인 과거월 작업도 결과를 새로 게시하지 못한다. 재시작 후 저장값은 그대로 읽고 외부 갱신 작업은 자동 반복하지 않는다.

## 검증

외부 갱신이 전부 실패한 경우 기존 정상 전망을 유지하고 작업 실패를 기록한다. 일부 갱신 실패는 결과번호를 재사용하더라도 별도 작업 진단에 남겨 표시한다. 입력 변경으로 후속 저장자료 계산을 수행한 경우에도 이 진단을 승계한다.

`npm run test:regional-outlook`으로 엔진·공휴일·영속 저장·화면·실제 로컬 앱 서버 계약을 확인한다. 제공기관은 합성 자료로 대체하고 로컬 앱의 외부 fetch를 금지한다. `node scripts/test_regional_analysis_api.cjs --preview`는 합성 자료로 실제 앱 검수 화면을 연다.

운영 성능·예측 정확도·실제 API 인증은 운영 검수 및 충분한 후속 관측으로 따로 확인해야 한다. 숙박 수집 워커·속도·차단 보호·예약 설정과 인사이트 서비스는 변경하지 않는다.

## 발행 전망의 후속 실측 검증

2026-10-16 추가 개발. **지역분석 → 수요 전망 → 지난 전망 검증**에서 최근 12개 발행월을 접고 펼쳐 본다. 기존 모형 선택에 쓰던 **과거 자료 모의검증**과 별개다. 후속 실제 발표값이 없는 전망을 정확도가 검증된 것으로 표시하지 않는다.

- 지역·발행월·지표·대상월·이번 달/다음 달 구분별로 **보존된 발행본 중 첫 전망**을 선택한다. 모델 변경 후 더 유리한 전망으로 바꾸지 않는다. 과거월 전망을 오늘의 자료로 새로 만들어 비교하지 않는다.
- 발행 기준월, 작성 시각, 실제 저장 발행 근거를 확인한다. 이미 실제 값이 있던 항목과 사후 작성본은 비교에서 제외한다. 과거 발행 기록은 보존 범위가 제한될 수 있으므로 ‘최초 발행 전체를 확보했다’고 주장하지 않는다.
- 대상월이 한국시간 기준으로 종료되고 같은 지역·지표·단위·제공기관의 정상 공식 값이 확보됐을 때 비교한다. 관측 0은 실제 값이다. 부분 응답·오류·누락·최신 변경 미확인은 검증 대기, 단위·출처·중복 충돌 등 비교할 수 없는 자료는 제외 사유를 표시한다.
- 실제 값은 평가 시점까지 확보한 최신 정상 공식 자료 기준이며 수신시각·출처를 남긴다. 공식 정정값이 들어오면 새 평가 결과를 저장하고 기존 전망과 이전 평가 결과를 보존한다. 일시적으로 자료를 읽지 못하면 이미 비교한 정상 결과를 지우지 않고 계산 실패를 알린다.
- 차이는 **실제 값 − 전망 값**이다. 평균 절대오차(MAE)는 같은 단위별로, 가중 절대비율오차(WAPE)는 실제 값 합계가 0보다 클 때만 계산한다. 이번 달 예상/다음 달 전망·지표·단위·제공기관·모델을 분리하고 비교 건수를 함께 표시한다. 적은 표본을 일반적인 미래 정확도로 해석하지 않는다.
- 네이버 검색 관심도는 조회기간과 응답 묶음이 같은 경우만 직접 비교한다. 정규화 범위가 다른 후속 상대지수는 비교 제외가 정상이다. 이 검증 기능에서 추가 네이버 조회를 하거나 기준이 다른 지수를 결합하지 않는다.

발행 전망 보존 기록은 `DATA_DIR/regional_outlook_evaluation/publications/<지역지문>/<발행월>/<전망결과번호>.json`에 교체 없이 저장한다. 신규 정상 게시 콜백만 기록하고, 기존 자료는 정상 완료 작업이나 게시 포인터에 남은 결과만 이관한다. `results/`의 고립된 파일은 발행 근거로 사용하지 않는다. 같은 전망 결과번호를 다시 보더라도 첫 보존 기록을 덮어쓰지 않는다.

검증 산출물은 별도 `regional_outlook_evaluation/results/`, `latest/`, `queue.json`에 저장하며 서버 재시작 후 재사용한다. 비교에 영향을 주는 입력이 같으면 동일 결과를 사용한다. 조회만으로 파일 탐색·계산·공급자 API 요청을 시작하지 않는다. 지역 자료 변경·새 전망 게시·월 변경은 저장자료 검증으로 연결되고, 수동 **저장자료로 검증**도 가능하다.

- `GET /api/regional-outlook` 응답의 `validation`에 저장된 검증 결과·작업 상태를 제공한다.
- `GET /api/regional-outlook/validation?regionKey=...&months=13`: 저장 검증 조회.
- `POST /api/regional-outlook/validation/refresh`: `{regionKey,months:13}`. 현재 평가월의 저장자료만 사용하며 `collectMissing:true`는 거절한다. 관리자·동일 출처·JSON·요청 빈도 검사를 적용한다.

방법 참고: [Forecasting: Principles and Practice — 실제 예측오차 평가](https://otexts.com/fpp3/accuracy.html), [네이버 검색어 트렌드 API](https://developers.naver.com/docs/serviceapi/datalab/search/search.md). 내부 검증과 발행 이후 실측 비교를 구분하고 네이버 상대지수의 정규화 조건을 보존한다.

# 관리자 아이디별 고객 화면 보기

인사이트 관리자는 고객 목록 또는 고객 상세의 **고객 화면 보기**를 눌러 해당 아이디에 등록된 내 매장, 경쟁업체, 지역 자료와 리포트를 확인한다. 고객 화면 상단에서도 아이디를 검색하고 전환할 수 있다. **관리자 체험**은 기존 관리자 전용 등록 공간이며 실제 고객과 분리된다.

실제 고객을 선택한 화면은 조회 전용이다. 기간·월·업체 선택과 저장 자료 조회는 가능하지만 등록·해제·정보 수정·수집 신청·지역 자료 준비·리포트 발행은 하지 않는다. 이 작업은 별도 관리자 관리 화면에서 처리한다. 이용이 중지된 고객과 다른 관리자의 체험 계정은 고객 화면으로 열지 않는다.

## 선택과 권한

- 화면 주소는 `/customer-view?customerId=cus_...#home`이다. 표시 아이디로 검색해도 내부 선택값은 변경되지 않는 고객 고유번호다.
- 새 고객을 선택하면 전체 페이지를 이동하고 기존 업체·기간·지역·비교 조건을 제거한다. 선택값은 탭별 주소에 있으므로 다른 탭의 고객을 바꾸지 않는다.
- 관리자 고객 조회 요청은 기존 관리자 로그인과 함께 `X-Insight-Customer-Id`를 전달한다. 이 번호 자체는 인증 수단이 아니다.
- 중앙 연결부는 관리자 인증, 고객 이용 상태, 실제 회원 상태와 등록 관계를 확인한다. 비동기 읽기 후에도 권한을 다시 검사한다.
- 실제 고객이 지정된 고객 화면의 모든 POST는 서버에서 차단한다. 일반 고객 API에서는 이 선택 헤더를 받지 않는다. 기존 관리자 고객 관리 권한을 늘리거나 고객 세션을 발급하지 않는다.
- 번호가 없는 기존 관리자 체험 화면의 등록·수정 동작은 유지한다. 실제 고객 조회 실패 시 체험 계정으로 대신 연결하지 않는다.

## 저장 자료와 캐시

메모리 요청·캐시는 관리자 세션과 선택 고객 번호를 함께 구분한다. 고객별 업체·지역·브리핑과 진행 중인 응답이 섞이지 않는다. 기존 고객의 영속 캐시와 보관소는 그 고객의 소유권으로 조회하므로 기존 발행본·일별 검수 결과를 그대로 확인할 수 있다. 관리자 체험 보관소는 기존 별도 경계를 유지한다.

이 기능은 중앙 데이터랩 연결부와 인사이트 화면·연결 서버에 적용한다. 수집 워커, 수집 속도, 정기수집 승인, 예약 시각, 원본, 발행본과 객실 계산 기준은 변경하지 않는다.

## 검증

- `node --test scripts/test_insight_customer_view_scope.cjs`
- `node --test customer-portal/test/admin-customer-scope.test.cjs customer-portal/test/admin-target-customer-ui.test.cjs`
- `npm --prefix customer-portal test`

로컬 시험은 모의 고객·저장 자료와 로컬 HTTP만 사용한다. 실제 수집 요청으로 검수하지 않는다. 운영에서는 두 고객을 번갈아 선택하고 새로고침·여러 탭에서 선택과 표시 자료가 일치하는지 확인한다.

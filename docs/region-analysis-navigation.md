# 지역분석 메뉴와 선택 지역

관리자 지역분석은 다음 다섯 화면을 같은 순서로 제공한다.

1. 지역 현황
2. 지역 지도
3. 수요 전망
4. 지역 비교
5. 자료·출처

데스크톱은 왼쪽 지역분석 하위 메뉴를 사용한다. 카드 내부의 중복 메뉴는 제거한다. 모바일은 본문 상단의 공통 지역 선택 아래에 같은 다섯 메뉴를 배치한다. 일반회원의 기존 지도·수요 전망 권한은 확대하지 않는다.

## 공통 지역 선택

지역분석 상단의 선택 지역은 정규 행정구역 키로 관리한다. 명시적으로 선택한 지역은 수집결과 선택과 구분하여 보존한다. 메뉴 전환이나 자료 조회 완료 때문에 임의로 다른 지역을 선택하지 않는다. 최초 진입은 이전에 저장한 선택을 우선하고, 선택이 없으면 현재 수집결과의 지역이 하나로 확인될 때만 추론한다. 산청을 임의의 기본값으로 사용하지 않는다.

지도와 숙박 수요는 선택 지역에 맞는 수집자료만 표시한다. 자료가 없거나 키워드·지역코드가 맞지 않으면 선택 지역의 자료 대기 상태를 표시한다. 동명 행정구역이나 여러 지역이 섞인 자료를 한 지역의 자료로 판단하지 않는다. 지역 비교는 기준 지역을 바꾸지 않고, 자료·출처는 해당 지역의 실제 출처와 기간을 보여준다.

브라우저 뒤로/앞으로 이동에서도 분석 지역과 화면을 복원한다. 검색, 시도·시군구 선택 등 지역 현황의 보조 선택 수단도 같은 공통 선택을 갱신한다.

지역 현황의 기본 입지는 기존 내부 입지 해석과 8개 참고 점수를 직접 표시하고, 공식 관측 통계와 구분한다. 수요 전망 바로가기는 특정 관광지표의 확보 여부로 잠그지 않는다. 관광 자료가 부족하면 해당 항목에 상태를 표시한다.

업종분석 연결은 선택 지역이 정확히 일치하는 저장 수집자료 중 검색어별 최신 결과를 제시한다. 예를 들어 가평펜션과 가평글램핑을 선택할 수 있으며, 현재 열어 둔 키워드가 내부 사전의 기본 키워드와 다르다는 이유로 막지 않는다. 이름이 모호하거나 다른 지역인 자료는 포함하지 않는다. 연결은 선택한 저장 결과를 열며 새 수집을 시작하지 않는다.

체류·소비 갱신 후에는 해당 지역의 저장자료를 다시 읽는다. 실제 확보된 월수를 확인해 완료·일부 확보·저장자료 없음·조회 실패를 구분하며, 늦게 도착한 이전 지역의 응답이 현재 선택이나 수집결과를 덮어쓰지 않도록 한다.

## 지역 자료 관리

지역 현황 하단에 있던 전체 관리·검수 영역은 `DB → 지역 DB → 지역 자료 관리`로 이동한다. 분석 상단의 `[지역명] 자료 관리` 버튼은 해당 지역을 선택한 지역 DB를 연다. 관리 데이터가 없을 때 다른 지역 상세로 대체하지 않는다.

`[지역명] 분석으로 돌아가기`는 들어오기 전의 분석 지역과 다섯 화면 중 보던 화면을 복원한다. DB 작업 중 선택한 관리 지역은 분석의 복귀 지역을 덮어쓰지 않는다. 공개 상태, 검토 메모, 업체 표본 보완, 기준값 수정 기능과 기존 저장 API는 유지한다.

## 관광지 방문 전망

실제 관광지 목록과 날짜별 예측 그래프는 `지역분석 → 수요 전망`의 숙박 수요 아래에 배치한다. 별도 시도·시군구 선택을 받지 않고 공통 선택의 공식 행정코드를 예측 API의 지역 코드표와 정확히 대조한다. 도 단위나 제공기관 코드표에 없는 지역을 가까운 다른 지역으로 대체하지 않는다.

`관광지 불러오기`를 눌러 선택 지역의 저장 자료 또는 당일 자료를 가져온다. 단순 메뉴 이동이나 지역 변경은 외부 예측 API를 호출하지 않는다. 지역별 관광지 선택, 이름 검색어와 펼침 상태를 기억한다. 다른 지역의 늦은 응답은 현재 지역의 선택이나 오류 상태를 바꾸지 않는다.

설정에는 연결 상태, 마지막 저장 갱신 시각, 수요 전망 바로가기와 저장 지역을 명시한 갱신 기능을 둔다. 설정에서 특정 지역을 갱신해도 분석 중인 지역을 바꾸지 않는다.

지수는 공식 0~100 상대 방문 집중 예측을 그대로 표시한다. 여러 관광지 지수를 평균해 지역 전체 수요로 만들거나, 숙박 예약률·매출 계산에 합치지 않는다. 캐시·자료 보존·원 제공기간 정책은 [관광지 예측 연결](tourism-forecast.md)을 따른다.

# 인사이트 기간 조회와 부분 자료 표시 보완

## 기간 조회 전달 오류

단일 업체의 상세 수집 요청에 `bookingRangeDays=30`과 `bookingRangePlaceLimit=0`이 함께 전달됐다. 수집기는 0을 기간별 조회 비활성으로 해석하므로 첫 숙박일만 조회했다. 기존 30일 결과 검증은 이런 결과를 `COLLECTION_STORED_SCOPE_MISMATCH`로 보류했지만, 요청 전달 오류는 그대로 남아 있었다.

수동·정기 요청의 대상은 한 업체이므로 2일 이상 조회에는 기간 조회 대상 수를 1로 전달한다. 당일 조회는 0을 유지한다. 세 워커 선택, 차단 보호, 중복 방지, 재시도 제한은 바꾸지 않는다. 수집기 자체를 변경하지 않아 워커 재배포는 필요하지 않다.

외부 통신 없는 시험은 실제 수집 함수에 16상품 × 30일 응답을 주입해 480개 상품·숙박일이 처리되는지 확인한다. 운영 수집은 이 배포 검수에 사용하지 않는다.

## 부분 자료 전달

기존 월별 통합 DB가 선택한 정상 관측, 별도로 보존한 부분 금액, 날짜별 제외 사유를 사용한다. 원본 수집, 월별 집계의 선택 기준, 발행본을 변경하지 않는다.

- 현재 30일 투영에서도 검증된 `partialConfirmedRevenue`와 `partialRevenueEvidence`를 보존한다. 업체 번호, 숙박일, 수집 번호, 관측 시각, 금액의 일치를 검사한다.
- 부분 금액은 정상 매출 소계와 별도로 표시한다. 공개예약과 타채널 추정 중 기존 기준으로 산출 가능한 금액이며, 전체 예약수량·전체 매출·예약률로 대체하지 않는다.
- 오래된 정상 수량은 `storedReference`로 분리한다. 기존 `OBSERVATION_STALE` 상태와 현재 비교 제외를 유지한다.
- `missingReason`, 최근 재확인 시각과 사유를 고객 화면까지 전달한다. 응답 성공과 재고 근거의 완전성을 구별한다.
- 서로 다른 수집본의 수량·금액을 합치거나, 누락을 0실·0원으로 바꾸지 않는다. 같은 날짜의 정상 금액과 부분 금액을 중복 합산하지 않는다.

고객 화면은 정상 사용 가능일, 부분 금액이 있는 날짜, 오래된 참고 날짜, 보완 근거가 없는 미확인 날짜를 구분한다. 부분 자료와 오래된 자료를 가격·쿠폰 실행 근거에 넣지 않는다.

## 저장 자료와 일정 보존

기존 정상/부분 캐시의 형식 번호와 저장 공간을 유지한다. 새 필드는 선택적인 표시 확장이며, 저장 자료를 먼저 보여주고 기존 읽기 경로로 최신 투영을 갱신한다. 원본·업체 검수값·발행 리포트·정기수집 상태를 수정하지 않는다. 중지한 정기수집을 재개하거나 누락된 수집을 다시 실행하지 않는다.

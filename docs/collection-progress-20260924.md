# 수집 진행 표시

워커 카드에서 현재 키워드, 실제 업체 처리 수, 예상 남은 시간과 처리 단계를 확인한다. 카드를 접으면 키워드와 예상 시간이 남고, 다른 관리자 메뉴에서는 작은 진행 요약을 표시한다.

## 표시 기준

- 업체 처리 수는 실제 상세 대상의 고유 업체 수를 기준으로 한다. 실패한 업체도 처리가 끝나면 처리 수에 포함된다. 중복 행, 범위 밖 업체와 차단 이후 시작하지 않은 업체는 완료 수에 포함하지 않는다.
- `20 / 20곳 처리`는 전체 작업 완료가 아니다. 정상 결과 검증과 중앙 저장이 끝난 완료 영수증 및 runId를 확인한 뒤에만 `저장·검증 완료`라고 표시한다. 부분·실패·차단 결과를 정상 완료로 바꾸지 않는다.
- 진행 막대는 실제 업체 처리 수만 사용한다. 기존 API의 시간 기반 `estimatedProgress`는 막대에 사용하지 않는다.
- 단계는 실제 실행 보고에 따라 `목록 확인 → 상세수집 → 저장·검증`으로 표시한다. 실제 단계 보고가 없으면 시간 추정만으로 단계 완료를 표시하지 않는다.
- 남은 시간 범위는 기존 예상 시간의 약 80~120%를 읽기 쉬운 단위로 표시한 참고 범위이며 통계적 신뢰구간이 아니다. 예상 시간이 지나면 숫자를 0분 완료처럼 표시하지 않고 지연 상태로 바꾼다.
- 워커 연결 갱신과 실제 진행 보고를 구분한다. 연결이 오래되거나 상태 API 수신이 끊기면 연결 확인, 새 업체·단계 보고가 오래 없으면 응답 확인 상태로 바꾸고 애니메이션을 멈춘다. 이 화면 판정은 실행 중인 수집을 취소하지 않는다.
- 유사 실행 시간은 워커와 데이유즈 조건도 비교한다. 다른 워커의 이력을 동일한 서버 성능으로 간주하지 않으며, 실패·부분 결과와 기존 결과 재사용 시간을 정상 수집 학습에 섞지 않는다.

## 상태 전달

공통 수집 엔진은 `COLLECTOR_PROGRESS` 한 줄 JSON을 출력한다. `version`, `phase`, `completedPlaces`, `totalPlaces`, `currentPlaceName`, `updatedAt`만 허용한다. 업체명은 제어 문자를 제거하고 120자로 제한한다.

2Gweb_worker는 자식 출력에서, BG worker와 AWS worker는 인증된 heartbeat에서 진행 보고를 전달한다. 중앙 서버는 수신 시각을 붙이고 `/api/collector-status`의 `workers[].crawl.progress` 및 워커별 `/api/crawl-status`에 반환한다. 단순 heartbeat는 마지막 실제 진행 시각을 갱신하지 않는다. 원격 결과 전송과 최종 검증도 별도 단계로 전달한다.

진행 화면의 상태 조회와 보고는 STAYDATALAB 서버끼리의 통신이다. 이번 변경은 네이버 요청 간격·동시 수·수집 범위·차단 보호 또는 자동수집 설정을 변경하지 않는다.

## 검증

실제 네이버 수집을 실행하지 않고 다음 경계를 모의 검증한다.

- 실제 대상 선정, 중복 제외, 동시 업체 완료 순서, 차단 후 미시작 제외
- 세 실행 경로의 진행 보고와 중앙 상태 API, 상태 갱신과 실제 진행 시각의 구분
- 정상 결과의 중앙 보관함·업체 DB 반영, 부분·차단의 정상 자료 반영 보류
- 예상 시간과 실제 처리량 분리, 저장 전 미완료, 지연·연결 끊김·차단 표시
- 접힌 카드, 다른 메뉴 요약, 모바일, 라이트·다크 테마, 동작 줄이기 설정

운영 배포 완료 판단은 세 Render 서비스의 동일 커밋 Live, 웹 health 및 배포된 파일 확인, 관리자 상태 API의 실제 연결·대기 상태 확인을 기준으로 한다.

## 고객 화면

### 경쟁분석

- 등록 카드 목록 중심 화면을 기준 내 매장·선택 경쟁업체의 나란히 비교 화면으로 바꿨다.
- 업체별 객실 기준·공식 지역·업종·유효 관측일·추정 예약률·예약 수량을 표시한다. 개별 요약과 공통 날짜 비교는 서로 다른 범위임을 명시한다.
- 공개 예약은 녹색, 타채널 추정은 보라색 막대로 합산한다. 두 업체에 같은 날짜·세로축을 적용하고 실제 0실은 점, 미확인은 ×로 구분한다. 모수 충돌이 있어도 정상 수량은 표시하고 예약률은 보류한다.
- 공통 날짜 표에 지역 관계·비교 목적·확인 금액·부분 금액을 표시한다. 접힌 근거에 제외 날짜·금액 미확인 날짜·실제 관측시차와 정책 상태를 둔다.
- 가격·상품 보기는 기본 객실·데이유즈·확인 금액과 기존 A·B·C 업체자료로 연결한다. 저장되지 않은 상품별 가격을 예시 가격으로 대체하지 않는다.
- 지역 배경은 중앙 비교 계약의 분석지역으로 묶는다. 현재 권한으로 연결된 지역만 링크한다. 타지역 경쟁업체의 파생 지역 조회 권한을 임의로 만들지 않는다.
- 등록·해제·경쟁업체 추가는 설정으로 모았다. 경쟁분석에는 접힌 등록업체 자료 링크를 유지한다.

### 공통 선택

인증된 등록 관계로 1단계 선택 모듈을 설정한다. 내 매장 선택은 경쟁분석·지역분석·리포트에 이어지고, 업체자료에서 다른 내 매장을 열면 기준 매장도 갱신한다. 비교업체가 0곳인 선택도 새로고침 후 유지한다. 계정·권한 변경 시 선택 범위와 늦은 응답을 다시 검사한다.

주소 검색 조건과 메뉴 해시는 분리했다. 뒤로가기에서 해시와 조건이 함께 바뀌면 화면을 한 번만 구성한다. 보기 탭을 바꾸는 동작은 추가 GET 없이 저장 자료를 다시 그리며, 진행 중 최신 확인의 완료 반영을 막지 않는다.

### 내 매장·경쟁업체 C 통합관측

기존 A 기본정보·B 예약채널·C 월 합계·공개+추정 막대·기본 접힌 주간 표를 유지했다. C에 ‘최근 관측 간 변화’를 추가했다.

- 동일한 이전·이번 관측 시각에 겹치는 고정 숙박일 묶음만 비교한다. 서로 다른 관측 구간이나 전체 월의 누적 증감을 섞지 않는다.
- 공개 예약 변화와 방막기 변화를 부호 있는 객실 수로 구분한다. 0과 미확인을 구별하고 방막기 0은 보라색으로 강조하지 않는다.
- 펼친 근거에 숙박일, 두 관측 시각, 각 변화량, 중앙에서 제공한 리드타임 범위와 제외 사유를 표시한다.
- ‘예약 접수·취소 확정이 아닌 관측 수량의 변화’라고 명시한다. 구형 `observationFlow`를 되살리거나 실제 예약 접수일로 변환하지 않는다.
- 직접 실적 입력·객실 수정 기능의 잠금을 변경하지 않았다.

## 저장 자료와 갱신

기존 리포트 저장소·권한 검사·진행 중 요청 공유를 재사용했다. 경쟁 화면 첫 응답에는 이미 저장된 브리핑도 포함하며, 초기 복원을 위해 새 계산을 실행하지 않는다.

- 저장 정상 자료를 즉시 표시하고 뒤에서 최신 상태를 확인한다.
- `peekCurrentBriefing`/`readCurrentBriefing`은 DOM 없이 같은 캐시와 실제 네트워크 요청을 공유한다. 소비자가 나중에 합류했다는 이유로 요청 순서를 새로 부여하지 않는다.
- 새로고침 응답보다 늦게 온 이전 성공 응답이 최신 정상 캐시를 덮지 못한다. 미리보기와 정상 결과는 구분하며 최신 정상 결과가 있으면 우선 표시한다.
- 일시적 연결 실패 때는 현재 캐시를 다시 확인해 다른 조회가 완료한 최신 정상 자료도 유지한다. 401·403·404·409는 기존 권한·범위 보호대로 표시 자료를 폐기한다. 요청 순서만으로 권한 거부를 무시하지 않는다.
- 원본·발행본·기존 정상 캐시 이름공간과 확인 시각을 유지한다. 새 필드에는 회사·정확한 30일·관측 기준·수량 합계·모수·KST 날짜·미확인 구분 검증을 적용한다.

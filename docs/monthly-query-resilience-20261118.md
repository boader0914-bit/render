# 월별 저장 자료 조회 복원과 응답 지연 보완

## 확인한 문제와 원인 구분

2026-11-18 오전 운영 검수에서 첫 키워드 목록은 296ms, 자료 응답은
578ms였지만, 새로고침은 Render HTTP 502로 끝났다. 정상 재조회 한 번도
`KEYWORD_MONTHLY_ANALYTICAL_BUSY`(503)로 보류됐다.

503은 저장 금융 자료의 메모리·실행 허가 경로가 집계 작업과 충돌하면
발생할 수 있다. 과거 응답만으로 정확한 거절 분기를 확정하지 않는다.
버전 조회는 해당 금융 실행 허가를 사용하지 않으므로 502와 같은 원인으로
취급하지 않는다.

같은 시간대에 최대 25.03초 이벤트 루프 지연과 30.37초 `source-options`
실행이 관측됐다. 월 목록을 찾는 SQLite SELECT가 웹 스레드에서 동기 실행되고,
비포괄 인덱스로 큰 원시 행 테이블에 접근할 수 있었다. 과거 로그에는 이 SQL의
단독 실행 시간이 없으므로 이것을 운영 502의 유일한 원인으로 단정하지 않는다.

## 변경

* `GET /api/keyword-monthly/catalogue`는 준비 결과의 작은 포인터·카탈로그만
  전후 검증한다. 관리자 인증, 전환 보호, 메모리 보호, 단일 조회·응답 한도를
  유지한다. `metadataOnly=true`, `financialResultValidated=false`로 목록 선언과
  금융 자료 검증을 구별한다. 기존 `/options` 및 금융 자료의 보호·해시 검사는
  유지한다. 카탈로그가 없거나 손상됐을 때 원본 계산으로 우회하지 않는다.
* 마지막 정상 prepared 응답 하나를 동일한 관리자 세션의 브라우저 저장소에
  제한 보관한다. 새로고침 시 먼저 표시하고 실제 버전 GET으로 변경 여부를
  확인한다. 확인 전·실패 상태를 최신 완료로 표시하지 않는다. 새 포인터는
  정상 prepared 금융 응답을 검증한 뒤에만 반영한다. 계정·세션·조회 조건,
  내용 해시·유효기간·저장 용량을 검사한다. 저장할 수 없어도 정상 조회는 유지한다.
* 월 목록의 기존 동일 SQL을 웹 호스트의 읽기 전용 Worker로 옮긴다. 인덱스와
  스키마를 수정하지 않는다. 원본·인덱스 전후 식별값, 결과 형식, 직렬 소유권,
  시간 제한과 실제 Worker 종료를 검증한다. 이미 격리된 복사본은 명시적
  capability로 같은 SQL을 기존 자식 안에서 실행한다.
* `history_index_months_query` 단계로 해당 SQL의 이후 실제 소요시간을 구분한다.
  선택 목록의 코드 버전에 새 Worker 파일도 포함한다.

## 유지 범위

원본 관측, 기존 발행 JSON/PDF, 수량·매출 계산 기준 7개 파일, 수집·예약·속도
설정과 보호 임계값은 바꾸지 않는다. 인사이트 정기수집은 중지 상태로 유지한다.
운영 검수를 위한 수집·재수집, 강제 재계산, 보호 해제는 하지 않는다.

## 검수 기준

관련 보호·저장 자료·격리 복사본·Worker·브라우저 회귀 테스트를 실행한다.
운영은 지정 커밋 배포와 코드 지문, 전후 보존 비교 후 검수한다. 첫 목록,
새로고침 후 실제 표시, 표시 후 최신 저장 버전 확인을 따로 측정한다.
같은 세션의 캐시 복원은 직전 정상 응답, 조회 조건·포인터·입력 해시·KPI,
새 문서 및 실제 화면 프레임과 후속 버전 응답을 연결한다. 새 버전 채택과
오류 시 기존 자료 유지는 별도 회귀 테스트로 확인한다.

실측이 2초를 넘거나 오류·인증·프레임 근거가 빠지면 통과로 보고하지 않는다.
저장된 공개 버전 확인은 원본의 재수집·새 계산 완료를 뜻하지 않는다.

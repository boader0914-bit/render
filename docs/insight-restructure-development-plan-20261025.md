# 인사이트 기능·메뉴·화면 구조 개선 개발계획

작성일: 2026-10-25 KST. 상태: 1단계 기반·시안과 2단계 현재 30일 비교 연결 개발·로컬 검수 완료, 운영 배포 전. 구현 범위와 남은 항목은 [1단계 검수](insight-comparison-stage1-20261025.md), [2단계 연결·검수](insight-comparison-stage2-20261025.md)에 기록했다. 화면 검수 자료는 가상 자료이며 운영 고객 자료 검수와 구분한다.

## 1. 검토 범위와 서비스 목적

인사이트는 숙박업 운영자가 내 매장·경쟁업체·지역의 변화를 함께 읽고, 다음 운영 행동을 결정한 뒤 결과를 확인하는 고객 서비스다. 화면의 흐름은 **현황 → 변화 → 비교 → 실행 → 결과 확인**으로 정리한다.

- 운영 인사이트 `/api/health`: HTTP 200, connected, `ccc0953c2dd2`. 인사이트 체크아웃의 전체 커밋 `ccc0953c2dd29b672b4b3249d55d49baf9186ab0`과 일치.
- 중앙 데이터랩 연결부 검토 기준: `9c628f9219b7690ed613185d0b029dea4f7fe941`. 인사이트 체크아웃에 들어 있는 구형 중앙 코드만 보고 판단하지 않았다.
- 화면 구성·동작·연결 계약·권한·보관 코드를 읽기 전용으로 대조했다. 이번 검토의 운영 브라우저는 관리자 로그인 화면까지 확인했으며, 관리자 세션 만료로 실제 고객 자료를 넣은 전 화면 조작 검수는 수행하지 않았다. 개발 단계에서 재검수한다.
- 이 문서 작성으로 수집 실행, 예약 등록, 고객·업체 DB 수정, 서버 배포를 수행하지 않는다.

| 내 매장 | A 기본정보·상품, B 예약채널, C 월 합계·막대·주간 접기표 | 이전 관측 이후 무엇이 달라졌는지 연결 강화 |

현재 중앙 비교는 동일 숙박일·동일 KST 관측일·최근 7일·공통 숙박일 7일 이상을 확인한다. **지역·업종 차이를 비교 유형과 행동 제안에 반영하지 않는 부분**이 최우선 보완 대상이다. 현재 지역 조회 범위는 내 매장 소재지·관심지역이며, 경쟁업체 소재지 자동 연결은 아직 없다.

## 3. 권장 메뉴와 화면 구조

메뉴는 기존 여섯 개를 유지한다. 메뉴를 늘리기보다 각 메뉴가 답해야 할 질문을 구별한다.

| 메뉴 | 사용자에게 주는 답 | 화면 구성 |
|---|---|---|
| 홈 | 지금 무엇이 달라졌고 무엇부터 볼까? | 기준 내 매장, 예약 현황, 전회 대비 변화, 경쟁 차이, 지역 신호, 이번 할 일 최대 3개 |
| 내 매장 | 내 상품과 예약 흐름은 어떤가? | A 기본정보·상품 / B 예약채널 / C 통합관측. C 안에 예약 현황·관측 간 변화·월별 정리 |
| 경쟁분석 | 누구와 어떤 조건을 비교할까? | 내 매장·업체 선택, 비교 유형·확보 상태, 예약 흐름 / 가격·상품 / 지역 배경 |
| 지역분석 | 내 지역과 참고 지역의 수요는 어떻게 움직이나? | 내 매장 지역 / 경쟁업체 지역 요약 / 관심지역. 본문 네 묶음과 요약 해석 |
| 리포트 | 이번 기간을 어떻게 정리하고 무엇을 실행할까? | 주간·월간 선택, 현황·변화·비교·지역 배경·다음 행동, 발행본 보관, 실행 기록 |
| 설정 | 등록과 계정을 어떻게 관리하나? | 내 매장·경쟁업체·관심지역 등록·해제, 비교 목적·별칭·메모, 수정 요청, 자료 갱신, 계정 |

### 홈

1. 업체가 없으면 등록 또는 준비 중인 사업의 기준 지역 선택을 명확히 안내한다.
2. 업체가 있으면 기준 내 매장과 기간을 표시하고, 정상 저장 자료를 먼저 보여준다.
3. 예약 수량·예약률, 관측 매출, 전회 이후 변화와 각 확인 기간을 짧게 요약한다.
4. 같은 지역 경쟁업체 요약과 다른 지역 참고 업체를 구별한다.
5. 지역 신호는 실제 공표월을 표시하고, 할 일은 근거가 있는 항목만 최대 3개 제시한다.
6. 각 카드에서 해당 조건을 유지해 내 매장·경쟁분석·지역분석·리포트로 이동한다.

### 내 매장

- A: 객실 기준·기준 출처, 상품명·구분·평일/금요일/토요일/일요일 가격. 긴 상품 목록은 접는다. 정보 수정은 A의 보조 동작으로 유지한다.
- B: 확인된 판매채널·마지막 확인 시점. 전화예약을 실제 판매 확인 자료로 만들지 않는다.
- C: 월 합산 요약, 공개 예약+타채널 추정 합산 막대, 기본 접힌 주간 합계와 일별 표를 유지한다. 관측 간 증감과 리드타임은 별도 보기로 제공한다.
- 수집·등록 해제·검수 이력은 기본 분석 화면의 주 동작에서 제외하고 설정 또는 접힌 관리 영역으로 연결한다.
- 내 매장 직접 입력 실적·보정은 별도 저장·출처 표시 원칙을 유지한다. 이번 메뉴 개편으로 잠긴 수정 기능을 자동 개방하거나 중앙 원본을 덮어쓰지 않는다.

### 공통 선택 상태

- 기준 내 매장, 비교 업체 집합, 숙박기간, 관측 기준일, 지표 구분을 공유한다.
- 기본 분석 기간은 향후 30일을 제안하며, 이번 숙박월·마감월·사용자 기간을 선택할 수 있게 한다. C의 월별 정리와 발행 리포트는 숙박월로 묶는다.
- 두 달에 걸친 30일 자료는 중앙의 업체×숙박일 기준으로 연결한다. 월 자료를 합친 뒤 같은 날짜를 중복 가산하지 않는다.
- 지역 통계의 공표월은 숙박기간과 별도 표시한다. 예약 전망의 10월과 최신 공표 통계의 8월을 같은 시점처럼 표현하지 않는다.
- 내 매장을 바꾸면 종속 지역·경쟁 설정도 바꾸고, 같은 맥락 내 메뉴 이동은 선택을 유지한다. 브라우저 뒤로가기·새로고침도 동일하다.

## 4. 경쟁업체를 분류하는 두 축

**지역 관계**와 **사용자가 정한 비교 목적**을 별도로 저장한다.

- 지역 관계: 같은 분석 지역 / 다른 분석 지역 / 지역 확인 필요. 공식 지역번호와 기존 분석 지역 매핑으로 자동 판정한다.
- 비교 목적: 직접 경쟁 / 운영·상품 참고. 사용자가 선택하며, 자동 제안과 사용자의 최종 선택을 구별한다.
- 같은 시군구라도 상품·가격대·고객층이 다를 수 있다. 행정구역 일치만으로 직접 경쟁을 확정하지 않는다.
- 타지역이라도 고객이 함께 검토하는 숙소일 수 있다. 직접 경쟁으로 지정할 수 있으나 지역 수요 차이 표시는 유지한다.
- 여러 내 매장이 있는 관리자는 매장별 비교 업체 집합을 구별한다. 한 매장에 등록한 경쟁업체를 다른 매장의 직접 경쟁으로 자동 간주하지 않는다.

| 상황 | 기본 비교 방식 | 화면·판단 규칙 |
|---|---|---|
| 같은 시군구·같은 업종 | 같은 지역 경쟁 비교 후보 | 같은 날짜·관측 기준에서 예약률·가격·예약 증가 속도 비교. 상품 조건 차이는 표시 |
| 같은 시군구·다른 업종 | 다른 상품 유형 참고 | 상품·가격·채널·콘텐츠 참고. 동일 업종 비교 평균에 자동 포함하지 않음 |
| 다른 시군구·같은 업종 | 다른 지역 참고 비교 | 업체 흐름과 각 지역의 수요 흐름 병렬 표시. 지역을 보정한 성과 순위는 만들지 않음 |
| 다른 시군구·다른 업종 | 운영·상품 참고 | 상품 구성·가격·판매 방법 중심. 예약률 차이에 따른 일괄 운영 경고 제한 |
| 같은 도·다른 군 | 다른 지역 | 도가 같다는 이유로 동일 시장으로 합치지 않음 |
| 같은 시의 일반구 | 기존 분석 지역 정책 적용 | 주소 단위와 통계 제공 단위가 다르면 상위 시 기준임을 표시 |
| 지역번호 미연결·주소 모호 | 지역 확인 필요 | 업체 자료는 표시 가능한 범위에서 제공하고 지역 기반 판단 보류. 기본 지역으로 임의 치환하지 않음 |
| 동일·타지역 혼합 | 직접 경쟁과 참고 비교 분리 | 같은 업체 표에 지역 관계를 표시하고, 해석·평균·행동 제안은 유형별로 구분 |
| 모든 경쟁업체가 타지역 | 지역별 참고 비교 | 같은 지역 비교업체가 없음을 안내. 타지역 표본을 내 지역 평균으로 부르지 않음 |
| 복합 업종 | 공통 업종·상품 범위 지정 | 복수 업종 포함 원칙을 유지하고 전체 합계에서 companyId 중복 제거 |
| 객실 규모 차이 | 총량과 비율 함께 표시 | 총매출만으로 우열을 정하지 않음. 초기에는 규모 등급·성과 티어를 도입하지 않음 |

### 경쟁분석 화면의 기본 모습

상단의 기준 내 매장·숙박기간·관측 기준 아래에 비교 업체 카드를 나란히 배치한다. 각 카드에는 이름, 지역 관계, 비교 목적, 업종, 객실 기준, 자료 확보 상태가 있어야 한다.

본문은 **예약 흐름 / 가격·상품 / 지역 배경** 세 보기로 구성한다. 공통 날짜 수, 관측 간격, 비교 제외 사유는 표와 접힌 근거 영역에 함께 둔다. 초기에는 내 매장 대 각 업체의 쌍별 비교를 기본으로 하며, 평균을 제공할 경우에도 ‘등록 비교업체 평균’과 산식을 명시한다.

## 5. 비교 지표와 자료 품질 기준

### 수량·금액·시점은 각각 판정한다

- 날짜별 예약 수량과 예약률은 같은 지표를 두 그래프로 반복하지 않고 하나의 흐름에 수량과 비율을 함께 표시한다.
- 예약률 = 공통 유효 숙박일의 예약 객실 수 합계 ÷ 같은 날짜의 객실 공급 수 합계. 날짜별 비율을 단순 평균하지 않는다.
- 매출은 캘린더 또는 표 중심으로 제공한다. 가격 일부 미확인 시 확인된 소계와 미확인 수량·기간을 구별한다.
- 수량이 정상이고 가격만 빠졌다면 수량 비교는 허용하고 금액 비교를 제한한다. 하나의 partial 상태로 모든 지표를 함께 탈락시키지 않도록 계약·테스트를 보완한다.
- 객실 기준은 중앙 DB 검수값 우선, 없으면 중앙이 계산한 최대관측 기반 추정값과 경고를 사용한다. 새 40실 제한을 만들지 않는다. 충돌·총량 미확인은 예약률 등 분모가 필요한 판단을 보류한다.
- 숙박·데이유즈 공유, 런치·디너 재사용, 상품별 최대관측 수량은 현재 중앙 공통 계산을 재사용한다. 인사이트에 다른 산식을 만들지 않는다.
- 공개 예약은 녹색, 타채널 추정은 보라색 계열을 유지한다. 추정이 없는 날짜의 보라색 표시를 생략하며 오류·누락은 실제 0과 구별한다.

### 변화와 리드타임

- 같은 숙박일의 이전·이후 관측을 비교한다. ‘오늘부터 30일’과 ‘내일부터 30일’의 전체 합계 차이를 신규 예약으로 표시하지 않는다.
- 이전 관측이 3일 전이면 ‘3일 전 관측 대비’로 표시한다. 공백을 보간해 매일 수집한 것처럼 표현하지 않는다.
- 공개 예약 증감과 방막기 추정 변화는 구분한다. 재고 수정·운영 중지·객실 검수 변경도 수량 변화를 만들 수 있으므로 변화 전부를 신규 판매·취소로 확정하지 않는다.
- 리드타임은 재고 변화가 관측된 구간의 추정치이며, 실제 예약 접수일이 아니다. 최소·최대 범위와 관측 간격을 함께 제공한다.
- 평일·금요일·토요일·일요일·연휴·연휴 전날을 구별한다. 기간별 날짜 구성 차이를 매장 경쟁력 차이로 해석하지 않는다.

### 공통 조건과 판단 상태

- 현재 향후 30일 브리핑의 초기 엄격 비교는 현행 동일 숙박일·동일 KST 관측일·최근 7일 기준을 유지한다. 이때의 최근 7일은 현재 브리핑의 신선도 기준이며 과거 마감월 전체에 적용하지 않는다.
- 과거 주간·월간 분석은 선택한 관측 마감일 이하의 중앙 유효 관측을 사용한다. 같은 숙박기간과 관측 마감일을 맞추고 당시의 관측 공백·숙박일까지의 관측 간격을 표시한다. 현재 날짜에서 오래됐다는 이유로 9월 자료를 제외하거나, 마감일 이후 관측을 당시 알고 있던 자료처럼 섞지 않는다. 원본 복구·검수에 따른 새 계산 버전은 별도로 명시한다.
- 같은 KST 날짜라도 실제 시각 차이를 표시한다. 같은 수집 묶음의 자료를 우선 연결하되 묶음이 같다는 이유만으로 동시 관측이라고 표시하지 않는다. 자동 행동 제안에 사용할 최대 허용시차는 1단계에서 실제 수집 간격을 검토해 정책값으로 확정한다. 허용시차를 초과했거나 시차 정책이 미확정인 자료는 수치 참고만 제공하고 자동 우열·행동 제안에서는 제외한다.
- 공통 7일 미만은 비교 표본 부족으로 표시한다. 이는 통계적 신뢰를 보증하는 기준이 아니다. 짧은 연휴 자료는 사실 요약이 가능하나 강한 우열·행동 판단은 보류한다.
- 관측 시점이 다른 자료는 ‘시차 있는 참고 자료’로 분리한다. 시각이 없는 구형 자료에 임의 시각을 만들지 않는다.
- 숫자마다 표시 가능 / 비교 가능 / 행동 제안에 사용 가능을 구별한다. 업체 전체에 단일 성공·실패 배지를 붙여 정상 부분을 가리지 않는다.
- 사용자 실적과 관측 추정은 별도 계열·출처로 표시한다. 직접 입력 실적을 중앙 원본에 자동 병합하는 정책은 이번 개편의 범위가 아니다.

## 6. 지역분석의 연결 방식

지역분석 기본값은 선택한 내 매장의 실제 시군구다. 본문은 네 묶음으로 정리한다.

| 묶음 | 지표 | 고객이 읽을 내용 |
|---|---|---|
| 수요 흐름 | 방문·체류·소비 | 수요의 계절적 움직임과 최근 변화 |
| 관심 흐름 | 검색 트렌드 | 관심 증가·감소 시기와 예약 관측 흐름의 관계 |
| 수요 배경 | 인구·산업·입지·클러스터 | 주거·산업·주말 관광 등 고객 수요를 검토할 배경 |
| 관광 구성 | 관광자원·다양성 | 지역 방문 목적과 상품·콘텐츠 연결 후보 |

- 확인 가능한 최신 마감월을 끝으로 최근 11~12개월을 기본 표시한다. 지표별 실제 공표월·확보 개월 수·연간/월간 단위를 유지한다.
- 서로 다른 지역의 직접 수치 차이는 같은 제공기관·정의·행정단위·대상월이 맞을 때만 계산한다. 맞지 않으면 각 지역의 흐름과 최신 자료를 병렬 제공한다.
- 검색 관심도는 같은 키워드 집합·정규화 기간 등 저장 조건을 확인한다. 서로 다른 기준의 지수를 절대 수준으로 비교하거나 합산하지 않는다.
- 경쟁 3곳이 같은 지역이면 그 지역은 한 번만 읽고 하나의 배경 카드로 공유한다. 서로 다른 지역이면 지역별로 구분하며 임의 평균 수요 점수를 만들지 않는다.
- 등록된 소수 업체의 평균을 ‘지역 전체 평균’이라고 표현하지 않는다. 초기에는 지역 보정 점수·미래 매출 예측·성과 티어를 도입하지 않는다.

### 경쟁업체 소재지의 신규 조회 권한 제안

경쟁업체의 지역 배경은 **등록 관계에서 파생되는 저장 지역 요약 조회**로 제공한다. 이 부분은 현재 없으므로 중앙 연결 계약·권한 검사를 개발해야 한다.

- 내 매장 지역, 명시적 관심지역, 경쟁업체 소재지 참고 요약을 구별한다.
- 경쟁업체 소재지 요약은 관심지역 등록 수량을 소모하지 않도록 제안한다. 관심지역의 전체 분석·갱신 권한으로 확대하지 않는다.
- 일반 고객이 등록할 수 있는 경쟁업체·관심지역 한도는 기존 관리자 설정을 유지한다.
- 업체 해제 시 파생 조회와 관련 캐시 권한을 회수한다. 기존 발행본은 발행 당시 허용된 자료와 출처를 보존한다.
- 조회 권한을 외부 API 수집·수집 일정 등록 권한으로 간주하지 않는다.

## 7. 리포트와 실행 기록

리포트는 **요약 → 내 매장 변화 → 같은 지역 경쟁 → 다른 지역 참고 → 지역 배경 → 다음 행동 → 근거·미확인** 순서로 정리한다.

- ‘현재 브리핑’은 홈에서 요약하고 필요하면 상세로 연결한다. 리포트 메뉴의 중심은 선택한 주간·월간 결과와 발행본이다.
- 현재 발행본은 예약·매출·근거를 보관한다. 새 형식에서는 지역 배경, 비교 조건, 자동 제안, 운영자 의견, 선택한 행동도 발행 시점에 고정한다.
- 제안은 최대 3개로 제한하고 근거, 실행할 내용, 확인할 지표를 제공한다. 다른 지역의 예약률 차이만으로 가격 조정을 권하지 않는다.
- 사용자의 의견·제안 채택·시행일·진행 상태·결과 메모는 인사이트 고객 기록에 별도 저장한다. 자동 생성 문구와 사용자의 의견을 명확히 구분한다.
- 다음 기간에 시행 전후의 공통 조건과 변화를 보여준다. 실행 후 변화가 나타났다는 사실과 그 행동의 인과 효과는 구별한다.
- 원본 복구·객실 검수 변경 후에는 최신 계산 결과로 새 발행본을 만든다. 기존 발행본은 덮어쓰지 않는다.
- 회사번호·수집번호·계산 버전·객실 기준 버전·지역 지표 출처/공표기간·발행 버전을 함께 보존한다.
- PDF/인쇄는 발행본의 읽기 전용 화면을 기준으로 후속 연결한다. 미확인 날짜·금액을 출력에서도 생략하거나 0으로 바꾸지 않는다.

## 8. 데이터·연결 구조

**데이터랩**은 원본·업체 통합 계산·공통 품질 판정의 기준을 맡는다. **인사이트**는 권한 있는 표시용 자료·고객별 관계/메모·실행 기록·발행본을 보관한다.

- 중앙 연결부: 비교 기간/관측 기준, 비교 가능 상태와 사유, 공통 날짜, 업종·지역 관계, 경쟁지역 파생 조회를 확장한다.
- 인사이트 BFF/화면: 선택 상태·권한 투영·캐시 검증·표시·발행 스키마를 함께 변경한다. 필드만 추가하고 영속 스냅샷·브라우저 검증을 누락하지 않는다.
- 비교 응답에는 comparisonRole, regionRelation, industryScope, basis, quantityQuality, revenueQuality, comparisonStatus, reasons, provenance를 둔다. 표시명은 쉬운 한국어로 제공한다.
- 캐시 키에는 고객/권한, 기준 내 매장, 비교업체 집합, 숙박기간, 관측 기준, 비교 규칙 버전, 계산/객실 기준 버전을 반영한다.
- 같은 지역·업체 중복 읽기는 공유하고, 요약 응답에서 모든 업체의 무거운 재계산을 동시에 시작하지 않는다. 세부 근거는 펼쳤을 때 읽는다.
- 저장 자료 우선 표시·실제 최신 확인·새 계산 중·실패를 계속 구분한다. 표시 속도와 재계산 완료 속도를 하나의 성공 수치로 합치지 않는다.
- 정상 일부는 유지하고 실패 업체·기간·안전한 사유를 표시한다. 권한 만료·등록 해제·계정 변경은 즉시 관련 캐시와 늦은 응답을 배제한다.

## 9. 구현·배포 순서

| 순서 | 범위 | 변경 위치 | 완료 기준 |
|---|---|---|---|
| 1. 비교 기준·화면 시안 | 비교 유형/품질 계약, 공통 선택 상태, 동일·타지역·혼합 실제 자료 기반 PC/모바일 시안 | 중앙 연결부 설계 + 인사이트 | 지역·업종·공통 날짜·수량/금액 사유가 명확하고 타지역이 자동 우열 판단에 섞이지 않음 |
| 2. 내 매장·경쟁분석 | 기존 A/B/C 유지, 관측 간 변화 노출, 실제 나란히 비교, 등록 관리 분리 | 인사이트 + 최소 비교 API | 같은 조건의 모든 화면 수치 일치, 중복 집계 없음, 보류 사유와 정상 부분 표시 |
| 3. 지역 맥락·홈 | 경쟁업체 지역 요약·권한, 지역 네 묶음, 홈 판단 요약과 공통 이동 | 중앙 지역 연결 + 인사이트 | 동일/타지역/혼합·새 지역·해제 시 권한 정상, 중복 지역 1회 조회, 관심지역 한도 유지 |
| 4. 리포트·실행 | 과거 주/월 계약, 지역/비교 스냅샷, 의견·실행 기록, 새 버전 발행, 인쇄 | 중앙 기간 계약 + 인사이트 보관/UI | 화면과 발행 수치/범위/출처 일치, 기존 발행본 불변, 다음 리포트에 실행 상태 연결 |
| 5. 공개 서비스 수집 | 내 매장+경쟁업체 일별 묶음, 업체 중복 재사용, 검수·완료 전달·일별 보관 | 별도 수집 서비스 단계 | 계정/업체별 정책 구별, 동일 업체/날짜/조건 중복 방지, 실패 원인 표시, 조회 없이도 승인된 일별 기록 보관 |

1~4단계에서 수집 엔진·일정·차단 보호·원본 매출 계산 산식을 변경하지 않는다. 중앙 수정은 필요한 비교·지역·기간 연결 계약으로 한정한다. 새 연결 계약이 필요한 배포는 중앙 호환 API를 먼저, 인사이트를 다음으로 적용한다. 새 필드를 모르는 구버전 화면은 계속 동작해야 한다.

5단계의 정책 주의: 현행 일반 고객 수집 한도는 **계정 전체 하루 1회**다. 구상한 **내 매장 1곳+경쟁 3곳을 매일 준비**하는 서비스는 아직 그 정책과 다르다. 사용자 요청 횟수·실제 업체별 작업·고객 간 재사용·예약/실행·결과 검수·보관을 분리해서 정의하고, 별도 구현·검수 후 활성화한다. 이번 계획만으로 자동 수집을 켜지 않는다.

## 11. 이번 구조 개편에서 보류할 항목

지역 보정 성과 점수, 규모/성과 티어, 자동 가격 결정, 자동 매출 예측은 비교 가능한 표본과 검증 기준이 쌓인 뒤 검토한다. SNS·광고 노출 등 새로운 자료 연결은 출처·제공 범위·비교 기간을 확인한 별도 기능으로 계획한다. 먼저 기존 자료만으로 사용자에게 현황·변화·비교 근거와 실행 기록을 일관되게 제공한다.

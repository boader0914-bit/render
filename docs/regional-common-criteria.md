# 새 지역에도 적용하는 지역 지표 공통 기준

2026-10-17 개발본. 운영 배포·실제 공급자 수집을 완료했다는 기록이 아니다.

## 적용 위치

기존 지역분석 메뉴를 유지한다. 지역 현황과 자료·출처는 지표 묶음 안의 **공통 기준 확인**을 접고 펼친다. 지역 비교는 같은 저장 결과를 읽으며 지표별 직접 비교 허용 여부를 공통 모듈로 판정한다. 지역 DB의 기존 즉시 갱신·예약 갱신 절차를 사용하며, 화면 조회는 새 수집을 시작하지 않는다.

공통 정책은 `web/regional-data-contract.js` 한 곳에 정의하며 서버의 결과 정리와 브라우저의 비교 판정이 함께 사용한다. 특정 지역명이나 기존 DB에만 맞춘 예외는 없다.

## 식별과 범위

- 내부 지역은 행정구역 원장의 `regionKey`, 공식 코드, 광역/기초 단위, 시·군·구 유형으로 식별한다.
- 공급자마다 코드 체계가 다르므로 내부 코드를 그대로 모든 API에 전달하지 않는다. 관광공사와 KOSIS의 지역 연결을 각각 유지한다.
- 요청 지역과 응답에서 확인한 지역은 별개다. 입력을 되돌려준 `result.region`이나 기존 매핑의 `ready`만으로 실제 제공 범위가 검증됐다고 판단하지 않는다.
- 관광 자료는 실제 응답의 지역코드·지역명 검사를 통과한 근거를 저장한다. KOSIS는 표별 이름·상위 지역 메타 매핑과 실제 `C1` 일치 검증을 함께 보존한다.
- 일반구는 기존 주소 매칭 단위로 유지한다. 하위 구 자료를 상위 시 지수로 임의 합산·평균하거나 대체하지 않는다.

## 기간과 비교

| 자료 | 저장·비교 기준 |
| --- | --- |
| 월간 관광 흐름 | 지표별 최신 정상 확보 월을 포함한 13개월. 내부 공백은 유지한다. 기존 24개월 조회도 보존한다. |
| 인구·산업 | 실제 공표월 또는 기준연도를 유지한다. 연간 값을 13개월로 반복하지 않는다. |
| 검색 관심도 | 응답 전체의 검색어·정규화 기간·자료 묶음을 보존한다. 서로 다른 묶음의 상대지수는 지역 간 직접 비교하지 않는다. |
| 지역 간 비교 | 동일 지표·출처·단위·공표 주기·행정구역 수준이며 각 지역의 실제 범위가 확인된 관측만 비교한다. |

지역코드는 서로 다른 것이 정상이다. 코드 자체가 같아야 한다는 조건을 두지 않는다. 지표별 공통 정상기간을 최신부터 검사하며, 해당 월의 행별 범위 근거가 모두 일치할 때에만 선택한다. 최신 공통월의 범위가 미확인이면 더 이전의 검증된 공통월을 선택하고 이를 알린다. 공통월이 없으면 직접 비교값은 비우고 각 지역의 참고값·기간·제한 사유를 표시한다.

## 수집 상태와 이전 자료

- 정상 응답의 0은 실제 관측값이다.
- 미수집, 정상 빈 응답, 공표 대기, 오류·차단, 범위 불일치를 구분한다. 정상 빈 응답만으로 해당 지역이 영구 미지원이라고 단정하지 않는다.
- 매핑이 존재하는 것과 자료가 확보된 것은 다른 상태다. 응답이 비었다고 지역 매핑을 없애지 않는다.
- 범위가 틀린 값은 일반 관측값·전망 입력에서 제외하고 별도 참고값으로 남긴다. 원본은 삭제하지 않는다.
- 범위 증거가 기록되지 않은 이전 저장본은 값을 보존하되 **범위 확인 필요**로 표시한다. 과거 입력값에서 응답 증거를 역생성하지 않는다.
- 새 공급자 응답부터 근거를 저장한다. 기존 자료를 확인하기 위한 외부 갱신은 기존 잠금·호출 예산·관리자 갱신 절차를 따른다.
- KOSIS의 기존 지역 ID 별칭과 정식 지역키는 같은 원장 식별자로 연결하며, 별칭 조회 때문에 저장 자료가 사라지지 않는다.

## 저장과 이행

정리 결과에 `contractVersion`, `regionIdentity`, `comparisonRules`를 저장한다. 각 지표 묶음·지표·기간별 관측은 `spatialContract`를 가지며, 월간/연간의 `temporalPolicy`와 상태별 `availability`를 보존한다. 계약의 변경은 입력 자료 지문과 새 결과 번호에 반영된다.

기존 결과 파일·발행 리포트는 유지한다. 새로운 기준이 없는 기존 결과를 읽어도 외부 호출·자동 재수집·원본 전체검사를 하지 않는다. 다음 명시적 갱신이나 기존에 승인된 갱신 작업에서 새 결과를 저장한다. 외부 재수집 없이 저장 자료만 다시 정리할 수도 있지만, 원자료에 없던 범위 검증 근거를 만들어내지는 않는다.

## 새 지역 적용 절차

1. 원장에 활성화된 선택 가능 지역과 공급자별 매핑을 확인한다.
2. 지역 DB에서 기존 자료를 먼저 읽고, 미확보 부분은 기존 즉시/예약 갱신으로 준비한다.
3. 실제 응답 범위·기준기간·정상/누락 상태를 동일한 계약으로 저장한다.
4. 지역 현황에서는 확보된 흐름과 공백을 확인한다.
5. 지역 비교에서는 지표별 검증된 공통월 또는 공통 기준연도를 선택한다.

## 검증

`npm run test:regional-common-criteria`는 공통 정책, 수집기 응답 근거, KOSIS 보존·별칭, 결과 저장, UI 비교를 검사한다. 새 시·군·자치구, 다른 코드체계, 실제 0, 빈 응답, 잘못된 지역, 이전 저장본, 행별 공통월 검증이 포함된다. 외부 공급자 대신 격리된 응답을 사용한다. 운영 성능과 실제 신규 지역의 API 제공 범위는 배포 후 별도 검수한다.

보관된 실제 응답이 있는 과거 자료는 [보관 원본 검증 근거 연결](regional-stored-evidence.md)의 공통 절차로 재검증할 수 있다. 정리된 값·요청 지역만 남아 있는 자료는 미확인을 유지한다. 새로운 검증 근거는 다음 명시적 저장 자료 재정리에 반영하며 기존 결과를 수정하지 않는다.

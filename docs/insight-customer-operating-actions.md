# 고객별 경쟁분석과 가격·쿠폰 운영 검토

## 범위

인사이트의 기존 고객 조회와 예약브리핑 응답을 사용한다. 고객에게 등록된 내 매장과 경쟁업체만 비교한다. 새 데이터랩 연결, 수집, 예약 변경, 원본 수정, 가격 저장, 쿠폰 발급을 추가하지 않는다. 정기수집은 중지 상태를 유지한다.

## 선택과 고객 구분

- 첫 진입은 해당 내 매장에 등록된 경쟁업체를 전부 선택한다.
- 선택 저장 형식은 v2다. 기존 v1의 빈 선택은 한 번 기본 선택으로 이전한다. v2의 명시적인 빈 선택과 URL의 `comparisonIds=`는 유지한다.
- 고객·내 매장·권한이 바뀌면 허용된 업체를 다시 확인하고, 이전 응답과 쿠폰 입력이 다른 고객에게 섞이지 않도록 선택 토큰과 문맥 키를 검사한다.
- 동일 조건의 저장 자료 자동 갱신과 보기 전환에서는 쿠폰 입력을 유지한다. 날짜·기간·상품·고객 변경 시 가정을 초기화한다.

## 비교와 제안 기준

동일지역, 타지역, 지역 미확인을 나눠 표시한다. 쿠폰 판단에는 같은 지역이면서 공통 업종이 확인되는 업체만 포함한다. 다른 업종과 타지역은 별도 참고로 남기고 제외 사유를 표시한다. 중앙 비교의 판단 보류 상태는 유지하며, 날짜별로 근거가 있는 경우도 읽기 전용 검토 후보로만 제시한다.

같은 숙박일과 실제 관측 시각이 확인되는 유효 수량만 비교한다. 정상 0실과 미확인, 공개예약과 타채널 예약 추정을 구분한다. 관측 공백은 보간하거나 0실로 바꾸지 않는다. 검토 기준일부터 숙박일까지 남은 날은 예약 리드타임으로 표현하지 않는다. 예약 증감 이력이 없는 응답에서 예약 변화나 쿠폰 효과를 만들지 않는다.

현재 기본 가정은 예약률 차이 10%p, 숙박일까지 14일, 비교업체 1곳 이상, 확보율 80%다. 검증된 수요·가격 정책이 아닌 검토 우선순위를 위한 가정으로 표시하고, 차이와 기간은 화면에서 변경할 수 있다.

## 가격과 쿠폰 산술

현재 예약브리핑 응답에는 상품별 판매가격이 없다. 상품 판매가격은 미확인으로 유지하고 직접 입력한 가정을 명시한다. 매출을 예약수량으로 나눠 상품가격을 대신하지 않는다. 미래의 검증된 상품가격은 순수 계산 함수의 선택적 `priceRows` 계약으로 전달할 수 있으나 이번 변경에서 새 조회는 추가하지 않는다.

할인 후 가격 = 상품가격 × (1 − 할인율). 1실당 남는 금액 = 할인 후 가격 × (1 − 수수료율) − 변동비. 할인 전의 앞으로 팔릴 수량 가정과 같은 금액을 남기는 최소 정수 수량을 계산하고 상품 판매한도와 비교한다. 할인은 신규 판매에만 적용하며 업체 전액 부담, 수수료는 할인 후 가격 기준이다. 원가·수수료·수량 미입력 시 손익을 확정하지 않는다. 고정비·세금과 판매확률은 이 계산에 포함하지 않는다.

검산 예: 가격 179,000원, 할인 10%, 변동비 50,000원, 수수료 10%, 기준 2실이면 할인 후 161,100원, 필요 3실이다. 한도 2실이면 초과 경고를 표시한다.

## 월명 고정 검토 자료

기존 9월 월명·경남 상위20 보존 화면과 자산은 유지한다. 진입 카드는 인증된 `/admin`에서만 표시한다. 고객화면에는 노출하지 않으며, 예전 고객 hash 경로는 관리자 화면으로 이동하는 안내를 표시한다. 보존 경로의 기존 관리자 인증은 유지한다.

## 검수

`node --test customer-portal/test/*.test.cjs`로 선택 이전, 고객 범위, 늦은 응답, 날짜별 수량·가격 미확인, 업종 제외, 쿠폰 산술, 관리자 보존 화면 접근을 검사한다. 로컬 가상 UI는 `node customer-portal/review/customer-operating/server.cjs`로 열 수 있으며 외부 수집과 저장을 하지 않는다. 배포 후 실제 고객 보기에서 내 매장·경쟁업체·지역 분리, 쿠폰 가정 계산, 모바일 테마를 확인하고 정기수집 상태를 배포 전후 대조한다.

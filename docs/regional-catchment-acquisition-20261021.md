# SGIS 실제 자료 반입 준비 · 2026-10-21

반경 배후시장 1차 개발은 `107f4df`다. **운영 배포·실제 격자 통계 확보는 아직 완료되지 않았다.** 다음 작업 지시에 따라 공식 원본의 실제 구조와 신청 조건을 확인하고 준비 도구를 보완했다.

## 실제 원본 형식 대응

[SGIS 공식 인구 격자 Python 예제](https://sgis.mods.go.kr/view/pss/dataBook04)는 2024년 CSV의 CP949 인코딩·헤더 없는4열과 총인구 항목 `to_in_001`을 설명한다. [공식 산업 격자 예제](https://sgis.mods.go.kr/view/pss/dataBook02)는 같은 격자 ID와4열 구조를 사용한다. 예제에서 확인한 교육서비스업 코드를 총사업체로 해석하지 않는다.

준비 도구는 다음을 지원한다.

- 인코딩과 열 순서를 명시하고 원본 CSV를 직접 읽는다. 헤더·항목코드·인코딩을 자동 추측하지 않는다.
- 기존 `xlsx`의 CP949 테이블을 CLI에서만 사용하며 재인코딩한 바이트와 원본의 일치를 검사한다. Node 내장 `euc-kr` 복호화의 확장 한글 오해석을 회귀시험으로 방지했다.
- 원본 CSV SHA, 복호화한 UTF-8 SHA, 원본 인코딩과 mapping SHA를 분리하고 저장·재사용 판정에도 유지한다.
- 인구 등 확인한 지표 하나만 먼저 반입할 수 있다. 미확보 사업체·종사자는 `not_acquired/null`로 유지한다. 이후 확보한 공식 XLS에서 총사업체 `to_fa_010`, 총종사자 `to_em_020`을 확인했다. 코드 확인과 실제 CSV의 값 확보는 별개다.

추가 보완 후 신규 관련 시험 **75/75** 통과. 전체 앱 API 시험에서 인코딩·원본/복호화 해시가 재시작 후에도 유지됐다. 원본/결과 GET 변경0·외부 요청0, 로컬 모의 저장 GET14.0~16.1ms였다. 실제 공간통계나 운영 부하 성능이 아니다.

## 자료 신청 준비와 경계

공식 ONE-ID 기존 계정으로 SGIS 인증까지 확인했다. 신청안 목표는 **2024년 전국1km 인구·사업체·종사자 격자와2025년 경계**다. 여러 지역을 같은 기준으로 재사용할 수 있도록 하되, 실제 반입 묶음은 확인한 중심점100km의 범위와 8MiB/50,000셀 제한에 맞춰 별도로 준비한다. 제공기관의 경계 압축 묶음에 여러 해상도가 포함되면1km 파일만 분석에 사용한다.

사용자가 **신청과 필수 동의를 승인**했다. 소속은 `사분`, 목적은 `공간DB구축·숙박업 배후시장 분석`으로 구성했다. 통계 각30개(인구·사업체·종사자)와 경계30개, **총120행**을 대조했고 통계연도2024·1km, 경계연도2025가 일치했다. 경계 신청은 제공기관의 여러 해상도 묶음이며 실제 분석에는1km를 선택한다.

SGIS 신청폼의 필수 조건은 출처 표시 및 결과 완성 시 국가데이터처에 결과물 사본1부 제출 동의다. 기존 계정의 성명·연락처·이메일 전송도 사용자 승인을 받았다. 필수 동의 확인 후 **신청완료를1회 눌렀으나 브라우저 응답이 멈췄다**. 별도 인증 탭의 신청내역에 접수번호가 없어서 상태는 **`NEEDS_VERIFICATION`**이다. 빈 목록만으로 서버가 절대 수신하지 않았다고 단정하지 않으며 중복 제출하지 않는다. 계정 개인정보·비밀번호·쿠키는 이 문서나 검수 파일에 보관하지 않는다.

사용자는 코덱스 내부 SGIS 창을 볼 수 없다고 답했다. 내부 신청 탭의 제출 응답은 아직 확인되지 않아, 사용자가 볼 수 있는 Chrome에서 이어갈지 질문을 남겼다. 브라우저를 바꾸더라도 접수 여부를 먼저 확인하며 기존 신청·필수 동의 승인을 반복 요구하지 않는다.

# 검색 수요 분석

통합 개발계획 v3를 구현한 독립 저장·조회 기능이다. 메뉴는 **업종분석 → 검색 수요 분석**이며, `키워드 월별`과 키워드를 공유한다. 숙박월·검색량 관측일·트렌드 조회기간·전망 대상월은 서로 별개다.

## 운영 경계

- 신규 자동 갱신은 기본 비활성이다. 중앙 웹에 `SEARCH_DEMAND_ENABLED=true`가 명시돼야 시작한다. 이 개발에서는 운영 배포·활성화·공급자 호출을 하지 않았다.
- 기존 하루 6회 숙박 수집, 120분 간격, 원본·이력·한도·보호 및 기존 수요전망 함수는 변경하지 않는다.
- KOSIS 자료는 읽거나 갱신하지 않는다. 기존 전면 보류를 유지한다.
- 화면·보고서·CSV는 관리자 인증을 거친 저장 조회만 한다. 조회로 작업을 만들거나 공급자를 호출하거나 전망을 발행하지 않는다.
- 새 자동 작업은 숙박 수집과 독립된 제한·상태를 쓴다. 현재 내부 일일 요청 상한은 제공처별 50회다. 이는 외부 계정 쿼터나 잔여 한도 검증값이 아니다.

## 주기와 보호

| 자료 | 정상 시각(KST) | 대상과 저장 |
| --- | --- | --- |
| 검색광고 | 매일 09:30 이후 | 해당 주기에 고정한 등록 기준 키워드별 1회, 응답의 전체 연관 행 |
| 검색 트렌드 | 매월 2일 08:30 이후 | 해당 월 주기에 고정한 대상 키워드, 직전 완료월까지 12개월의 한 조회창 |

각 제공처의 첫 정상 tick에서 목록을 고정하고 재시작 후에도 같은 목록을 재사용한다. 이후 등록한 키워드는 다음 정상 주기에 반영한다. 성공한 같은 작업은 재호출하지 않는다. 같은 API 호스트의 요청은 직렬이며 최소 간격을 둔다. 연관어마다 추가 조회하거나 관계를 재귀적으로 확장하지 않는다.

작업 ID에는 제공처·비밀값을 포함하지 않는 자격 범위 지문·키워드·처리 기간이 결합된다. 단일 실행권과 durable claim으로 중복을 막으며, 재시작 때 이미 요청했는지 불확실한 작업을 자동 재호출하지 않는다. 인증 오류와 429 등의 보호를 자동 해제하지 않는다. 월간 일시 오류는 하루 최대 1회, 같은 주기에 총 3회까지만 허용한다. 이미 저장된 자료의 전망 후처리 보류는 공급자 재호출 사유가 아니다.

## 저장과 값의 의미

신규 namespace는 `DATA_DIR/search_demand`다. 응답 스냅샷은 추가 저장하고 내용 SHA를 검증한다. 키·인증 헤더·쿠키·토큰·전체 응답 본문은 저장하지 않는다. 부모 경로·일반 파일·비 symlink·단일 hardlink·읽기 전후 파일 동일성 검사와 상한을 적용한다.

- `keywordId`: NFKC·띄어쓰기 정규화 버전의 고유번호다. 의미가 비슷하다는 이유로 다른 단어를 합치지 않는다.
- SearchAd는 반환 행·유효 행·고유 키·중복·상충·무효 행을 구분한다. 기준어의 정확 일치가 없으면 다른 연관어를 기준 값으로 대체하지 않는다.
- 숫자, `<10` 같은 범위, 미확인을 별도로 보존한다. 실제 0은 숫자 0이다. 범위·미확인을 0이나 임의 점 추정으로 바꾸지 않는다.
- 일별 관측은 조회 시점에 제공된 **최근 월간 검색량**이다. 당일 검색수나 달 전체 확정 검색수로 부르지 않으며, 날짜별 관측값을 더하지 않는다.
- 같은 날 여러 응답은 원 스냅샷을 보존하고 하루 대표 하나만 채택한다. 다중 기준어에 등장한 같은 연관어도 하나의 키워드 ID를 쓴다.
- 트렌드는 조회창 전체를 저장한다. 창마다 최대 100인 상대지수를 일부 월씩 이어 붙이지 않는다. 결측은 선을 끊는다.

## 전망과 보고서

`legacy-demand-ratio-v1`은 기존 전망의 계절 비율·최근 추세 보정 계산을 호환 어댑터로 재현한다. 원래 함수와 과거 결과는 보존한다. 정확한 같은 키워드의 당일 검색량, 완전한 12개월 조회창, 동일 창 안의 기간과 유효 값이 모두 있을 때만 새 전망을 추가 발행한다. 원 입력 스냅샷과 조회창·모델·계산 시각을 기록한다. 조회에서 계산한 미발행 값은 발행 전망과 구분한다.

일간 보고서는 선택일의 전체 정규화 응답, 주간은 직전 완료된 월요일~일요일의 관측, 월간은 선택월의 관측 마감까지를 조회한다. 월 대표는 마지막 정상 관측이며 합계가 아니다. PC/모바일·전일/7일 전 변화, 응답 목록의 재관측/처음 관측/다시 미관측, 갱신 이력과 알려진 호출량 소계, 누락·범위·전망 입력을 보존한다. 새 관측을 신규 개업이나 새 검색어 생성이라고 표현하지 않는다. 사후 정확도는 같은 지표·기간의 실제 관측이 없어 보류하며 MAE/MAPE를 만들지 않는다.

호출량 소계는 **보고기간에 예정된 작업의 누적 요청 수**다. 월간 작업의 재시도가 다음 날짜에 걸칠 수 있으므로 이를 그날 실제 호출 총량으로 바꾸지 않는다. 시도별 날짜별 계수 이력이 없는 실제 기간 총량은 미확인으로 표시한다.

## 관리자 GET

- `/api/search-demand/catalog`
- `/api/search-demand/analysis?keyword=...&day=YYYY-MM-DD&month=YYYY-MM`
- `/api/search-demand/report?keyword=...&day=...&month=...&cadence=daily|weekly|monthly&format=json|csv`

모두 관리자 전용, `no-store`, 제한된 쿼리 및 응답 상한을 적용한다. 상태 변경 경로는 없다. CSV는 전체 보고 행을 내보내며 수식으로 해석될 문자열을 방어한다.

## 검증

`npm run test:search-demand`는 모의 응답·임시 파일만 사용한다. 정상·부분·범위·0·누락, 전체 연관어, 중복·재시작·보호, 자료 유출 방지, 기존 전망 호환과 메뉴 왕복·조회 분리를 검증한다.

`scripts/validate_search_demand_realcopy.cjs`는 앞서 확보한 비밀값 없는 경남글램핑 **정확 키워드 한 행 영수증**을 새 로컬 저장소에 정규화해 화면/JSON/CSV/중복 재사용을 대조한다. 원 응답 861행 전체가 보관되지 않았으므로 실자료 전체 연관어와 실제 12개월 트렌드 검증으로 확대하지 않는다.

`scripts/preview_search_demand_isolated.cjs --copy <검증 사본 디렉터리>`는 신규 모듈만 가져오는 루프백 화면이다. 기존 앱·스케줄러·인증·공급자를 시작하지 않는다. 격리 화면은 운영 관리자 화면의 검수를 대신하지 않는다. 운영 반영과 실제 자연 일간/월간 주기는 별도 검증 단계다.

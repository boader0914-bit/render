# 고객 경쟁분석 대시보드

고객에게 등록된 내 매장과 선택한 경쟁업체의 기존 예약브리핑만 사용한다. 인사이트 웹 서비스만 배포하며, 중앙 데이터랩 연결·원본·발행본·수집기·정기수집 설정은 변경하지 않는다.

## 화면 순서

1. 비교 조건: 내 매장·등록 경쟁업체, 저장된 30일 안의 숙박 시작일·종료일·요일.
2. 핵심 지표 4개: 내 매장 추정예약률, 같은 지역·업종 표본예약률, 숙박상품 표시가격, 공개예약 순변화.
3. 판단 카드 3개: 예약 수준, 상품·가격 조건, 예약 변화. 근거와 다음 행동을 함께 표시한다.
4. 비교 그래프: 업체별 공개예약·타채널 추정 누적 예약률과 숙박일별 예약률 흐름.
5. 상세 근거: 업체별 확보일·비교 제외 사유, 날짜별 운영 검토·쿠폰 계산, 상품·예약수량·지역 자료. 기본은 접어 둔다.

## 계산과 선택

새 `comparison-dashboard.js`는 외부 통신 없이 기존 고객별 응답만 가공한다. 기간·요일은 응답 안의 날짜를 선택하는 표시 필터다. 중앙 조회의 기준인 원래 30일 기간과 관측 기준일은 유지한다. 필터 변경은 새 조회를 만들지 않는다. 필터는 고객·권한·매장·경쟁업체·원래 기간에 묶어 세션에 보관하며 조건이나 권한이 다르면 재사용하지 않는다.

내 매장 예약률은 선택 날짜 중 유효한 수량의 예약 합계 / 공급 합계다. 표본은 내 매장을 제외한 등록 동일지역·공통업종 업체 중 같은 숙박일·관측 조건을 충족한 자료만 공급 가중한다. 타지역·다른 업종은 개별 참고로 표시하고 표본 평균에 섞지 않는다. 내 매장의 전체 유효일과 표본의 공통일이 다를 수 있어 판단 카드에는 공통일 기준 내 매장 예약률을 별도로 제시한다.

최소 공통일·관측 시차·기준 객실수와 중앙의 판단 보류를 유지한다. 필터 후 공통일이 부족하면 날짜별 쿠폰 상세의 판단과 다음 행동도 보류한다. 정상 0실은 포함하고 오류·누락·충돌·오래된 참고는 미확인으로 남긴다. 부분 상품 금액은 기존 상세 근거에 별도로 보존한다.

현재 응답에 상품별 표시가격과 이전 동일 조건의 예약 증감이 없으므로 해당 지표는 미확인이다. 매출 / 예약수량을 상품가격으로 대체하지 않는다. 고정 월명·경남 상위20 보존 자료는 관리자 화면에 그대로 분리한다. 신규 키워드 지표 연결은 후속 작업이다.

## 검수

`node --test customer-portal/test/*.test.cjs`로 고객 범위, 정상 0/미확인, 날짜 중복·관측 버전, 지역·업종 구분, 필터 합계, 늦은 응답과 쿠폰 상태, 정적 자산 제공을 검사한다. `review/customer-operating/server.cjs`는 운영에 연결하지 않는 가상 자료 화면이다.

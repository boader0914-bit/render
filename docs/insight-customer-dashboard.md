# 고객 경쟁분석 대시보드

고객에게 등록된 내 매장과 선택한 경쟁업체의 기존 예약브리핑 및 이미 연결된 업체·월별 저장 조회를 사용한다. 인사이트 웹 서비스만 배포하며, 중앙 데이터랩의 신규 연결·원본·발행본·수집기·정기수집 설정은 변경하지 않는다.

## 화면 순서

1. 비교 조건: 내 매장·등록 경쟁업체, 저장된 30일 안의 숙박 시작일·종료일·요일.
2. 핵심 지표 4개: 내 매장 추정예약률, 같은 지역·업종 표본예약률, 숙박상품 표시가격, 공개예약 순변화.
3. 판단 카드 3개: 예약 수준, 상품·가격 조건, 예약 변화. 근거와 다음 행동을 함께 표시한다.
4. 비교 그래프: 업체별 공개예약·타채널 추정 누적 예약률과 숙박일별 예약률 흐름.
5. 상세 근거: 업체별 확보일·비교 제외 사유, 날짜별 운영 검토·쿠폰 계산, 상품·예약수량·지역 자료. 기본은 접어 둔다.

## 계산과 선택

`comparison-dashboard.js`와 `comparison-saved-metrics.js`는 외부 통신 없이 기존 고객별 응답만 가공한다. 비교 화면은 권한이 있는 업체·해당 월의 기존 GET과 영속 캐시를 순차적으로 재사용하며, 예약브리핑은 먼저 표시한다. 기간·요일은 응답 안의 날짜를 선택하는 표시 필터다. 중앙 조회의 기준인 원래 30일 기간과 관측 기준일은 유지한다. 필터 변경은 새 조회를 만들지 않는다. 필터는 고객·권한·매장·경쟁업체·원래 기간에 묶어 세션에 보관하며 조건이나 권한이 다르면 재사용하지 않는다.

내 매장 예약률은 선택 날짜 중 유효한 수량의 예약 합계 / 공급 합계다. 표본은 내 매장을 제외한 등록 동일지역·공통업종 업체 중 같은 숙박일·관측 조건을 충족한 자료만 공급 가중한다. 타지역·다른 업종은 개별 참고로 표시하고 표본 평균에 섞지 않는다. 내 매장의 전체 유효일과 표본의 공통일이 다를 수 있어 판단 카드에는 공통일 기준 내 매장 예약률을 별도로 제시한다.

최소 공통일·관측 시차·기준 객실수와 중앙의 판단 보류를 유지한다. 필터 후 공통일이 부족하면 날짜별 쿠폰 상세의 판단과 다음 행동도 보류한다. 정상 0실은 포함하고 오류·누락·충돌·오래된 참고는 미확인으로 남긴다. 부분 상품 금액은 기존 상세 근거에 별도로 보존한다.

상품가격은 최신 저장 회차의 숙박 상품·숙박일별 표시가격에서 중앙값과 범위를 계산한다. 데이유즈·오류·중복 충돌은 제외하고, 선택 날짜와 요일에 맞춰 다시 계산한다. 매출 / 예약수량을 상품가격으로 대체하지 않는다. 월별 응답에 같은 수집회차의 가격이 중복돼도 한 번만 반영한다.

예약 증감은 기존 통합자료에 저장된 유효 구간에서 같은 이전·현재 관측시각 쌍을 묶고 가장 최근 한 구간만 참고값으로 표시한다. 관측 구간이 다른 수량을 합치지 않는다. 날짜 중복·충돌·미래 관측을 제외하고, 공개예약과 방막기 변화는 구별한다. 최근 일부 근거만 제공되면 전체 월·기간 합계로 표현하지 않는다. 수집번호·객실 기준을 포함한 추가 연결 전에는 자동 가격·쿠폰 행동 판단에 사용하지 않는다.

미확인 사유는 관측일 차이로 비교 보류, 같은 지역·업종 표본 없음, 공통 관측 부족, 저장자료 미연결, 상품가격 없음/일부, 선택 기간 이전 관측 없음, 근거 충돌, 조회 중/실패로 구별한다. 정상 0과 음수 관측 변화는 그대로 보존한다. 고정 월명·경남 상위20 보존 자료는 관리자 화면에 그대로 분리한다. 신규 키워드 지표 연결은 후속 작업이다.

## 검수

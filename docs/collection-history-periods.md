# 기간별 수집 기록

2026-10-13 개발 범위. 수집 기록을 연도·월간·주간·일간 단위로 조회하고 각 기간의 기록을 접고 펼친다. 기본 보기 단위는 월간, 기본 조회 범위는 한국시간 올해 1월 1일부터 오늘까지다.

## 조회 기준

- 실제 실행 시각을 우선하고, 실행 시각이 없는 접수·미실행 예약·저장 결과는 날짜의 근거를 구분한다. 조회한 숙박기간을 수집 실행일로 사용하지 않는다.
- 주간은 월요일부터 일요일까지다. 선택 범위를 온전한 주 단위로 확장하면 실제 적용된 시작일과 종료일을 안내한다.
- 즉시수집과 예약의 영속 기록을 최근 조회 제한 없이 읽는다. 이전 일일 자동수집 상태와 기록이 없는 저장 결과도 연결한다.
- 저장 결과는 실제 실행 기록과 중복되지 않게 표시한다. 이후의 기존 자료 재사용 요청만 남아 있으면 원래 저장 결과의 과거 수집일도 보존한다.
- 수집기나 수집 시각을 확인할 수 없는 자료를 BG 워커 또는 현재 날짜로 대신 채우지 않는다. 파일 수정 시각만 남은 자료는 수집일별 집계에서 제외하고 확인 필요 건수로 표시한다.
- 실패·일부 완료·검토 필요와 정상 완료를 구분한다. 상태 미확인 자료를 정상 완료나 0건으로 처리하지 않는다.

## 화면과 API

- 접힌 전체 헤더에서 선택한 조회 범위의 기록 수, 최근 종료 결과, 주의 건수를 확인한다.
- 펼친 본문에서 보기 단위·시작일·종료일·수집기·키워드·상태를 선택한다. 검색 버튼으로 적용하며 날짜 입력 도중 결과를 바꾸지 않는다.
- 각 기간의 제목에는 기간·건수·상태별 집계를 표시하고, 펼칠 때 해당 기록을 읽는다. 기록이 많으면 최대 50건씩 서버에서 조회한다.
- 펼침 선택과 조회 조건은 화면 설정으로 보관한다. 원본 기록과 업체 자료를 브라우저 저장소에 보관하지 않는다.
- 관리자 전용 `GET /api/collection-history`로 조회한다. `from`, `to`, `groupBy`, `worker`, `keyword`, `state`, `groupKey`, `offset`, `limit`을 사용한다.
- 이 조회는 수집 실행·재실행·원본 수정·예약 등록·보호 해제를 수행하지 않는다. 진행 중인 작업은 기존 워커 카드에서 계속 표시한다.

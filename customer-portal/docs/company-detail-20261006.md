- B 예약 채널: 이름, 확인 상태, 연결 버튼만 남긴다. HTTP(S) 이외의 링크는 표시하지 않는다.

## 중앙 저장 방향과 미구현 범위

사용자는 업체 정보 저장소를 DataLab으로 통일하길 원한다. 현재 업체 등록, 개인 설정, 업체·상품 수정 요청은 이미 중앙 Insight API를 사용한다. 하지만 현재 `/commands`에는 날짜별 예약·매출 보정 저장 계약이 없다.

이번 로컬 작업에서 만든 `company-adjustment.js`는 **입력과 계산 미리보기만** 제공한다. 저장·리포트에 적용되지 않음을 화면에 표시하며 POST, 브라우저 저장소, 별도 서버 저장소를 사용하지 않는다. 미리보기는 내 업체에만 보이고 경쟁업체에는 보이지 않는다. 원본 및 채널별 금액은 바꾸지 않는다.

앞선 사용자 지시인 “인사이트 개발 시 데이터랩은 변경하지 말 것”에 따라 중앙 저장 API·테이블 추가 허용 범위를 질문했다. 답변 전까지 DataLab 파일·DB는 변경하지 않았다. 실저장 완료로 보고하면 안 된다.

후속 중앙 저장에는 고객/업체/숙박일 키, 수정자·시각·변경이력, 원본과 별도인 보정값, 버전 충돌 처리와 철회가 필요하다. 서버에서 현재 고객의 활성 `own` 관계를 검증해야 한다. 기존 `hasCompany`는 경쟁업체도 허용하므로 보정 권한 검증으로 재사용하지 않는다. 인사이트 고객 전용 보정값을 공개 관측값이나 다른 고객 자료에 자동 반영하지 않는다.

## 수집 통합·실적·리포트 연결안 — 아직 미구현

리포트의 기존 읽기 연결은 유지한다. `analysis.js`에서 업체별 `GET /companies/{id}/collection`을 읽고 `period-report.js`가 `history/current`의 같은 숙박일에서 최신 관측 1개를 선택한다. 오류·부분·누락은 정상 0으로 바꾸지 않는다. 현재 로직은 관측마감일과 당시 검수 버전을 고정한 월마감 정책이 아니며, 모든 키워드의 원본이 완전히 통합됐다는 증거도 아니다.

1. **수집 원본:** 업체 고유 ID + 상품 ID + 숙박일 + 관측시각 + runId와 검색 키워드를 보존한다. 같은 업체가 여러 키워드에 나타나더라도 업체 실적을 중복 합산하지 않는다. 키워드별 순위는 별도 이력으로 유지한다.
2. **숙박일 대표값:** 동일 숙박일의 관측 회차를 합산하지 않는다. 예를 들어 9/10 숙박의 예약이 9/1에 6실, 9/2에 9실, 9/3에 8실이면 9/3 기준 대표값은 8실이다. 흐름은 +3실, -1실이며 신규 예약·취소를 확정하는 값은 아니다. 월 집계는 각 숙박일의 대표값을 한 번씩 합산한다.
3. **품질과 마감:** 관측마감시각 안에서 어떤 정상 관측을 대표로 쓸지, 이후 오류가 있으면 과거 정상값을 별도 참고로 보여줄지 정한다. 과거 정상값을 최신 정상값으로 표시하지 않고 응답 시각·품질·사용 범위를 남긴다. 상품별 서로 다른 시점을 무작정 섞어 날짜 총량을 만들지 않는다.
4. **업주 실적 별도 저장:** 고객 ID + 업체 ID + 숙박일 기준으로 업주가 입력한 숙박 예약 객실 수·숙박 매출, 입력자·시각·버전·철회 이력을 수집 원본과 분리한다. 재수집이 실적 입력을 덮어쓰지 않게 한다. 저장 위치와 API는 후속 확정 사항이다.
5. **항목별 우선 적용:** 내 업체 리포트에서 활성 업주 입력값을 항목별로 우선한다. 매출만 입력하면 예약 수량은 수집 추정값을 유지한다. 빈칸은 미입력, 명시적 0은 0, 철회는 별도 동작이다. 업주 입력값을 독립 검증이 끝난 값으로 단정하지 않고 ‘매장 입력’으로 표시한다. 총매출을 네이버·타채널 금액에 임의 배분하지 않는다.
6. **리포트 계산층:** ‘매장 입력’과 ‘수집 추정’의 사용 날짜·금액·누락 범위를 표시한다. 부분 입력 월을 전체 실제 매출로 표현하지 않는다. 매장 입력값이 포함된 내 업체와 경쟁업체의 추정값은 출처 차이를 표시한다. 타 고객의 경쟁업체 화면에 비공개 실적을 자동 노출하지 않는다.
7. **발행본 고정:** 숙박기간, 관측마감시각, 실적반영마감시각, 집계규칙 버전, 사용 원본·실적·객실 검수 버전을 저장한다. 이후 자료가 추가되면 기존 발행본을 덮어쓰기보다 새 버전으로 발행한다.

수정 UI의 잠금 해제 조건은 별도 실적 저장 계약, 소유권·권한 확인, 중복·오류·부분 입력 처리, 리포트 출처와 재현성 검증의 완료다. 현재 리포트는 기존 수집자료 검토본이며 보정값은 연결하지 않는다.
